--- note 2026-08-11T02:10:40Z ---

MEASURED by SQ-0769's agent, reported as found-not-fixed.

`crates/app/src/term_colors.rs` sends the OSC 10/11 colour queries on **every** platform, but `drain_stdin_nonblocking` is a **no-op on Windows** — there is no portable non-blocking console read. So the answers are never consumed and arrive at the app as ordinary key events.

This is NOT the unix race SQ-0769 fixed. Unix leaked only when the terminal answered late; **Windows leaks on every launch**, deterministically, because nothing ever reads the replies. SQ-0769's `QuerySweep` gives up immediately on non-unix rather than holding the tty deaf, which is the right conservative default but leaves the platform unprotected.

VISIBLE SYMPTOM would be the same as SQ-0769's: the payload of the colour answers typed into the game — `0;rgb:…` / `11;rgb:…` — skipping keypress waits and answering prompts, since crossterm 0.29 has no OSC handling (`parse_event` falls through `ESC ]` to `Alt+']'` and hands the following bytes over as plain `Char`s).

RELEASE RELEVANCE: babelmap ships Windows binaries, and [[cross-platform-requirement]] is a standing rule. Whoever picks this up should decide between two shapes:
- **Read them.** A Windows-side console reader (crossterm's own event source, or the Console API) that consumes the replies, feeding the same `QuerySweep` machinery SQ-0769 built so the matching logic is shared rather than duplicated.
- **Do not ask.** If the queried values are not actually needed on Windows — or can be obtained another way — not sending the queries removes the problem entirely and is far less code. Establish what `term_colors` is used for before assuming the first shape is required.

The second deserves genuine consideration: a query whose answer we cannot read is pure liability.

RELATED, from the same investigation, both minor and unfiled elsewhere:
- The picker's own probe has the same shape — `ratatui-image` returns as soon as its reader thread signals Done, and only *then* restores the termios it saved.
- `pixel_mouse::query_pixel_mouse_support` shares `query_with` and is currently never called. If it is ever switched on it inherits the identical hazard and should hand its unanswered case to `QuerySweep`.

STEP 1 DONE (commit 6471bd16, worktree agent-ae138791198e30cb1).

Gate lives right next to `drain_stdin_nonblocking` in crates/app/src/term_colors.rs: a new `REPLY_DRAIN_AVAILABLE` const (`#[cfg(unix)] = true`, `#[cfg(not(unix))] = false`) sits directly below the two `drain_stdin_nonblocking` bodies, doc-commented to explain the mapping and to say what SQ-0770 step 2 needs to flip. `query_with` now calls `query_with_gated(query, REPLY_DRAIN_AVAILABLE, send_and_drain)`, which returns `None` immediately — the same "never asked" case the module already had for a non-tty — when the flag is false, before writing a single byte. `send_and_drain` is the old `query_with` body, untouched.

Two new tests: `the_query_is_not_sent_when_the_drain_is_unavailable` / `the_query_is_sent_when_the_drain_is_available`, both in term_colors.rs.

--- note 2026-08-12T05:57:18Z ---

STEP 2 ASSESSED AND DELIBERATELY NOT BUILT; the leak itself is closed. Commit 36b933b0 (worktree agent-a922eec227fd29c20, branched from 0fce86d2).

WHY NOT A WINDOWS READER. Step 1's "do not ask" is the whole fix, not a placeholder for one. SQ-0769's shape does not transfer: its machinery is `QuerySweep` holding the tty until the answer arrives, and holding requires a non-blocking read to hold it WITH — `query_sweep::read_available` is `None` on non-unix for exactly the reason `drain_stdin_nonblocking` is a no-op there. Building one means `GetNumberOfConsoleInputEvents` + `ReadConsoleInputW` (a new `windows-sys` dep, unsafe, unrunnable from macOS), and it consumes INPUT_RECORDs — get it wrong and Windows loses real keystrokes, which is strictly worse than losing a colour probe. The whole benefit purchased is the v6 raster canvas learning the terminal's default ink/page. Not a trade worth making blind.

WHAT ELSE ON WINDOWS ASKS A QUESTION. Audited every escape write in `crates/app/src`: `render/graphics.rs` sends kitty APC with `q=2` (responses suppressed by protocol), `clipboard.rs` OSC 52 is write-only, `pixel_mouse::query_pixel_mouse_support` goes through the gated `query_with` and is still never called. crossterm's `supports_keyboard_enhancement` is not used anywhere. That leaves the picker's `Picker::from_query_stdio` — and it is NOT the "never read" defect: ratatui-image 11.0.6 has a real Windows `enable_raw_mode` (CONIN$ + `SetConsoleMode`) and its reader thread does blocking `io::stdin().read()` until the DSR answer on both platforms. Its `query_with_timeout` timeout path abandons a thread still parked in that read, which is the SQ-0642 shape, identical on all three platforms and upstream's to fix.

RESIDUAL RISK, stated plainly. On unix the picker probe's leftovers are swept for free, because `term_colors` probes right after it and its drain takes everything pending. Windows no longer probes, so nothing sweeps a picker answer that arrives late or out of order there. Unmeasurable from here; it needs a Windows console reader to close, i.e. the same step 2 above.

NEW TEST, and why not the pty harness. The defect's trigger is a compile-time `cfg`, so a pty running the macOS binary cannot reach it however it answers — the harness would be measuring the unix path. Instead the platform became a parameter: `crates/app/src/term_colors.rs` gains `colors_and_sweep` (split out of `query_terminal_default_colors` the way `query_with_gated` was split out of `query_with`) plus a `FakeTerminal` that answers what it is asked and keeps what nobody drained, and one drain function per platform shape. Three tests, all running in the gate on every platform:
- `a_platform_that_cannot_drain_leaves_no_answer_for_the_game_to_read` — the Windows chain; asserts nothing is queued for the game AND that the sweep is not left owing an answer it cannot read.
- `a_platform_that_can_drain_still_reads_the_answers_and_settles` — the gate is invisible where the drain works.
- `a_drain_that_asked_and_heard_nothing_yet_still_holds_the_tty` — SQ-0769's protection, pinned at unit level so a future gate edit cannot quietly take it down.
