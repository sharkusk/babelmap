--- note 2026-08-13T18:38:58Z ---

SURVEY — the user's two `.2mg` images, measured 2026-08-13. **Unlike `.st`, this one really is a different filesystem — it shares nothing with the FAT12 work.**

## Container

Both are 819264 bytes = a 64-byte `2IMG` header over 819200 bytes (1600 × 512-byte ProDOS blocks, an 800K disk). Header: magic `2IMG`, creator `WOOF` (Sweet16/GSport lineage), `hdrlen=64`, `format=1` (ProDOS block order).

**TRAP: the header's `data length` field at `0x1C` is ZERO on both images.** Trusting it yields an empty buffer. Fall back to `blocks × 512`, or to end-of-file. A reader that believes the field will fail on the user's entire corpus.

## Filesystem

ProDOS, not FAT. Volume directory starts at **block 2**; each directory block is a 4-byte prev/next pair followed by 13 entries of 39 bytes. An entry's first byte packs `storage_type` in the high nibble and name length in the low nibble (`1` seedling, `2` sapling, `3` tree, `0xD` subdirectory, `0xE` subdirectory header, `0xF` volume header). File data is reached through index blocks that store **low bytes at 0..255 and high bytes at 256..511** — not adjacent pairs, which is the easy thing to get wrong. `BZ.DAT` is a tree, so it needs master-index → index → data; a sapling needs one level; a seedling is a single block.

## What is actually on them

**`Beyond Zork (1988)(Infocom).2mg`** — volume `BEYOND.ZORK`, a bootable GS/OS disk:
```
PRODOS 1452, SYSTEM/{EXPRESSLOAD, SYSTEM.SETUP/, TOOLS/TOOL014…TOOL028, FONTS/BZ.9, GS.OS, DRIVERS/, FSTS/}
COPY.HD 1938   BZ.SYS16 42596 (the IIgs interpreter)   BZ.DAT 261388 (the story)
```
`BZ.DAT` header: **v5 r57 s871221**.

**`Lost Treasures of Infocom, The (1993)(Big Red Computer Club)(Disk 1 of 7).2mg`** — volume `INFOCOM1`: PRODOS, a full `SYSTEM/` tree, `ICONS/`, `FINDER.DATA`, and `LOST1.SYS16` / `LOST2.SYS16` at **512 bytes each** — stub launchers.

**Disk 1 of 7 contains NO story files at all.** It is purely the GS/OS boot disk. This is the strongest evidence yet for SQ-0833's set model: mounting one image of a set can yield literally nothing playable, and there is no way to tell from that image alone that the games are elsewhere.

## Design consequences

* **Most of a IIgs disk is operating system.** Between `TOOL014`…`TOOL034`, `GS.OS`, drivers and FSTs, a directory walk drowns in files that are not games. The content-first scan `blorb::adf::Adf` established is not merely convenient here, it is the only sane approach — and it must recurse or block-scan, since the stories sit beside a deep `SYSTEM/` tree.
* Both games ship their own S16 interpreter (`BZ.SYS16`, `LOST*.SYS16`). We never run these; noted so a content scan is not surprised.

## Fixture gap for the PROFILE half

The user reports being unable to find separate v6 releases for IIgs or Atari ST. Current fixtures cannot validate a IIgs profile's graphics: Beyond Zork is v5 (no v6 art path), and the compilation's game disks are absent.

**The concrete lead:** the DOS *Lost Treasures Vol I* DOES include Zork Zero — `ZORK0.ZIP`, `ZORK0.CG1` and `ZORK0.EG1` are on `floppy4.ima`/`floppy5.ima` (see SQ-0833). So the IIgs Lost Treasures set plausibly carries Zork Zero too, on one of **disks 2-7**, which the user does not have. Tracking those down is the cheapest route to a IIgs v6 fixture. Until one exists, do not write `InterpreterProfile::AppleIIgs`'s palette or art path — this project's rules forbid deriving such constants from memory, and there would be no way to verify them.

CORRECTION — the previous note's lead was WRONG. The user supplied all seven disks; I scanned them.

**The IIgs Lost Treasures set does NOT contain Zork Zero, or any v6 title.** Disk 1 is the GS/OS boot disk (no stories at all); disks 2-7 hold 28 text games:

```
INFOCOM2  ZORK.I/II/III, HITCHHIKER 158413 (+3 .SAV), BEYOND.ZORK 261388
INFOCOM3  STATIONFALL, STARCROSS, SPELLBREAKER, SORCERER, PLANETFALL, MOONMIST, ENCHANTER
INFOCOM4  WITNESS, SUSPENDED, SUSPECT, INFIDEL, HORROR, DEADLINE, BALLYHOO
INFOCOM5  AMINDFV, TRINITY, BUREAUCRACY
INFOCOM6  SHERLOCK, BORDERZONE, NORDANDBERT, LEATHRGODDESSES, PLUNDERED
INFOCOM7  HOLLYWOOD, CUTTTHROAT, WISHBRINGER
```

Every story carries ProDOS file type `$F5`; saves are `$F8`. `HITCHHIKER` at 158413 and `BEYOND.ZORK` at 261388 are byte-for-byte the sizes of the DOS Lost Treasures and standalone IIgs copies respectively, so the collections share releases across platforms even though the media differ.

I reasoned from the DOS Vol I including Zork Zero to the IIgs set probably including it. It does not — the DOS compilation carried a v6 title and the IIgs one is text-only. **A v6 fixture for the IIgs profile therefore does not exist in the user's corpus, and the search should move elsewhere.** Nothing in this quest's ProDOS/container findings changes; only the fixture lead was wrong.

The Macintosh route turned out to be the one that paid off — see the new Mac quest. So the IIgs profile stays blocked on a fixture, and the container half (`.2mg` + ProDOS) remains worth doing on its own since it unlocks 28 games plus a IIgs Beyond Zork.
