**AUTHORISED BY THE USER 2026-08-15.** They had previously said frameless was expendable and expected to be removed eventually (recorded on SQ-0890); this quest is them asking for the removal itself. Until now no quest authorised it — this one does.

MEASURED footprint: **121 references across 16 source files in `crates/app/src/`, and 14 test files.** (`grep -rn "frameless\|Frameless"`.)

## The real prize is not the mode — it is `ContentSplash`

`crate::inline_image::ImageSource::ContentSplash` **exists only because frameless exists.** `crates/app/src/session.rs:2678`, from SQ-0461:

    // a large CONTENT-art draw into a graphics window (Shogun's title splash)
    // ALSO anchors a transcript inline band, so the frameless mode — which drops
    // graphics windows — still shows it. … Hybrid/raster ignore ContentSplash
    // entries (they render the window canvas itself), so no double-draw.

Frameless drops graphics windows, so for it the transcript is the only route to that art; every other mode renders the canvas and must therefore SKIP the entry. Remove frameless and no mode needs the band at all, which retires the whole picture-side "already on screen" apparatus:
  - the `ContentSplash` variant — `crates/app/src/inline_image.rs:44`
  - the band emission and its `is_content_art` gate — `session.rs:2667-2691`
  - the `last_content_pic` per-turn redraw dedupe — `session.rs:2680`
  - the drop in `crates/app/src/render/transcript.rs:2121`
  - the skip in `build_main_text` — `crates/app/src/render/screen.rs:3292`

That apparatus has already cost this session twice: SQ-0888 had to re-check the `build_main_text` skip because it was the reason the Apple press's art vanished, and SQ-0890 had to build a text-side analogue of the same idea (`frozen_head`). Retiring it removes a concept that has repeatedly needed re-reasoning.

**Verify the "only for frameless" claim before deleting** — it is READ from the comment plus a grep, not measured on the corpus. If any mode other than frameless turns out to depend on a `ContentSplash` entry, keep the machinery and say so; the mode removal stands either way.

## Do NOT remove in this quest

- **`frozen_head` / `Machine::v6_prose_retired_whole`** (SQ-0890). It is the text-side rule and is conditional on `menu_over_art`'s composite routing, not on frameless. It belongs to SQ-0894.
- **Raster.** Separately handled — see SQ-0894's acceptance criteria. Raster is where `picture_takeover` escapes to today and cannot go until the ring is complete.

## Product surface

Frameless is a user-facing render mode. Removing it means removing its config key and its `style.toml`/slash surface if it has one, and saying so in `README.md` and `docs/features/`. Check whether any per-game sidecar in the wild would name it — pre-release policy is that formats may break freely (no back-compat shims), so a config naming a removed mode should fail clearly rather than silently, or be ignored with a warning. Decide which and state it.

## Tests

14 test files reference frameless. **Do not delete a test merely because it mentions the mode** — several use frameless as a CONTROL for a cell-path property (SQ-0886's suite asserts "the coherent menu with its solid selection bar" on frameless precisely because it is a cell-path property). Those assertions still need a home: retarget them to whichever mode now carries the property, or state plainly why the property no longer exists. A removal that quietly drops coverage is the failure mode here.

## Gates

`cargo nextest run --workspace 2>&1 | grep -acE "^error(\[|:)| [1-9][0-9]* failed"` must print 0 (grep exiting 1 on zero matches IS the pass; never chain with `&&`), `Starting N` equal to `N tests run: N passed`. Baseline at `ac6ce2aa` is 5562; a removal will lower it, so state the new count and account for every test that went.

`cargo clippy --workspace --all-targets -- -D warnings` clean.
