FIXED 2026-08-09 (commit 7f9ee0e6, worktree agent-a780b4a5c02629c27). Status left at `confirm`: the frame is back, but the bet PROMPT still does not reach the screen, and that half is out of the render lane (see below).

ROOT CAUSE, measured. Choosing "CHANGE CURRENT BET" makes fmvpoker's 594x156 bottom panel the window it reads input through. zvm's divert rule is `prose_window() && !copy_to_transcript() && current != v6_input_window`, so the moment window 2 becomes the input window it stops being diverted and is published as the PRIMARY Buffer — and window 0, which still holds the 640x400 poker table drawn into it, is published as an ordinary Grid. The game drew nothing; the story window moved out from under its own art.

    menu frame:  story=(0,0,640,400)     story_gfx=(0,0,640,400)   path=raster
    bet frame:   story=(22,235,594,156)  story_gfx=(0,0,640,400)   path=hybrid-ring

`classify_windows` keeps a window-0 Graphics out of `chrome` on the grounds that it belongs to the story and is blitted inside the story viewport instead. That holds only while the plate is inside the window it is the plate OF. With the story viewport down to one bottom panel, the table was in neither half — the chrome canvas the ring's bands are cropped from measured ZERO opaque pixels — so nobody drew it, and the pane fell back to the ring's letterbox with the host transcript in the viewport. That is what the player read as "frameless": no frame, and the boot banner ("FROBOZZ MAGIC VIDEOPOKER / by Zach Matley / ...") back on screen.

HYBRID vs RASTER: they DIFFER on this frame, and raster was already right. Raster mode never consults `picture_takeover`; it blits `story_gfx` itself, so it kept the frame. Only hybrid — the shipped default, and what the player runs — lost it.

FIX: `picture_takeover` gains a third arm, `story_plate_escapes_story_window` — the story window's own plate painting outside the story window's box. Cheap containment test first (a plate the story box contains cannot escape), then a 4px-grid alpha sample only when the boxes disagree. Corpus-measured over 8 games x 8 frames: every frame that publishes a plate at all publishes it at EXACTLY the story window's box (Arthur's intro, Journey's title, mysterious01, fmvpoker's own steady state), so the predicate short-circuits and no other title's path moves.

FALSIFIED by disabling the arm: `left: "hybrid-ring"` against `right: "raster"`, both honor_game_colours modes — the switch the player reported.

MEASURED AFTER: the bet frame's composite is BYTE-IDENTICAL to the menu frame's composite over the whole region above the bet panel (y < 235, all 640 columns, 0 differing pixels, both honor modes). The path no longer changes at all across the transition, so hybrid and raster continue to agree for this title.

STILL WRONG ON THAT SCREEN, and NOT fixable in the render lane — worth its own quest:
The bet PROMPT is lost, and so are the money lines. When window 2 becomes the input window it is published as a primary Buffer, whose `lines` are empty by construction (a primary window's prose is the host transcript) — but the prompt was printed into window 2's `prose` buffer while it was still diverted, and that buffer is simply dropped. In the same instant window 0 stops being a Buffer, so its `px_runs` shadow (which carried "Current Bet: / 10 / Total Winnings: / 1000" at (76,247)/(76,265)/(420,247)/(420,265)) is dropped too. Measured at the bet frame: window 2 publishes `lines: []`, window 0 publishes `px_texts: []`, and the host transcript is unchanged from the menu frame. So the model carries no text for that screen at all, from either window, and the composite has nothing to draw. Both losses are in the session/zvm publish path.
Consequence today: the bet screen is the frame with empty panels. Before this fix it was no frame plus a stale boot transcript, so it is strictly better — but the player should judge whether it is good enough, which is why this is `confirm` and not `done`.
