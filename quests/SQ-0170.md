Exploration (2026-07-10), deferred. Infrastructure already exists: the hints panel boots a companion Invisiclues .z5 as a 2nd Z-machine session; hints resolve locally (remembered assoc in ~/.babelmap/hints/index.toml keyed by IFID → sibling *hint*.z5 → sibling zip → ask). A downloader would only need to: fetch bytes → write ~/.babelmap/hints/<sanitized-ifid>.z5 → save_hint_assoc(user_dir, ifid, path) → open the existing panel (zero panel changes). Blockers/decisions: (1) app has NO HTTP client or async runtime today — would add e.g. `ureq` (pure-Rust, blocking, cross-platform, fits the sync loop). (2) No IFID-keyed hint-download API exists online — IF Archive hosts Infocom Invisiclues .z5 but isn't IFID-indexed; IFDB is IFID-lookup-able but returns metadata/links, not hint programs. (3) IFID we compute is ZCODE-<release>-<serial>-<checksum> (Z-code only; no Glulx IFID). Options considered: A) curated Infocom→IF-Archive-Invisiclues URL table (matched via the release+serial we already use for known_titles.tsv; covers the Infocom canon, brittle if URLs move); B) paste-a-URL downloader (minimal/general, user finds the URL); C) IFDB 'find hints online' browser links (discovery only, not in-app play); D) defer (chosen — local sibling+browser flow already serves people who have hint files; network dep + brittle external URLs not worth it for a niche feature). Safety note: a downloaded .z5 is Z-code we'd execute, but the VM is a sandbox (Glk I/O only), so acceptable. Key files: hints.rs (HintIndex/resolve_hint_source/save_hint_assoc), render/hints_panel.rs, main.rs open_hints(:5171).
