## DISCARDED — the pair carries nothing the shelf does not already have

Investigated the two Amiga images directly rather than reasoning from their names.

  `Zork Zero - The Revenge of Megaboz_Disk1.adf`  is **BYTE-IDENTICAL** to
  `Zork Zero - The Revenge of Megaboz.adf`        (`cmp` reports 0 differing bytes)

Both are v6 **release 366 / serial 890323**, and both carry the same 13 files: `Story.data` (296,448), `Pic.data` (218,880), the `Zork Zero` executable (45,852), `bine`/`bine2`, and the Workbench `.info` icons.

`_Disk0.adf` has **no story at all** — 16 files, every one of them AmigaDOS system furniture: `c/Stack`, `c/EndCLI`, `c/Echo`, `c/LoadWB`, `l/Port-Handler`, `l/Disk-Validator`, `l/Ram-Handler`, seven `libs/*.library`, and `s/startup-sequence`.

The bootblocks say which disk is which, and are the decisive evidence:

  game disk   896 non-zero bytes in the first sector  -> a real CUSTOM bootblock; it self-boots
  Disk0        83 non-zero bytes                      -> a stock AmigaDOS bootblock

and Disk0's startup-sequence is somebody's later workaround, not something Infocom shipped:

    ;de
    ;Line above commented out to disable intro as
    ;this isn't compatible with ECS and AGA Amigas
    loadwb
    endcli > nil:

So this is ONE release plus a preservationist's helper boot floppy for running the game on ECS/AGA hardware — not a two-disk press, and not a second release. `crates/app/tests/suites/real_media_releases.rs` already has it right: it pins only `Megaboz.adf` at r366/890323 and never treated the pair as a separate medium.

Discarded because the payoff is gone, not because the gap is not real: `is_index_run` genuinely does refuse a `{0, 1}` run, and that refusal is deliberate — it is what correctly rejects `{360, 720}`. But making it accept a 0-based pair would buy access to nothing, since Disk1 is the file you already open directly. The user is removing the two-disk version from the shelf.

If a 0-based Amiga pair ever turns up where the LOW disk carries content, this is the reasoning to revisit — and the check to run first is `cmp` against the standalone image, which is what settled it here in one command.
