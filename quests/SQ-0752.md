--- note 2026-08-10T03:57:48Z ---

SECOND TITLE, same lane, user 2026-08-09: **"impossible stairs also has a funny format for it's room. It starts with `Year: 2001 Place: Front Lawn`"**.

Different game from the one this quest was filed for — fixture `stories/ImpossibleStairs.z8` (The Impossible Stairs, mathbrush, 2020), not `stories/the-impossible-bottle.zblorb.blorb`. Both are in scope here because they share a lane (`crates/zvm/src/location.rs`) and plausibly a cause.

The status line is `Year: <n>  Place: <name>` — the room name is a LABELLED FIELD inside the heading, not the heading itself. Any rung that takes the whole status-line left half as the room name will record "Year: 2001 Place: Front Lawn" as a single room, and every year change will mint a new room for a place the player never left. That is a distinct failure mode from a heading that is simply not found, and it is worth checking whether the user's Impossible Bottle report is the same shape or a different one.

Do NOT hard-code `Year:`/`Place:`. A rule keyed to those literals is a per-title special case wearing a general disguise, and this quest's whole point is to avoid the fifth rung. If a general rule is not available, say so plainly and report what a principled one would need — that is a better outcome than a literal match.

Worth weighing against the corpus: `Place:` here, "CONTENT WARNING" on SQ-0733, and Facility.z8 on SQ-0731 are all cases where the status line's left half is not simply a room name. That is now four titles pointing at the same question.

So the room name IS on screen, in the conventional place, and the map gets nothing. That is the "no candidate at all" shape, not "wrong candidate".

TWO CONSEQUENCES.

1. **Do not assume the break is in `detect_location`.** A name that is visibly correct on the status bar and absent from the map can fail at detection, at publication, or in the mapper. Trace the whole chain at boot for this title — what the status line contains and how it was written, what `detect_location` returns, what the mapper receives — and report where the value stops. If it stops downstream of `location.rs`, that is a different quest and a different lane; bending a detection rung to compensate for a publication gap would be worse than filing it correctly. Note a v5 may paint window 1 itself instead of using the standard status line, in which case a rung reading the standard status line sees nothing.

Two distinct causes among the five titles is a perfectly good answer and better than one strained rule claiming all of them.
