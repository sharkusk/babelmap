THE RULE, in the user's words 2026-08-13: "in general when reading a specific disk format we should default the interpreter number to match (even on the cli), but still allow an override."

So the medium is evidence about the machine, and that evidence must reach every front-end, not just the TUI. An explicit `-I`/config interpreter number still wins — this changes the DEFAULT, never the override.

## What is broken today

`crates/app/src/interpreter.rs::InterpreterProfile::resolve` already implements the rule for the TUI: explicit number wins, else a named art archive's flavour, else the MEDIUM (`is_adf` → `Amiga`), else `IbmPc`. `zvm-cli` gained disk mounting in SQ-0834 (`crates/zvm-cli/src/media.rs`) but resolves nothing from the medium — it mounts an Amiga floppy and then advertises the IBM PC default unless the user passes `-I 4` by hand. The lane that built it flagged this and correctly left it alone as out of its scope.

`InterpreterProfile` lives in `app`, and `zvm-cli` does not depend on `app`. Decide deliberately where the medium→interpreter mapping belongs so both front-ends share ONE answer rather than two that can drift; do not copy the logic.

## The case that is BLOCKED, and must not be forced

`hints::DiskImage::Hfs` (SQ-0837) identifies a Macintosh disk, and ZMSD §11.1.3 numbers the Macintosh **3** — that number is a verifiable spec constant. **But do not apply this rule to HFS yet.**

A Mac disk currently resolves to `IbmPc`, pinned deliberately in `real_media_releases.rs` and `hfs_disk_image.rs`. The reason is recorded in SQ-0838: the Mac's default colours, palette and screen geometry are NOT established by anything in hand, and `InterpreterProfile` bundles the number together with all of them. Worse, the number is not inert — the game reads it from header byte `$1E` and can take machine-specific paths we do not implement. Announcing "you are on a Macintosh" to Zork Zero r296 while rendering it as a PC is a behaviour change nobody has evidence for.

So: implement the rule for media whose profile is already established and verified (`.adf` → Amiga, interpreter 4). HFS follows when SQ-0838's profile half lands, and that quest is where it belongs.

## Requirements this inherits

Any front-end must let an explicit interpreter number override the medium — that ordering is already `resolve`'s contract and must not be reordered. A change here affects which interpreter number a real game sees, so it needs a real-game smoke, not only unit tests: this project's rules are explicit that a unit test sharing the implementation's assumption passes anyway. The `.adf` fixtures in `stories/` are the material.
