--- note 2026-08-10T15:03:40Z ---

MEASURED while fixing SQ-0755, 2026-08-10.

    stories/journey.z6                          release 83, serial 890706
    stories/Journey - The Quest Begins.adf      release 30, serial 890322

`InterpreterProfile::resolve` reads the MEDIUM and `Adf::story` reads the story out of it, so "the Amiga build" is not the same story under a different profile — it is a **different build of the game**. The two releases genuinely differ:

    r83   win0 (241,1) 392x304  streamed=8   <- narrates here; erases win0
    r30   win0 (1,401) 640x0    streamed=0   <- LEFTOVER, prose attrs still set
          win2 (265,17) 368x272 streamed=8   <- narrates here; erases win2

That difference WAS the whole of SQ-0755's reopened defect: an erase rule that asked "is this aimed at the first prose window?" was right for r83 by luck and never right for r30.

**THE STANDING HAZARD:** every earlier investigation of Journey's frame drove the .z6. Any finding recorded as "under the Amiga profile" whose fixture was the bare story file measured a build the user does not play, and a clean result there proves nothing about their screen. Named as needing re-measurement off the floppy by the SQ-0755 agent: **SQ-0747's truncated label** (it reproduces on r30 — the first time that defect has been reproducible in any harness) and **SQ-0750's border split**.

WHAT THIS QUEST IS FOR: Zork Zero, Shogun and Arthur also ship as floppies with their own releases. The SQ-0755 corpus drove both media for all of them and they agreed — but **no committed test drives the floppy** for any title. That is the gap. A real-media suite should pin both media per title, and any test claiming to cover "the Amiga profile" should say which release it actually loaded.

Related: SQ-0719 (the ADF mount), SQ-0744 (Shogun's floppy archive), SQ-0755 (where this surfaced), SQ-0747 and SQ-0750 (whose measurements are now suspect).

ALL FOUR graphical (v6) titles ship a DIFFERENT build on their floppy. All four v3/v5 titles ship the same build on both media (identical release, serial and header checksum; the .adf copy is a few hundred bytes longer because the on-disk file is block-padded — `Adf::read` truncates to the header's byte size, so that padding is the disk's, not ours).

Arthur.blb / Journey.blb / Shogun.blb / Zork0.blb / beyondzork.blb carry NO executable chunk — a resource Blorb is never a third build. The four v6 ones declare Reso = 320x200, the same standard window `InterpreterProfile::Amiga` supplies; beyondzork.blb (v5) declares none.

THE SUITE — crates/app/tests/real_media_releases.rs, 7 cases, ~25 s:
 1. every_medium_loads_the_release_it_is_pinned_at — the table above, per medium.
 2. a_floppy_and_the_story_file_beside_it_are_pinned_against_each_other — each pair pinned as same-build or not, so an upgraded fixture fails here instead of silently rebasing an investigation.
 3. the_medium_each_release_ships_on_picks_the_interpreter_profile — .adf -> Amiga, bare -> IbmPc, on the real files (interpreter_profile.rs covers the synthetic side).
 4. a_resource_blorb_beside_a_story_carries_no_release_of_its_own.
 5. each_v6_medium_narrates_through_the_window_its_own_release_uses — the prose window + its box, both honor_game_colours modes. The SQ-0755 fact, committed.
 6. a_game_that_names_its_release_names_the_one_the_medium_carries — drives VERSION and matches the game's own words: Zork Zero ("Release 366 / Serial number 890323" vs "Release 393 / Pix 393 / Serial number 890714"), Shogun, Zork I/II/III, and ZTUU off the floppy, whose line also reads "Interpreter 4" — the Amiga profile visible in the game's own output.
 7. each_v6_medium_renders_the_story_viewport_its_own_release_lays_out — both colour modes, pane widths 80/100/138: path:hybrid-ring, and the renderer's story viewport is the box of the window THAT release narrates through (Journey floppy -> win2). First committed render of a frame produced by a disk image.

HOW A FAILURE NAMES ITS RELEASE: `ctx()` prefixes every message with "<file> [<title> — Amiga floppy|story file, release N, serial S]", and `assert_is_the_pinned_release` runs BEFORE anything is measured, so a wrong fixture fails on identity rather than on the measurement. Falsified both ways: mislabelling the Journey floppy as r83 fails all four boot cases with "loaded release 30 — this medium carries a DIFFERENT build than the table says"; pinning its prose window at 0 fails with "this release narrates through window 2, not 0 ... right by luck on one release and wrong on the other (SQ-0755)".

SKIPS: verified vacuous — with `stories/` removed the whole binary is "7 passed ... finished in 0.00s", one SKIP line per missing medium, no `ran > 0` guard fired (they are gated on `any_real_media_present`).

DOCS: docs/features/interpreter.md gained "A floppy is a different release" (the table + the reproduce-on-the-medium rule); CLAUDE.md's existing disk-image paragraph now names the suite and the table.

FOUND, NOT FIXED (coverage work):

 - A v3/v5 story mounted off a floppy is handed v6_screen_px = Some((320,200)) from the Amiga profile; harmless today (art scaling is gated on version 6) but it is a v6 concept reaching a non-v6 boot.
 - SQ-0747's truncated label and SQ-0750's border split are still recorded as measured off the .z6; this suite gives the floppy a committed harness but does not re-measure them.
