WHERE THIS CAME FROM, and it is not a defect in SQ-0886's premise. That fix is right: a chrome graphics window carrying opaque pixels has no ring to live in, so the frame must take the composite. The consequence is that hybrid's prose viewport on this screen is now Shogun's own four-row box rather than the whole pane — which is what `v6_render = "raster"` has always shipped here, and the SQ-0886 lane flagged it honestly as "the consequence worth your eye" (its `more_pager_first_new_row` case moved for exactly this reason). TWO CANDIDATE SHAPES — measure before choosing, do not assume the smaller one:
  1. **Suppress the replay.** In the composite, when the frame is a menu takeover and the story box is this small, the transcript should not re-emit lines the canvas has already drawn. Option 1 is the one to try first, but confirm by measurement that nothing on this frame is transcript-only before suppressing anything: if any line reaches the user ONLY via the replay, suppressing it loses text, and that is worse than the collision.

FIX SHAPE REFRAMED BY THE USER 2026-08-15, and this supersedes the two candidates in the note above. Both of those were heuristics — "is the box small?", "is this a menu takeover?" — and the right question is not a heuristic at all: **the renderer should know a line is already on the screen and not draw it twice.**

**THE MECHANISM ALREADY EXISTS IN THIS CODEBASE. IT IS JUST IMAGES-ONLY.** `crates/app/src/session.rs:2558-2578`, from SQ-0461 decision 3:

    // a large CONTENT-art draw into a graphics window (Shogun's title splash)
    // ALSO anchors a transcript inline band, so the frameless mode — which drops
    // graphics windows — still shows it. … Hybrid/raster ignore ContentSplash
    // entries (they render the window canvas itself), so no double-draw.

`crate::inline_image::ImageSource::ContentSplash` IS the "already painted on the canvas" mark. The transcript entry exists for the one mode that needs it (frameless, which has no graphics window), and the modes that render the canvas themselves skip it. That is precisely the rule this quest needs — SQ-0461 reasoned it through for pictures and shipped it.

Text has NO equivalent. Shogun's credits reach the screen twice by two unrelated routes: as `PxText` runs in `GridWindow::px_texts` (`crates/app/src/engine.rs:171`, with `PxText` at :174) painted into the v6 canvas, and as ordinary transcript lines. Nothing marks them as the same content, so the composite draws both — the canvas rendition up top, the transcript rendition into the four-row prose box, on top of the menu.

**SO THE FIX IS TO GIVE CANVAS-PAINTED TEXT THE SAME PROVENANCE PICTURES ALREADY HAVE**, and have the canvas-rendering modes skip it for the identical reason they skip `ContentSplash`. Symmetry with an existing, deliberate, documented decision — not a new special case, and it removes the duplication at its source rather than hiding it behind clipping.

What to establish before building it:
  - Does a v6 story's `px_texts` paint ALWAYS correspond to transcript text, or only sometimes? If only sometimes, the mark has to be set where the correspondence is known, exactly as `is_content_art` gates the picture case rather than tagging every draw.
  - **Frameless must keep working.** It is the whole reason the transcript entry exists for pictures — it drops graphics windows, so for it the transcript IS the only route. Whatever mark you add must be one frameless ignores, not one that deletes the entry. Verify frameless on all three presses before and after; a fix that cleans up hybrid by emptying frameless's screen is a worse bug than the collision.
  - Confirm by measurement that nothing on this frame is transcript-ONLY. If any line reaches the reader only via the replay, suppressing it loses text.
  - Check the dedupe precedent too: the picture path already guards against a per-turn redraw spamming the transcript (`last_content_pic`). Canvas text redrawn every turn would need the same care.

The SQ-0888 lane is currently working `ContentSplash` handling at `screen.rs:3292` (`build_main_text` skips it on the stated assumption that hybrid draws the graphics window itself — which for the Apple press it does not). That is the SAME mechanism seen from the other side: SQ-0888 is a case where the skip is WRONG because the canvas never gets drawn, and this quest is a case where a skip is MISSING. Whoever takes this should read SQ-0888's resolution first; the two answers must be consistent, and if SQ-0888 changes the ContentSplash contract this quest inherits it.
