SCOPE DECIDED (user, 2026-07-29). Display: **numeric average to one decimal** (`3.8`), NOT star glyphs. Also: **add rating as a sort key** to the picker's `s: sort` cycle; unrated stories sort last.

Data is already fetched and discarded — no new network call, no new endpoint. Verified against the captured real IFDB response at `crates/app/tests/fixtures/ifdb-zork1.xml` (not from memory): the `viewgame?ifiction` XML carries, at path `/ifindex/story/ifdb/`:
  - `averageRating`  = `3.81858407`   <- the one to display, rounded to 1dp
  - `starRating`     = `4`            (IFDB's own rounded-to-half-star value)
  - `ratingCountAvg` = `226`
  - `ratingCountTot` = `226`
These sit in the same `<ifdb>` element that `ifiction::IfdbExt` already parses for tuid/link/cover_url, so this is a field addition to an existing parse site (`crates/app/src/ifiction.rs:26`), not a new parser.

Work outline:
1. `ifiction.rs` — add `average_rating: Option<f32>` (and likely `rating_count: Option<u32>` even if unshown, for the sort tiebreak) to `IfdbExt`; parse from the element names above. Guard against IFDB omitting the block entirely for unrated games.
2. Sidecar — `story_info` persists the PARSED struct, not the raw XML, so **every already-fetched story on disk has no rating until re-fetched**. Pre-release, breaking the sidecar shape is fine (no back-compat shims). Decide render for the missing case (blank column, not `0.0`) and note in the commit that `r` (refresh) repopulates.
3. `picker.rs` — carry the rating on the picker `Entry` alongside `year`.
4. `picker_ui.rs` — new column; keep it narrow (4 cells: `4.6` plus a pad) so title/author don't crowd on a small pane. Add the sort key to the existing `s`/`d` cycle.
5. Tests: parse-with-rating, parse-without-`<ifdb>`-rating, sort ordering with unrated entries last, and column render.
6. Docs per standing policy — this is a user-visible picker feature, so it belongs in the story-list/interface docs.
