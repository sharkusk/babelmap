--- note 2026-07-16T22:11:16Z ---

DECISION (2026-07-16, architecture session): implement v6 NATIVELY in zvm, not via Glk. v6's pixel-exact window layout is the part Glk models least cleanly, and native integrates as an additive extension of the existing zvm (admit v6 in parse_header; add a `6 =>` packed-address arm mirroring v7 at memory.rs:170; ~18 v6 graphics/window opcodes are EXT opcodes that slot into the existing EXT dispatch + fallthrough; version-6 branches in set_window/split_window/erase_window/set_cursor/set_colour; the substantive new piece is a v6 window model extending the ScreenState→ScreenModel adapter, with picture rendering reusing blorb Pict + app graphics.rs). Native v6 is decoupled from the glk-crate extraction (SQ-0386) — it targets ScreenModel directly. Guardrail: v6 graphics nodes must reuse the same ScreenModel graphics representation the Glk path produces. Full rationale: docs/design/2026-07-16-glk-crate-and-format-strategy.md.

--- note 2026-07-22T03:11:41Z ---

DECISION (2026-07-21): text-over-graphics policy = **cell-text-wins tiling**. v6 windows are modelled as cell-quantized tiles reusing the existing ScreenModel text + graphics nodes (the Glk render path). v6 pixel window-rects snap to the nearest cell; the tiling WinNode tree renders unchanged; text stays real terminal text (themeable, automap-scrapeable). For the overlap case (text printed onto a picture), cell-text wins and the picture shows through the gaps — consistent with the existing thin/uniform cell-sampler in render/graphics.rs. Explicitly NOT doing arbitrary pixel overlap / z-ordered compositing (would need a new z-axis compositing plane; only a handful of modern titles would exercise it). This caps fidelity for sub-cell positioning + proportional-font text-over-image, which is acceptable for the real corpus (Infocom v6: Zork Zero, Arthur, Shogun, Journey use text-window + picture/border-window layouts that quantize cleanly).
