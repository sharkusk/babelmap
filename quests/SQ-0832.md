Verified against main after SQ-0831 merged. Two separate facts, and the second is why this is a lane and not a one-line edit.

**1. `Action::BandWheel` moves a cursor.** `crates/app/src/input.rs`, the `Action::BandWheel(col, delta)` arm, calls `b.scroll[col].move_by(delta as isize, vp, &anim)`. Its own comment reads "The wheel scrolls the HOVERED column", which is the intent — the call is not it. The existing test `wheel_scrolls_a_column_without_taking_focus` asserts `scroll[COL_HERE].selected == 1` after one notch, so it pins the cursor step and will need retargeting to the new rule.

**2. The band never publishes a viewport.** `modal_list_viewport` is written in exactly four places — `render/saves.rs:352`, `render/config_screen.rs:376`, `render/filebrowser.rs:227`, and `main.rs:1712` (carrying `panes.modal_list_viewport`). None of them is the command band, and `AppState::default()` starts it at 0.

That is what makes this more than a filter swap. With `move_by` a zero viewport is harmless — `ensure_visible` no-ops and the cursor still steps — so the missing plumbing has never been visible. `ListScroll::scroll_by` (SQ-0831) returns early on `viewport == 0`, correctly: you cannot scroll a window whose size you do not know. Convert the call without plumbing the viewport and the band's wheel goes dead instead of scrolling.

So the work is: give the band's columns a real viewport from `render/command_band.rs` (per column — the columns need not be the same height), carry it the way the other modals carry theirs, and only then move the arm onto `scroll_by`. Whether it belongs in `modal_list_viewport` or in the band's own state is a design call — the band is a dock, not a centered modal, and it can be open while a modal is not, so sharing one global slot with the modals is the thing to look at first.

**Also found and not yet addressed:** the picker's launch-options dialog (SQ-0789, `launch_row_rects` in `picker_ui.rs`) has a row cursor and no wheel handling at all, so a notch over the open dialog scrolls the story list BEHIND it. Its list is short enough that the SQ-0831 rule would make scrolling a no-op there, so the fix is to swallow the notch rather than to scroll — a modal must not leak its wheel to the surface underneath.
