DESIGN (from bug-B headless trace, confirmed): the two @save paths are distinguished by Glk fileref creation method —
• GAME AUTO (silent, no prompt): `glk_fileref_create_by_name` (selector 0x0061), fixed SavedGame names — CM uses `_Counterfeit_Monkey-startup-data` (the init-skip cache), `_autotesting`, `_undo-<uuid>-N`, etc.
• PLAYER save verb (the ONLY UI/prompt case): `glk_fileref_create_by_prompt` (selector 0x0062) — the single create_by_prompt in the whole CM session (usage=1 SavedGame, fmode=1).
WHY IT'S NOT A SMALL ADD-ON: the VM doesn't yet distinguish the methods — `FileRef` has no `by_prompt` flag, `create_by_prompt` returns a name without suspending, and `StepResult::SaveRequest`/`PendingSaveLoad` carry NO fileref identity to the host, so both gvm-cli and the app prompt on every @save.
FIX SHAPE: thread `{name, by_prompt}` through the SaveRequest/PendingSaveLoad API (gvm), and branch in BOTH hosts — named fileref → silent read/write of a fixed `.qzl` in the per-game `.save` dir + auto-restore at boot; prompt fileref → the save UI. Symmetric for @restore (auto-restore the named slot at boot, no prompt). HOOK ALREADY PRESENT: `Model::savegame_streams` (Null-stream → fileref name), landed in the SQ-0292 fix 1a03f49, makes the name recoverable at @save time. Confirmed the "Save failed." bug (SQ-0292) also reproduces in gvm-cli (shared gvm path). NOTE: the bug-B agent's report calls this follow-up "SQ-0295"; the canonical quest is THIS one, SQ-0296.
