MEASURED 2026-08-10.

`hints::hint_download_for(game_stem, game_title)` takes the stem from **`entry.path.file_stem()`** — the container's filename — and matches with:

    normalize_ident(s) = s.chars().filter(is_ascii_alphanumeric).lowercase()
    matches(key) = key.len() >= 3 && (stem.contains(key) || title.contains(key))

against curated keys like `zork1`, `zork2`, `zork3`, `ztuu`.

A bare story file is named for its identity — `zork1-r88-s840726.z3` normalizes to `zork1r88s840726`, which contains `zork1`. **A disk image is named for the box**, and none of ours contain their key:

    Zork I - The Great Underground Empire.adf   -> zorkithegreatundergroundempire   vs key zork1  (roman numeral, not digit)
    Zork II - The Wizard of Frobozz.adf         -> zorkiithewizardoffrobozz         vs key zork2
    Zork III - The Dungeon Master.adf           -> zorkiiithedungeonmaster          vs key zork3
    Zork - The Undiscovered Underground.adf     -> zorktheundiscoveredunderground   vs key ztuu   (abbreviation appears nowhere)

So the match fails for exactly the titles that DO have a hint file. `title` cannot rescue it when the picker's title also derives from the filename.

STILL TO CHECK, do not assume: whether Arthur, Journey, Shogun, Zork Zero and Beyond Zork have entries in `SLAG_HINTS`/`IZM_HINTS` at all. Only the first few `IZM_HINTS` rows were read. If they are absent, "no hints for those titles" is correct behaviour and only the Zork I/II/III + ZTUU cases are the defect.

ROOT CAUSE, and it is the same lesson as SQ-0760: **the medium is not the story.** Hint lookup should key off the loaded story's identity — release + serial, or the Treaty of Babel IFID — not the file stem. Release and serial are already read when mounting (`crates/app/tests/real_media_releases.rs` pins them for every medium), so the identity is in hand at the point the lookup happens.

Care needed: the filename path must keep working for the many stories that are only ever bare files, and `hint_matches_story` / `pick_hint_candidate` / `load_hint_index` also key on names — a change here should not break local sidecar detection, which is the common case.
