--- note 2026-08-11T15:55:47Z ---

THE BUG: `qwertty-term-vt` 0.4.0, `src/kitty/exec.rs:208` — `debug_assert!(!load.more)` fires on a CHUNKED transmit-and-display (`a=T` with `m=1` continuation chunks). `load_and_add_image` hands back the deferred `display` on EVERY intermediate chunk instead of only the final one. Upstream Ghostty defers it.

REPRODUCER: any real babelmap capture. `kitty_transmit_virtual` (`crates/app/src/render/graphics.rs:1331`) chunks every upload at 3072 bytes, so a debug build trips on chunk 2 of the first image.

BEHAVIOUR WITH THE ASSERTION COMPILED OUT (i.e. release): correct — the premature display finds no stored image and is refused, the final chunk places the image properly. So it is a mis-placed assertion, not a logic error in the release path.

OUR WORKAROUND, which should not be permanent: `[profile.dev.package.qwertty-term-vt] debug-assertions = false` in the workspace `Cargo.toml` (commit 18c4f924), fully commented. Remove it when a fixed version ships.
