--- note 2026-07-29T17:48:23Z ---

PROVEN EMPIRICALLY, not inferred. A throwaway test parsing a style.toml string and resolving it:

    [symbols] diagonal_corners = false  ->  parsed=None  resolved=true
    [map]     diagonal_corners = false  ->  parsed=None  resolved=true

The switch cannot be turned off from any config file. Users on fonts without Unicode 13 Symbols for Legacy Computing coverage (reported in iTerm2) have NO escape hatch — the half-diagonal stubs `U+1FBA0`-`U+1FBA3` are forced on.

WHY IT IS DEAD — the plumbing is complete except for one link:
  - `crates/app/src/style.rs:139` — `StyleSymbols.diagonal_corners: Option<bool>` EXISTS.
  - `crates/app/src/style.rs:162` — `finalize_symbols` reads it into `SymbolConfig`. WORKS.
  - `crates/app/src/style.rs:292` — `merge` layers it for per-game overrides. WORKS.
  - `crates/app/src/symbols.rs:404` — `SymbolSet::resolve` carries it to the renderer. WORKS.
  - `crates/app/src/style.rs:385-403` — the `[symbols]` TOML parser handles ONLY `box_style`, `arrow_set`, `portal_icons`, `path_style`, `overrides`, then `_ => {}` with the comment "unknown symbol keys ignored". **`diagonal_corners` falls into that arm and is dropped.** <- THE BUG
  - No `map.diagonal_corners` row in `crates/app/src/theme/registry.rs`.
  - `Config` has no `symbols` field, so config.toml cannot supply it either (`config_has_style_sections` only DETECTS a legacy `[symbols]` to warn about migration).
So the field is always `None` and `finalize_symbols` always falls back to `default_diagonal_corners()` = `true`.

FIX: add the missing parser arm — `"diagonal_corners" => symbols.diagonal_corners = val.as_bool(),` — plus a test that a style.toml STRING round-trips to `SymbolSet.diagonal_corners == false`. The existing test (`symbols.rs:659`) only covers `SymbolConfig -> SymbolSet` and so never touched the broken link; that coverage gap is why this shipped.

ALSO ADD IT TO THE USER-FACING SURFACE: it is absent from `style.example.toml` and from `theme/template.rs`, so even once it works nobody would discover it.

DOCS ARE ALREADY OUT AHEAD OF THE CODE — fix these together or they will lie:
  - `README.md` (commit 510fe702) now says the switch is "not yet wired up" and lands "in the next release". When this quest closes, that caveat MUST be removed.
  - `docs/features/mapping.md:175` states flatly that "`diagonal_corners` toggles the half-diagonal corner stubs off for fonts without Unicode 13 coverage" — that is currently FALSE and should be corrected or fixed-by-this-quest.

SEPARATE BUG FOUND ALONGSIDE, NOT PART OF THIS QUEST — see the sibling quest: `style.example.toml` documents the glyph presets (`box_style`, `arrow_set`, `portal_icons`, `path_style`, `portal_path_style`) under `[map]`, but `parse_style_toml` reads them from `[symbols]`. Probe: `[symbols] box_style = "double"` -> `"double"`; `[map] box_style = "double"` -> `"rounded"` (the default). The `[map]` rows exist in `theme/registry.rs` but nothing resolves them at runtime, and `render/map.rs` consumes `SymbolSet`.

Priority HIGH because the docs currently promise a fix that does not exist, and real users are hitting the underlying glyph problem now.
