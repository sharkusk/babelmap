--- note 2026-07-20T20:56:36Z ---

Feasibility research (2026-07-20). Difficulty: MODERATE — quite doable; the quit path is already clean.

Current structure (single-shot / linear):
- `boot()` in crates/app/src/startup.rs: install_termination_handlers() (ONCE) -> run_story_picker() (startup.rs ~83, only when the arg is a directory; returns Some(story) or exit(0) on quit) -> build engine/session/AppState/audio (state.audio at ~423) -> run the play loop -> process ends.
- The play loop exits via a clean `break 'event_loop` (main.rs ~1059/1072/1101), NOT process::exit (those exits are error paths only). restore_terminal() (LeaveAlternateScreen etc., main.rs:72) already runs on the way out. So quit is a tidy return and the terminal is already restored.

Work required:
1. Extract "play one story" (per-story setup + play loop, currently inline in boot) into a fn returning a QuitOutcome { ToLibrary, ExitApp }.
2. Wrap picker + play in a loop: pick -> play -> on ToLibrary loop back to the picker; on ExitApp (or picker returns None) exit.
3. Quit semantics: a directory launch (story_path.is_dir(), knowable at boot top) -> quitting a story returns to the library; quitting the library exits. Add a distinct "return to library" outcome/command.
4. Keep one-time setup (signal handlers) OUTSIDE the loop; per-game state (engine, session, state.audio, VFS sidecar, save) is already function-local and rebuilds naturally each iteration.

Main risk: terminal alternate-screen enter/leave hygiene across the picker<->play handoff — each brackets its own alt-screen, so ensure play leaves its alt-screen before the picker re-enters, every loop.

Estimate: ~half-day to a day: mostly the boot() control-flow refactor + verifying the alt-screen handoff + a manual TUI smoke (hard to unit-test the loops). No new engine/state plumbing needed.
