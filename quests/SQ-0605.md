## Evidence (measured 2026-08-03)

Byte-identical copies in BOTH `zvm-cli/src/screen.rs` and `gvm-cli/src/glk_term.rs`:
`osc_set_bg`, `osc_reset_bg`, `cursor_steady_block`, `cursor_reset`, `page_bg_escape`.
(A sixth, `rgb24`, exists only in gvm-cli.)

The drift argument is not hypothetical: the stdin-EOF bug. zvm-cli fixed it long ago
(`read_byte_or_eof` + clean exit); gvm-cli carried the identical defect until SQ-0604,
months later. Same bug, two codebases.

Teardown (raw mode off, OSC reset, cursor reset) is duplicated in zvm-cli and gvm-cli
and ABSENT from scott-cli. `parse_args` exists separately in zvm-cli and scott-cli;
gvm-cli parses inline.

## Scope: plumbing, NOT renderers

Share: terminal escape helpers; input reading (cooked/raw line + char, EOF -> clean
exit); an RAII teardown guard so every exit path restores; the Rich/Plain mode
decision; common flags (`--version`, `--help`, `--plain`).

Do NOT share the renderers. `gvm-cli/glk_term.rs` (2016 lines) and `zvm-cli/screen.rs`
(807) have essentially no logic in common — Z-machine windows, Glk windows and Scott's
prose are genuinely different models, and scott-cli (244 lines) would pay for machinery
it does not need. Each CLI keeps its renderer and asks the shared mode what to do.

Estimated ~300-400 lines, mostly moved rather than written.

## Why it matters for accessibility

With it, plain mode is decided once and each CLI honours it. Without it, screen-reader
mode is implemented and maintained three times — and the EOF bug says they will drift.
See [[SQ-0606]].

## Shipped 2026-08-03 — commit cd93a404

`crates/cli-host` (586 lines incl. tests + docs); CLIs net -113 lines
(133 insertions / 246 deletions across 8 files).

### What it owns
- `term.rs` — the five formerly-duplicated escapes + `rgb24`; `restore_terminal`,
  `restore_and_exit`, `TerminalGuard`.
- `mode.rs` — `HostMode`: separates the device fact (`stdout_tty`) from the
  decision (`rich`), and `stdin_tty` from `raw_input`. `detect_with(force_plain)`
  is the seam SQ-0606 plugs into; every caller passes `false` today, so behaviour
  is unchanged. Published process-wide via `install()` because the exit paths that
  need it are several frames below anything that could be handed a copy.
- `input.rs` — the EOF rule + `exit_at_eof`.
- `flags.rs` — `--help`/`--version` (name/version passed in, so `env!` expands in
  the *binary's* crate).

Owns none of the drawing, as scoped.

### Two real bugs found and fixed by consolidating

**1. The EOF bug had a THIRD copy.** zvm-cli's *line* path had it all along, one
function over from where the char path was fixed months ago. Measured on the
pre-change build: `zvm-cli gostak.z5 < /dev/null` → 3.6 MB of `>Louk?` under a
pty, killed by SIGKILL. After: 808 bytes, exit 0. This is the quest's own thesis
landing harder than expected — the note said "same bug, two codebases"; it was
three.

**2. zvm-cli's EOF exit never restored the terminal.** It called
`process::exit(0)` directly, so `echo cmds | zvm-cli story.z5` in a real terminal
left the shell with the game's page background and a block cursor. Verified under
a pty: baseline emits no OSC 111 and no DECSCUSR reset; new build emits both plus
the scroll-region reset. Nothing restored on a panic in any of the three either —
`TerminalGuard` now does.

### Design decision worth carrying forward
`TerminalGuard` has two flavours. `new()` restores everything; `raw_only()` leaves
raw mode and emits NOTHING. scott-cli takes `raw_only` — the full guard would have
put 15 bytes of escapes into the one transcript that has never had any, which is
precisely the property that makes it the cheap SQ-0608 pilot. Restore what you
set. Verified: scott-cli's pty output is still 600 bytes with zero escapes.

One behaviour change, deliberate: the page-background release is no longer
honor-gated on the normal-exit paths. OSC 111 restores the terminal's own default,
so sending it when no colour was honoured is a no-op — and both Ctrl-C paths had
already reached that conclusion independently.

### Verification
- Transcripts byte-identical vs. the pre-change build (a `git worktree` at HEAD):
  4 Z-machine stories, 5 Glulx, 3 Scott. `--help`/`--version` identical for all
  three binaries in all four spellings.
- Terminal restore compared under a pty (piped stdin + TTY stdout) on the EOF,
  normal-quit and Ctrl-C paths.
- Gate: 0 errors, 64 binaries == 64 `test result:` lines. Clippy clean.
- Falsified: reintroducing the EOF bug fails 4 cli-host tests with `Some("")` for
  `None`, fails both CLIs' own retained regression tests, and brings back the
  90 KB hang (exit 124).

### Not verified

end-to-end; the unit tests cover the latch and the flavour only.
