DECISION (user, 2026-07-29): **WIRE THEM UP, under `[elements]`.** Not deleted, and not given their own `[picker]` section.

Rationale: `[elements]` is already where the story picker's selectors live — `story_badge`, `story_title`, `story_info`, `story_info_label`, `story_rating` (added by SQ-0529) are all `Section::Elements` rows in `crates/app/src/theme/registry.rs`. Putting the badge GLYPHS beside the `story_badge` selector that COLOURS them keeps one concept in one place, and avoids adding a `Section` variant for six keys. The main win for users: Nerd Font owners can swap the plain `Z`/`G`/`B` letters for real icons.

Current defaults (`crates/app/src/config.rs:52-57`), which must remain the fallbacks:
    badge_zcode = "Z"   badge_glulx = "G"   badge_blorb = "B"
    badge_save  = "S"   badge_hint  = "H"   badge_hint_available = "h"

The plumbing already exists and is the SAME shape SQ-0557 fixed for `diagonal_corners`: the six fields are on `StyleSymbols` and `SymbolConfig` and feed `picker::BadgeGlyphs` — only `parse_style_toml` never read them (not even under the old `[symbols]`), and `Config` has no `symbols` field. So this is the missing parser arms plus registry rows plus template/example surfacing, exactly as SQ-0557 was.

Do NOT put these under `[map]` — they are picker-row glyphs, not map glyphs. `[map]` is now canonical for the MAP's glyphs only (SQ-0558).

`docs/features/interface.md` currently says the badges are not settable yet (corrected during SQ-0558 because the old text pointed at a `[symbols]` section that no longer exists). That line must be updated to describe the real `[elements]` keys when this lands.
