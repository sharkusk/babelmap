--- note 2026-08-13T06:48:58Z ---

REGRESSION — reopened. The band beside the drop cap and room icon IS fixed (user confirmed by
eye), but the same build introduced a new artifact.

SYMPTOM: a very thin dark line down both edges of the story pane, on Amiga Zork Zero.
The user attributes it to this fix specifically ("that was introduced with the dropcap fix").

MEASURED off their screenshot (583x850):
  - exactly ONE PIXEL wide, at x=86 (left edge) and x=497 (right edge)
  - colour RGB(130,130,130) against the page's RGB(163,163,163)

The width is the puzzle worth starting from: a cell-level background run cannot produce a
one-pixel line — only a bitmap can, or a rasterised path where runs become pixels rather than
cells. `margin_ground_run` inserts a background run over the reserved columns, which is cells.
So either the artifact is downstream of the runs in a path that rasterises them (the raster
composite, or the hybrid ring's own bands), or the line is not what it appears to be.

I first attributed this to SQ-0824's Triangle downscale blending a hard crop boundary — the
user corrected me. Do not spend time on that theory; bisect instead.

--- note 2026-08-13T07:16:20Z ---

RESOLVED (135b60ec, branch worktree-agent-a0f2607ca6e6660d4) — and the attribution was wrong
in BOTH directions. Bisected with the pty harness, same frame, 83x50 at 7x17 (a 581x850 frame
against the user's 583x850):

  004af8a7 (before both)                 — no line
  e39fc95f (SQ-0824, area filter)        — LINE, x=84 and x=496, RGB(142,142,142) vs page 173
  adbc192c (after 0824, BEFORE 2f1adcb4) — line still there
  cf90bbae (HEAD)                        — line still there

So SQ-0824's resample introduced it and the drop-cap fix (2f1adcb4) is exonerated. That was
worth proving: a background run works in cells and cannot draw a sub-cell line at all.

ROOT CAUSE: non-premultiplied alpha. `image::imageops::resize` filters the four RGBA channels
independently, and a transparent pixel carries (0,0,0) behind its zero alpha. Zork Zero's flank
crop ends in the story page abutting CLEAR canvas, so shrinking 95 native px to 84 emitted
(38,38,38,57) at the seam — over the page the band is drawn on, 38·57/255 + 173·198/255 = 142
against 173. Read straight out of the emitted kitty RGBA payload, so it is not an inference.
Width-dependence follows: past ~95 columns the flanks GROW, take the Nearest arm, and never
blend (measured 70/83/90 = line, 95/100/110 = none).

FIX: `resize_directional` associates alpha across a blending pass and unassociates after. Seam
now goes out (170,170,170,57) → composites 172 vs 173. Bit-identical on fully opaque art
(at a=255 both directions are exact), so every SQ-0824 RMS number stands.

Tests: 4 new unit cases in `render::graphics::resample_tests`, plus a real-game suite
`crates/app/tests/suites/pty_flank_alpha_seam.rs` (pty + oracle, both honor_game_colours modes,
skips without the floppy). Falsified at both layers. Gate 4977/4977, clippy clean.
