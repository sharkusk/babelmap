## What is stale, and what it actually costs

`Picker` is built in exactly two places — `picker_ui.rs:713` (story picker) and `startup.rs:419` (session start) — both via `build_cover_picker`, which calls `Picker::from_query_stdio()`. Every `Event::Resize` arm in `main.rs` (1967, 2034, 2325, 3098) only calls `clear_terminal`. Nothing rebuilds the picker, so `picker.font_size()` is whatever the terminal reported at launch, for the life of the session.

**The absolute value does not matter; the RATIO does.** `v6_halfblocks_grid` computes `box_w = cols * fw` and then converts back with `tw.div_ceil(fw)` — a uniform scale error in fw and fh cancels exactly. What survives is `fw:fh`.

And that ratio is not stable across font sizes, because a cell is `round(adv_em * px)` by `round(line_em * px)` and the two round at different rates. Measured (see SQ-0986): FiraCode Nerd Font, em ratio 2.002, yields cell ratios from **1.750 (4x7 @ 6px/em)** to **2.250 (4x9 @ 7px/em)** on ADJACENT sizes. A user who starts at one and moves to the other leaves lanthorn fitting with an aspect 29% wrong, and the composite is stretched until restart.

Symptom to expect: art looks subtly stretched after changing font size, and correct again after a relaunch — which makes it very easy to misattribute.

## Why it is startup-only today, and the cheap fix

`from_query_stdio` **reads stdin**. Doing that mid-session, with the app in raw mode owning the input loop, means interleaving a terminal round-trip with real keystrokes — genuinely delicate, and almost certainly why nobody did it.

But the crate's fallback needs no round-trip at all. `font_size_fallback()` is a `tcgetwinsize` syscall returning `FontSize::new(ws_xpixel / ws_col, ws_ypixel / ws_row)`. That can be re-read on every resize for free, with no stdin interaction and no protocol negotiation. Suggested shape:

- On `Event::Resize`, re-derive the cell from `tcgetwinsize`.
- Use it only when `ws_xpixel`/`ws_ypixel` are non-zero; otherwise keep the existing value rather than falling to a default and making things worse.
- Do NOT re-run the capability query — the protocol (kitty/sixel/halfblocks) has not changed, only the cell.
- Invalidate the caches keyed on cell geometry when it moves: `GraphicsRender`'s per-window cache is keyed on `(version, area.width, area.height)` in CELLS, which does not change when only the pixel size does, so a stale composite could survive a font change that should have rebuilt it. Check `chrome_bands` and the v6 ready-encode key for the same hazard.

## Platform caveat

`font_size_fallback` is `#[cfg(not(windows))]`; the Windows arm returns `None`. So on Windows a terminal that does not answer `CSI 16 t` has no backstop at all, and this fix would not reach it. Worth stating in whatever lands rather than silently helping two platforms of three.
