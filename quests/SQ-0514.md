--- note 2026-07-25T14:10:30Z ---

Diagnosis (probe-verified, debug build): full render_story_pane = ~377ms on every turn vs ~18ms on identical-frame cache hit. Chain: Score/Moves rasterized into the chrome canvas each turn (on-art, not carved out) → draw_chrome_band cache key hashes the ENTIRE canvas raw bytes (graphics.rs:452-461) → one changed digit invalidates all ~4 ring bands → each miss resizes the whole 640×400 canvas (once PER band), re-encodes, and re-transmits a full image synchronously on the UI thread (terminal-side decode = the GPU spike). Fix order: (1) B2+C now — hash only the band's own crop + scale once per frame, graphics.rs-only, >4× cut; (2) A after SQ-0511 — off-thread band encode with last-good-frame reuse mirroring SQ-0469's raster worker (conflicts with SQ-0511's screen.rs hybrid-arm rewrite, so sequenced after).
