## Shipped 2026-08-03 — commit 257ca2f7

### The bug, measured before
- `zvm-cli stories/gostak.z5 --no-statu` → exit **0**, flag silently ignored
- `gvm-cli stories/ABCA5.gblorb --plane` → exit **0**, same
- `zvm-cli -x` → taken as the story path, reported as "cannot read '-x'"
- `scott-cli --bogus` → exit 2 (the only one that was right)

### Answer to "are these all using the common code?"
Initially no — I had shared only the *policy* (`usage_error`, `looks_like_flag`,
`EXIT_USAGE`) while leaving three separate scanning loops. That is the same
shape as the LineHold duplication and would have drifted the same way, so the
loop moved into `cli_host::args` too.

`Opt::flag(&[names])` / `Opt::valued(&[names])`, first name canonical, aliases
after. `scan(argv, opts) -> Result<Matches, String>`. Each CLI declares only its
table; the flag sets genuinely differ (`--volume`/`-I`, `--no-accel`, `--seed`)
but the rules never did.

Four rules, one place: valued options consume the next argument (error if
absent); anything else flag-shaped is an unknown-option error; everything else is
positional in order; `--` ends option parsing (new — a story file called `-x` is
now reachable).

### Fallout worth noting
- Removed three redundant argv scans in zvm-cli — `parse_game_colours`,
  `parse_interpreter`, `parse_volume` each walked the command line again for one
  flag. They read off the single scan now, via new `Args` fields.
- `parse_args` returns `Result` instead of exiting. This matters for testing:
  `usage_error` calls `process::exit`, so with the old shape a broken parser
  aborted the whole test binary rather than failing an assertion. (The gate still
  caught it — `error: test failed` matches the grep — but the message was
  useless.)
- scott-cli now rejects a `--seed`/`--max-turns` that does not parse. Silently
  ignoring it would make a run look reproducible when it is not.
- Exit code: 2 everywhere for usage errors, including zvm-cli's "no story file"
  which was 1. Deliberate — 2 is the shell convention and is now distinct from
  the 1 these binaries use for an unreadable/invalid story file.

### Verified
All three produce identical messages and exit 2 for: unknown option, single-dash
unknown, missing value, extra positional. Every documented flag still parses,
including value-taking ones. Transcripts identical to the previous build across
4 Z-machine + 4 Glulx + 3 Scott with `-I`/`--volume`/`--seed` exercised.
Gate 0 errors, 64 == 64. Clippy clean. Falsified twice; each failure hits both
the cli-host test and the CLI's own.

### A test that guards the next flag
`every_documented_flag_parses` (zvm-cli) walks every flag in HELP through
`parse_args`. It is what catches a flag added to the help and its reader but not
to the OPTS table — the new way to get this wrong now that unknown options are
rejected.
