FIXED (c87f998). Third and last piece of SQ-0360's fallout, and the one my OWN SQ-0223 change set up.

CAUSE: draw_portal_icons has three fixed slots — portal_slot maps Up→0 (top), Down→2 (bottom), In/Out/Unknown→1 (right), and `_ => None` for every compass direction. SQ-0223 (earlier the same day) deliberately routed interlayer edges through those slots IN PORTAL VIEW, to preserve the floating "Room · Layer" label that the plain badge path cannot draw:
    if edge.is_interlayer && !show_labels { layer_badges.push(..); continue; }
    let Some(slot) = portal_slot(edge.dir) else { continue };   // <- compass lands here
That was correct while only portals could cross a layer. peel-layer <direction> (SQ-0360) made compass crossings real, and they hit `portal_slot(..) -> None -> continue` and vanished — icon AND label. Reproduced side by side: a Down seam drew `╚════↓════╝` + "There · There" while an East seam drew a bare box. With labels OFF the same edge showed `▶` (SQ-0362's path), which is what made it look arbitrary rather than systematic.

FIX (user chose "on the border it points at, with its label", over an in-room badge): `portal_border_placement((bx,by), bearing) -> (glyph_cell, label_cell, right_align)`, one rule for all eight directions:
    col = dx<0 ? bx : dx>0 ? bx+BOX_W-1 : bx+BOX_W/2
    row = dy<0 ? by : dy>0 ? by+BOX_H-1 : by+BOX_H/2
    label: any vertical component -> above/below at col bx; purely horizontal -> out to the side on the glyph's row, right-ALIGNED when westward so the name runs back toward the box.
STRONG SIGNAL IT IS THE RIGHT RULE: it reproduces the three fixed slots exactly — Up (bx+BOX_W/2, by), Down (bx+BOX_W/2, by+BOX_H-1), eastward In/Out (bx+BOX_W-1, by+BOX_H/2 = by+2 at BOX_H=5). Same rule they always were, written for every direction instead of the four that used to be possible.

Rendered proof, all five directions:

  N:  Vault · Vault / ╔════▲════╗     S:  ╚════▼════╝ / Vault · Vault
  NE: Vault · Vault / ╔═════════↗
