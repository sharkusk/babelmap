CONFIRMED, SQ-0726 (where it was the prime suspect — and where it turned out NOT to be the cause of that quest's input-echo defect).

Boot sunburst.z6, press `s` at the menu, and `screen()` publishes a `Layered` root with TWO entries, both `Buffer { primary: true }` at pixel rect 640x400 @ (0,0):

    [0] cell 0x0 @(0,0)   px 640x400 @(0,0)   Buffer primary=true  px_runs=14
    [1] cell 80x25 @(0,0) px 640x400 @(0,0)   Buffer primary=true  px_runs=0

`classify_windows` (crates/app/src/render/v6_layout.rs) takes the first as `story` and files the second under CHROME. A second primary buffer is not chrome.

MECHANISM. Both come from `GameSession::v6_screen_model` (crates/app/src/session.rs). Entry [0] is the real window 0. Entry [1] is the SYNTHETIC full-screen buffer the `degenerate` branch adds — the SQ-0459 fallback for Inform 6's v6 library, which leaves every window at height 0 so the size-0 skip drops them all and raster mode would otherwise draw a blank screen. Its guard is `degenerate = max_x == 0 || max_y == 0`, where max_x/max_y are the maxima of each entry's CELL rect (`pw.x + pw.w`), and a window's cell size is `win.grid.cols/rows` — the char grid, which sunburst never sizes because it never resizes window 0 off its boot rect. So window 0 is published with `w: 0, h: 0` and the guard fires even though a real primary Buffer is standing right there. The branch's own doc says "when NOTHING survived", which is not what it tests.

`content_size` reads the same flag and DOES want it: it falls back to the header's 0x21/0x20 char dims (80x25 here) precisely because the cell extent is 0, and that fallback is correct and load-bearing. So the two consumers need splitting — the synthetic buffer wants "no window survived at all" (`text_entries.is_empty() && graphics_entries.is_empty()`), `content_size` wants the existing zero-extent test.

WHY IT IS BENIGN TODAY, and why that is luck rather than design: the story window carries the whole 640x400 in PIXELS, and both the hybrid and raster v6 paths measure the story box in pixels, so the 0x0 cell rect is never consulted. The synthetic chrome twin draws nothing (no lines, no px_runs) and `fill_window_pages` skips any chrome window overlapping the story box, so it paints nothing either. Both v6 paths render sunburst correctly as things stand.

sunburst.z6 is worth keeping for this: 65 KB, no resource blorb, 0 pictures declared — the only fixture in the corpus that exercises the v6 TEXT path with no graphics at all.
