CORRECTION from the user, before any work was done on this — the original framing was wrong.

The art panel must NOT take the Amiga machine page. It is filled from the ARTWORK'S OWN
BACKGROUND COLOUR, derived from the picture being shown. That behaviour already exists and
the user confirmed it working earlier in the same session: "the background behind the artwork
properly changes color (based on the art)".

So RGB(66,66,66) — the Amiga page SQ-0822 established — is NOT the target here, and
`v6_machine_page` / `v6_host_pair` are not this panel's source.

What IS measured evidence: the panel renders RGB(58,58,58), the host theme's chrome, in the
user's screenshots of `Journey - The Quest Begins.adf` (release 30 / serial 890322) at a pane
size small enough that the art is scaled down. The correct value is whatever the
artwork-derived fill computes for that picture.

Three candidates to separate: the artwork-derived fill is not computed for this frame; it is
computed and does not reach the panel's ground; or something paints the theme colour over it.

Worth checking whether this shares a trigger with SQ-0824 — both symptoms appear in the same
screenshots, at the same small sizes.
