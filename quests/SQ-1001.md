## The proportion is not a preference — it is arithmetic, and it is currently wrong

User: "the zork zero drop cap is HUGE". It is not. Everything else is half-size.

`zork0-dos.png` footer: **162x53 cells at 8x16px**, **640x400 native at 2.000x**.

For art and text to agree, the device cell must be `magnification x native cell`. lanthorn assumes a fixed native v6 cell of 8x16 (which is SQ-0917's subject), and the composite is magnified 2x — so the text cell should be **16x32**. It renders at **8x16**, so text is exactly half-scale relative to the art on both axes.

That is why Zork Zero's decorative drop cap spans about eight text lines instead of the three or four it was drawn for: the cap is a PICTURE, scaled with the composite; the prose beside it is GLYPHS, scaled with the cell. The two are only in proportion when the cell tracks the magnification, and nothing makes it.

So the user's request for a larger font is not cosmetic — it is the fix. **16x32 at 2x magnification** puts the type back at the size the game was drawn for, AND is exactly 1:2 (square half-block samples) AND a FiraCode sweet spot at px/em 26 (the rounded cell lands on 2.000). All three properties at once.

## Candidate shapes for Journey's 640x400, all at whole magnification

    today          162x53 @  8x16  = 1296x848   2x   text half-size
    proposed        96x28 @ 16x32  = 1536x896   2x   correct proportion
                    80x24 @ 16x32  = 1280x768   2x   tighter crop
                    64x20 @ 20x40  = 1280x800   2x   largest type

`16x32` (px/em 26) and `20x40` (px/em 32) are both exact FiraCode sweet spots.

What cannot be had is all of: larger font, smaller window, AND 3x. `journey-wide` at 3x needs 1920x1200 device pixels, which at 16x32 is 120x38 cells — a bigger grid, not smaller.

## Do this per shot, from the magnification

Rather than picking cell sizes by eye, DERIVE the cell: `cell = magnification x native_cell`, then choose the grid to fit the frame. That makes the proportion correct by construction, and a shot whose cell does not satisfy it is a bug the manifest can assert against.

Relates to SQ-0917 (adopt each release's own font metrics instead of the fixed 8x16), which is the same disagreement seen from the other end — if the native cell is not really 8x16 for a given press, the multiplier changes with it.
