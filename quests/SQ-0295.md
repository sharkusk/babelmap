Implementation sketch (from SQ-0292 investigation):
1. VM can't yet distinguish create_by_name vs create_by_prompt — FileRef { id, rock, name, usage } has no creation-method flag; fileref_create_by_prompt returns a name immediately (no suspend). Add `by_prompt: bool` to FileRef.
2. StepResult::SaveRequest / PendingSaveLoad carry NO fileref identity to the host today; both gvm-cli (main.rs StepResult::SaveRequest) and the app (open_ingame_saves/dialog) unconditionally prompt.
3. Plan: thread {name, by_prompt} onto PendingSaveLoad at @save/@restore time → extend SaveRequest/RestoreRequest so the host learns it → branch in BOTH hosts: named fileref = silent read/write into the persistent store (no prompt, report success); by_prompt = show UI. Symmetric @restore.
Hook already landed in 1a03f49: Model::savegame_streams maps the Null save-stream id → its fileref name, so at @save time (exec.rs shim has l[0]=stream) the name is recoverable; remaining work is the by_prompt flag + SaveRequest API + host plumbing.
Converges with the cross-session existence limitation (host↔VM SavedGame file bridging) also noted in the SQ-0292 report.
