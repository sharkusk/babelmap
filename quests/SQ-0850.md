--- note 2026-08-14T03:31:31Z ---

zvm-cli must gain the same save-directory behaviour as the app, not a second implementation of it — one shared key helper, used by both. The user asked for this explicitly when scheduling the disk-format queue. Decisions already taken: a disk-mounted story keys on its own release+serial (survives renaming the image and a game moving between disks in a set); a loose story file keeps its <basename>.save/ so no existing save is orphaned. Glulx and Scott have no release/serial and fall back to the basename — a disk-mounted story must never reach that fallback, and that should be asserted rather than assumed.
