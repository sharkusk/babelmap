--- note 2026-08-15T08:05:44Z ---

MEASURED, on the same build both sides — `James Clavell's Shogun.adf`, release 295 / serial 890321, at the credits-and-menu screen.

  original (Amiga)   "Amiga Interpreter version 6.8"
  babelmap           "Amiga Interpreter version 6.65"

(My first reading of the low-resolution screenshot said 6.0; the user corrected it to 6.8. The mechanism is the same either way and 8 is the plausible value — an interpreter release number.)

WHO PRINTS IT: the STORY does, not us. Shogun reads header byte `$1E` (interpreter number, 4 → the word "Amiga") and `$1F` (interpreter version) and formats them, and this build formats `$1F` as a DECIMAL rather than as a character. `zvm::screen::init_header_caps` writes

    // Interpreter version (0x1F): b'A' = 0x41.
    mem.write_byte(0x1F, b'A');

unconditionally, for every machine and every story version. 0x41 is 65, so the banner reads 6.65. The original Amiga interpreter evidently wrote 8.

SAFE TO CHANGE: nothing in the VM reads `$1F`. Grepped — the only reader is a test asserting the byte is `b'A'`. The byte exists solely for a story to print, so this changes what the player sees and nothing else.

THE OPEN QUESTION, and it needs a second data point before anything is written. `$1F` is plainly a per-machine constant, but it may also be per-INTERPRETER-RELEASE, and two Amiga games disagree about how they render it:

  Shogun r295 (v6, 1989)        "Amiga Interpreter version 6.8"     — formats $1F as a decimal
  Nord and Bert r19 (v3, 1987)  "Infocom Interpreter 4 Version C"   — renders a LETTER, 'C'

If both read the same byte, the Amiga wrote 'C' (67) for Nord and Bert's era and 8 for Shogun's — two different interpreter releases on one machine, which is entirely plausible and means a single per-machine constant cannot be right for both. If instead Nord and Bert prints its own build letter from elsewhere and only Shogun reads `$1F`, one constant per machine is fine. RESOLVE THIS BEFORE PICKING A VALUE: find a second Amiga v6 title's banner, and check what an Apple/Macintosh/DOS press prints in the same slot — the corpus has bootable media for all of them and every one of those banners is a free measurement.

Note this sits in the same family as SQ-0872's machine table and SQ-0873's period look: another small per-machine constant that is visible to the player and currently hard-coded to one value for every machine. If it does turn out to be per-machine, it belongs as a column in `zvm::interpreter::MachineProfile` beside `number`, and `zvm-cli --machines` should print it.
