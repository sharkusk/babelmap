SCOPE DECIDED (user, 2026-07-29). Queue position 1 of 3: SQ-0522 -> SQ-0525 -> SQ-0391.
Collapse goes first because it deletes whole connectors, which changes how many crossings
are left for SQ-0525 to restyle.

DECISION: "Everything per pair." Every passage between the same two rooms draws as ONE
line, whatever its direction — compass AND Up/Down/In/Out. The retained pairing prefers a
true opposite (a straight line); every other passage becomes a direction icon stacked at
its own end. This replaces today's merge-stub T-junctions as well.

WHERE IT IS TODAY. `route::select_shared_paths` (SQ-0225) already collapses same-pair
compass edges into a retained connector plus `secondary_exit`/`secondary_entry` records,
which `render/map.rs:1513` stamps as arrow glyphs in the border slot beside the retained
arrowhead. It is gated on `fwd.len() >= 2 && bwd.len() >= 2` — "collapse ONLY true
bidirectional redundancy". Dropping that guard is the core of this quest.

THE CASE IT MISSES, and the one to test with. Adventure's maze pairs are 1-out/1-back and
NON-RECIPROCAL: `65169 -S-> 53329` with `53329 -W-> 65169`. fwd=1, bwd=1, so no collapse;
and the router's dedupe only skips an edge whose exact reciprocal-opposite was emitted, so
BOTH are drawn — two separate connectors between the same two rooms, crossing each other.
That is the rat's nest the user is looking at. `~/.babelmap/saves/advent.blb.save/default.babelmap`
is the fixture; its maze is 12 rooms with many such pairs.

IMPLEMENTATION NOTES / TRAPS.
- Up/Down currently gets its OWN trunk on purpose: `ch_key = (pair.0, pair.1, is_up_down)`
  (SQ-0224) keeps a pair's vertical and horizontal passages independent so neither
  collapses into the other as a merge stub. "Everything per pair" means retiring that
  channel split. Check what SQ-0224's tests lock in before removing it.
- In/Out/Unknown carry NO layout offset and are not routed at all — they are portal badges
  anchored at the room. Folding them into a pair's line only works when the pair already
  HAS a line. Suggested rule: an In/Out/Unknown edge whose pair carries a drawn connector
  joins it as a stacked icon; one whose pair has no connector keeps its badge as today.
- `select_shared_paths`'s `pick` already prefers `edge_is_satisfied` then the opposite
  direction; the user's "stack arrows next to the reciprocal direction if possible,
  otherwise minimize path crossings" is that preference plus a crossing-count tiebreak when
  no opposite exists. `render_stats`/`count_overlaps` in render/map.rs gives the crossing
  count to score against.
- Existing tests lock in the merge-stub rendering for one-sided redundancy (the #33/#175
  shape named in the code comment). They will need revising, not deleting — capture what
  they were protecting.
