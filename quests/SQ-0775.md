WHY IT IS WORTH MORE THAN A DEBUG TOY (user, 2026-08-11): "especially helpful when you need me to verify something and I'm remote." Several open quests end in "the user must look at it" — SQ-0772's changed draw-order winner on Journey's right flank, SQ-0725's missing title card, SQ-0742's misplaced ring. A rendered frame turns those from "please reproduce this" into "here is the picture, is this right?", and a BEFORE/AFTER pair turns a render change into something reviewable without a terminal at all.

EVERY PIECE ALREADY EXISTS IN THE TREE — this is assembly, not new capability:
  - `qwertty_term_vt::kitty::render::image_rgba(&Image) -> Cow<[u8]>` decodes any stored image's pixels. babelmap transmits `f=32` raw RGBA, so no PNG decoder is needed on the read side.
  - Each resolved placement carries source rect, destination size and grid position (see `crates/app/tests/pty_stream/oracle.rs`), so art composites at its true screen location. The oracle already reports per-cell `source_y`, added for SQ-0772 — that is what distinguishes a healthy placement from one redrawing its first row, and it must survive into the raster.
  - Text cells come from `snapshot_window(0)` with resolved fg/bg; `font8x8` is ALREADY an app dependency for glyphs.
  - `image` is already a dependency with the `png` feature, so writing the file is trivial.

SHAPE: extend `oracle.rs` with a rasteriser (cell grid → RGBA canvas at cell_w x cell_h, art composited by z-order — the port draws virtual placements BELOW text), and give `examples/pty_capture` a `--png PATH` flag beside the existing `--out`/`--raw`. A `--png-diff BEFORE AFTER` mode is the natural follow-on.

HONEST LIMITS to state in the docs: one bitmap font, no real font metrics, no ligatures/italics — so it is an oracle for LAYOUT, ART PLACEMENT and COLOUR, not for text rendering fidelity. It shows what Ghostty's ALGORITHM resolves, rendered with our own glyphs; it is not a screenshot.
