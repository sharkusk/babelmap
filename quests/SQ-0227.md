SCOPE EXPANDED (2026-07-08): folded in the root-cause fix. The naming confusion (Save State vs the game's save) and a CONFIRMED SQ-0163 regression share one root cause — babelmap doesn't cleanly separate the two save mechanisms.

CONFIRMED REGRESSION: SQ-0163 changed the in-game @save Quetzal PC to point at the instruction descriptor (standard §5.8) and taught complete_restore_success to complete it, but did NOT change restore_file (host Ctrl+R / saves-manager load). Verified: after an in-game @save, restore_file() sets pc=descriptor(0x41) instead of the resume point(0x42) -> misexecutes. So loading a game-created @save save via the host path is broken. FINE: auto-save/auto-resume + Ctrl+S Save State (resume convention) + in-game @save->@restore round trip.

FIX DESIGN (recommended): keep the two mechanisms distinct end-to-end.
 - "Save State/Restore State" = emulator host snapshot: resume-convention PC; restore just resumes (restore_file). Rename user-facing save-game/Saves accordingly.
 - "@save/@restore" = game path: standard descriptor-convention PC (SQ-0163); in-game @restore completes the descriptor (complete_restore_success).
 - HOST restore of a babelmap archive: store a babelmap-specific RESUME-PC field in the archive so host restore always resumes correctly (fixes the regression); IFhd keeps the standard descriptor PC for interop/export.
 - Bare FOREIGN .qzl import (no resume field): treat as standard @save -> complete the descriptor. (This is what SQ-0158's interop READ test needs.)
 Alt: a 1-byte convention marker in archive meta. Needs a red->green regression test (host-restore-of-in-game-@save-save resumes at post-instruction, not descriptor).

DEPENDENCY: SQ-0158 (Z-machine interop tests) is PAUSED pending this — its foreign-.qzl READ test rides on the descriptor-completion import path. SQ-0158 branch sq-0158-save-interop already has the dfrotz golden fixtures + generator committed (groundwork). Do a brainstorm->spec pass for this before implementing (save-format change).
