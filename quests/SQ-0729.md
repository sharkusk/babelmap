DEFECT 2 — the concatenated menu. VERDICT: MODEL-SIDE, in zvm, and NOT fixable in the render lane. The previous agent's finding is confirmed and traced one level deeper. At that frame the window is a non-primary `WinNode::Buffer` whose `lines[0]` is already "PLAY CURRENT BETCHANGE CURRENT BETSAVERESTOREQUIT". A v6 window in flowing-prose mode streams through `ZWindow::push_prose`, which appends to `prose` lines and keeps no cursor x. The columns are lost inside the VM before any render code sees them. Fixing it means teaching zvm to shadow a secondary prose window's runs the way it already shadows the primary's (`streamed`/`retire_streamed`), which is a VM-core change and belongs to a zvm lane. New `draw_secondary_prose` stacks such a window's lines from its own origin, one 16px row each; `chrome_text_rects` spares them so the story page fill cannot erase them; `v6_raster_gen` hashes the lines so the cached composite cannot outlive them. It sits beside `build_chrome_canvas` rather than inside it because the ink is honor_game_colours-gated and that function is not — painting fmvpoker's declared black regardless put black glyphs on the host's black page, caught by the theme-only half of the pair. Without this, routing hybrid to the composite would have LOST the menu row hybrid used to show (garbled), so the two halves had to land together.
