## Why scott-cli first

244 lines, exactly one TTY gate, no alternate screen, no cursor control, no status
window to linearise — everything a Scott game says is already prose ("I'm in a forest /
Obvious exits: North. South. East. West."). It is nearly a screen-reader client as
shipped.

The only real change is input: it enables raw mode purely to control echo
(crates/scott-cli/src/main.rs, `enable_raw_mode` with a manual echo loop). Plain mode
should take the cooked branch it already has for non-TTY stdin, which restores the
terminal's own echo and line editing.

It also has NO terminal teardown at all (no OSC/cursor reset — it sets neither, so
nothing leaks today, but that changes the moment it does). Folding it onto the shared
teardown guard from [[SQ-0605]] closes that.

## Value

A day's work for something a real user can actually try, and what it teaches about the
prompt, echo and pacing should shape [[SQ-0606]] for the other two before their much
larger surfaces are touched.

## Shipped 2026-08-03 — commit ed7223b8

### Most of this quest had already landed elsewhere
- Cooked input in plain mode → SQ-0606 (`HostMode::raw_input`).
- The missing terminal teardown → SQ-0605 (`TerminalGuard::raw_only`, chosen
  precisely so scott-cli's escape-free transcripts stay escape-free).

The "pilot first, then apply the lessons to the other two" sequencing was
overtaken — all three CLIs got plain mode together in SQ-0606.

### What the pilot idea actually turned up
One real, scott-specific screen-reader defect that the other two do not have:
`separator()` draws `<` + ~34 em-dashes + `>` between the room block and the
command area. A reader either announces every em-dash or drops the line by
punctuation filtering; neither conveys the window boundary it stands for. It is
now `separator(block, plain) -> Option<String>`, `None` in plain mode. The blank
line before the room block already separates the two for a listener.

Untouched outside plain mode — the default and piped transcripts still carry the
authentic rule, verified byte-identical on adv01, 1_baton and 8_akyrz.

scott-cli had no test module at all; it has one now (2 tests). Falsified by
un-gating the plain check.

### Worth remembering
The generalisable lesson is the one the quest predicted, just smaller than
expected: **decoration that reads fine listens terribly.** Everything else Scott
prints is already prose. Worth grepping the other two for box-drawing or rule
characters if more reader feedback arrives — nothing obvious found this pass
(zvm-cli pads with spaces and trims; gvm-cli's window borders are TTY-only).
