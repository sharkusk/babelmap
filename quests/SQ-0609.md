## The problem

Stripping escapes is the easy half of screen-reader support. The hard half is games
whose UI is a grid redrawn in place. Known cases in the fixture set:

- Counterfeit Monkey's hint menu — CM's status line IS its menu, resized from 1 row to
  4 while open (confirmed from the layout log during SQ-0603), cleared and reprinted on
  every arrow key.
- Shogun's startup menu ("You may choose to:" + a key list).
- Arthur's menus (arthrizm.z5 opens on one: "N = next item / P = previous item /
  ENTER = select item / Q = quit program").

In a linear stream these either have to be re-emitted in full on every keypress, which
is very noisy for a reader, or converted into a numbered list with its own input
convention — which changes the interaction model and has to be done per engine, since
the Z-machine, Glk and Scott all express menus differently.

## Recommendation

Deliberately scoped AFTER [[SQ-0606]]. Plain mode is worth shipping without menu
support: ordinary play is the common case, and a menu that is merely noisy is still
better than a screen the reader cannot follow at all. Solve this once there is a real
user to test the interaction with — the right convention is not guessable from here.

## Partially delivered 2026-08-03 — commit ed7223b8

**Status set to `partial`, not `confirm`: half of this is deliberately not done.**

### The quest's premise is out of date — menus DO linearise already
Measured, not assumed:

- **Arthur (arthrizm.z5), zvm-cli --plain** — the menu comes through as text,
  header, key legend and all, and the whole block re-emits each time the
  selection marker moves. 77 lines for 3 keypresses.
- **Counterfeit Monkey hint menu, gvm-cli --plain** — same: all 7 items, the `>`
  marker, and the "N = Next / Q = Quit Menu" legend, as text.

This came free from SQ-0607 (Glulx grid streaming) and zvm-cli's pre-existing
inline block. So option (a) from the original note — "re-emitted in full on every
keypress" — is what ships today.

Added two tests (one per engine) pinning it, so it cannot silently regress while
the rest stays open. Both falsified.

### What is NOT done, and why
Option (b): converting a menu into a numbered list with its own input convention.
That is the fix for the noise — 77 lines per keypress is exactly the "very noisy
for a reader" this quest predicted — but it changes the interaction model, has to
be done per engine, and the original note is explicit: "Solve this once there is a
real user to test the interaction with — the right convention is not guessable
from here." I did not guess.

I also considered and rejected a middle option: emitting only the *changed lines*
of a re-drawn block. It would cut Arthur from ~20 lines to 2 per keypress, but
announcing "  Documentation / > Sample Transcript" with no surrounding context is
its own guess at what a listener wants, and it would make plain-mode output
diverge from piped output, which the test harnesses read. Same objection, quieter
form.

### To close this
Either a real reader user tries `--plain` on arthrizm.z5 and says whether the
full re-read is tolerable (if so, close it), or they help design the numbered-list
convention (if not, that is the remaining work).
