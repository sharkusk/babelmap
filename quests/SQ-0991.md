  Found while doing SQ-0976: lanthorn's own kitty_transmit_virtual now sends o=z, but that path only serves graphics WINDOWS (Glulx toolbars, Scott room art). All v6 art — hybrid chrome bands and the raster full-pane composite — is uploaded by ratatui-image's own encoder, which sends raw uncompressed RGBA with no o=z. Measured under a pty: Journey r30 hybrid at 117x64 emitted 3.5 MB of graphics in one capture, and a Zork Zero r393 raster session emitted 22.9 MB across 8 frames — 2.82 MB per 920x575 frame, which deflates to 31.5 KB at level 6 (89x) in ~9 ms. ratatui-image is a fork we control (github.com/sharkusk/ratatui-image, branch lanthorn-11.0.6-u16-fix), so this needs an o=z option on its kitty encoder. NOTE: the pty placement oracle cannot read compressed uploads either — Capture::terminal_bytes() (SQ-0976) already undoes o=z, so it will cover this too.
