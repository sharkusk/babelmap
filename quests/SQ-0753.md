MEASURED by SQ-0747's band-lifecycle work, reported as found-not-fixed.

`retain_chrome_bands` / `invalidate_chrome_bands` record a `Drop` and forget the protocol, but emit no kitty `a=d`. Windows do this correctly — `retain_live` deletes properly since SQ-0637 — so bands are the outlier.

WHY IT COULD NOT BE FIXED IN THAT LANE: the image id lives inside ratatui-image's `Kitty` struct with no accessor, so we cannot name what to delete. Fixing it means placing bands the way `render_kitty_virtual` places windows, which is a larger change than the lifecycle fix warranted.

WHY IT STILL MATTERS after that fix: SQ-0747 cut Journey's upload rate about 5x (87 → 17 over a 20-frame resize sequence), which is the cheap half of the problem. But kitty evicts by LRU, and it evicts images that ARE currently placed — so an unbounded set of undeleted uploads can cause a live image to vanish. The lower rate makes that rarer, not impossible.

Related: SQ-0637 (the window-side delete that already works and is the model to follow), SQ-0747 (the lifecycle fix that reduced the rate).
