--- note 2026-07-29T04:19:37Z ---

SCOPE DECIDED (user, 2026-07-29). Queue position 2 of 3: SQ-0522 -> SQ-0525 -> SQ-0391.
Runs after the collapse work, which deletes connectors and so changes which crossings are
left to restyle.

DECISION: "Break the crossed line." The connector running straight through the cell keeps
its glyph; the other stops a cell short, leaving a visible gap. Precedence: a straight run
beats a turning one; if both are straight, VERTICAL passes and horizontal breaks. No new
glyphs, no reliance on colour, and it reads instantly as "these do not meet".

    now                    after
      |                      |
      |                      |
    --+--                  --  --
      |                      |
      |                      |

KEY FINDING that simplifies this: every `+` on the map is ALREADY an unconnected crossing.
Connectors are point-to-point and never branch, so a 4-bit cell can only arise from two
DIFFERENT connectors passing through the same cell. There is no genuine junction case to
preserve — the change is unconditional wherever the mask reaches all four bits.

WHERE IT IS. `render/map.rs`: DIR_N/E/S/W bits (~line 806), `glyph_for(mask, path)` (~831)
maps the 4-bit mask to `path.nsew`, and the per-cell accumulation that ORs masks is at
~1293 ("ORing masks means a perpendicular crossing of ..."). The break has to happen where
the second connector's bits are about to be OR'd in — it needs to know WHICH connector owns
the cell already, which the current mask does not record. Expect to carry an owner id (or
the straight/turning axis) alongside the mask.

TRAPS.
- `count_overlaps` (~2329) treats a cell written by >=2 distinct connectors as a CLEAN
  crossing only if the mask is exactly all four bits; anything else is an illegal overlap.
  Breaking the line makes the crossing cell single-owner, so this function must be taught
  the new shape or every crossing will score as an overlap. The tidy scorer (~2461) ranks
  candidate layouts by "zero illegal overlaps, then fewer crossings", so getting this wrong
  silently degrades layout quality rather than failing a test.
- Diagonals: `chain_glyph_bits` (~818) gives half-diagonal endpoints the same edge-midpoint
  bits as `-` and `|` precisely so a chain and an orthogonal run MERGE into one mask instead
  of overwriting (SQ-0356). A diagonal crossing an orthogonal is the same "unrelated
  crossing" case and needs the same break — decide which one is "straight" there.
- Every glyph involved is themeable (`crate::symbols::PathGlyphs`), so the break must be
  expressed in terms of the theme's glyphs, never literals.

CORRECTION to the previous note's first trap: the tidy-scorer risk was OVERSTATED. There is
no degradation risk provided the change stays in the rendering stage.

WHY. `overlap_stats` (render/map.rs:2336) does NOT read the rendered buffer. It calls
`plot_connector` itself and builds its own `cell -> {connector -> mask}` map from the
router's `RoutePlan`. `render_overlap_stats` -> `mapper::render::render(graph)` ->
`overlap_stats(plan, cols, rows)`; the ratatui Buffer never enters it. Glyph emission lives
in `render_lane_connectors`, which keeps a SEPARATE `cells: HashMap<(i32,i32), u8>`.

The precedent is in the function's own comment (:2342): the metric deliberately uses the
orthogonal reading (`diag = None`) so it "must not move when a user toggles the
`diagonal_corners` DISPLAY setting — otherwise tidy would make different layout decisions
per theme."

DESIGN RULE for this quest: the line break is display-only, exactly like `diagonal_corners`.
It must not touch `plot_connector`, `RoutePlan`, or anything `overlap_stats` consumes. Same
routes in, identical `(illegal, crossings)` out, identical tidy decisions — only the glyph
at one cell changes. If a change to this quest requires editing `plot_connector` or the
plan, stop: it has left its remit.

SCOPE NARROWED — break only the clean 4-bit crossing.
A 4-bit mask can only arise from two STRAIGHT perpendicular runs (N|S plus E|W). A turning
connector contributes two perpendicular bits (e.g. N|E), which combines to a 3-bit T
(`nse`/`nsw`/...) — and `overlap_stats` already classifies those as ILLEGAL, not clean
crossings. So:
  * 4-bit clean crossing -> break. This is the case the metric certifies as legitimate and
    the tidy pass is content to leave in place.
  * 3-bit T-stomp -> LEAVE ALONE. It is a real layout defect that `cleanup_overlaps` exists
    to remove; breaking a line there would hide a visible bug, and the turning connector
    would lose its own corner.
Consequence: since both contributors are always straight in the 4-bit case, the "straight
run beats a turning one" clause never fires. The tiebreak is unconditionally VERTICAL
PASSES, HORIZONTAL BREAKS.

MECHANICS. `render_lane_connectors`' `cells` becomes `HashMap<(i32,i32), (u8, usize)>` —
mask plus owning connector index. Same owner rewriting its own cell stays idempotent (a
connector may legitimately revisit a cell). A DIFFERENT owner whose mask would complete all
four bits does not OR: the N|S contributor wins the cell, the E|W one skips it entirely
(paints nothing, records nothing), leaving a one-cell gap with its neighbours intact. Handle
both arrival orders — if the horizontal painted first, the vertical overwrites the cell and
takes ownership.

TWO CASES TO DECIDE FROM A REAL MAP, NOT IN THE ABSTRACT.
1. Up/down vs compass crossings produce no `+` today at all: they accumulate in separate
   maps (`cells` vs `updown_cells`), so both paint the buffer cell and the LAST writer wins,
   non-deterministically by connector order. Already effectively broken, just arbitrarily —
   decide whether to make it deliberate.
2. Half-diagonal chains deliberately merge their endpoint bits into a compass cell's mask
   (SQ-0356) "rather than either line losing it". Same unrelated-crossing situation, but
   changing it reverses a decision made on purpose. Look at it on screen first.
