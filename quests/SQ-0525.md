SCOPE DECIDED (user, 2026-07-29). Queue position 2 of 3: SQ-0522 -> SQ-0525 -> SQ-0391.
Runs after the collapse work, which deletes connectors and so changes which crossings are
left to restyle.

DECISION: "Break the crossed line." The connector running straight through the cell keeps
its glyph; the other stops a cell short, leaving a visible gap. Precedence: a straight run
beats a turning one; if both are straight, VERTICAL passes and horizontal breaks. No new
glyphs, no reliance on colour, and it reads instantly as "these do not meet".

    now                    after
      |                      |
      |                      |
    --+--                  --  --
      |                      |
      |                      |

KEY FINDING that simplifies this: every `+` on the map is ALREADY an unconnected crossing.
Connectors are point-to-point and never branch, so a 4-bit cell can only arise from two
DIFFERENT connectors passing through the same cell. There is no genuine junction case to
preserve — the change is unconditional wherever the mask reaches all four bits.

WHERE IT IS. `render/map.rs`: DIR_N/E/S/W bits (~line 806), `glyph_for(mask, path)` (~831)
maps the 4-bit mask to `path.nsew`, and the per-cell accumulation that ORs masks is at
~1293 ("ORing masks means a perpendicular crossing of ..."). The break has to happen where
the second connector's bits are about to be OR'd in — it needs to know WHICH connector owns
the cell already, which the current mask does not record. Expect to carry an owner id (or
the straight/turning axis) alongside the mask.

TRAPS.
- `count_overlaps` (~2329) treats a cell written by >=2 distinct connectors as a CLEAN
  crossing only if the mask is exactly all four bits; anything else is an illegal overlap.
  Breaking the line makes the crossing cell single-owner, so this function must be taught
  the new shape or every crossing will score as an overlap. The tidy scorer (~2461) ranks
  candidate layouts by "zero illegal overlaps, then fewer crossings", so getting this wrong
  silently degrades layout quality rather than failing a test.
- Diagonals: `chain_glyph_bits` (~818) gives half-diagonal endpoints the same edge-midpoint
  bits as `-` and `|` precisely so a chain and an orthogonal run MERGE into one mask instead
  of overwriting (SQ-0356). A diagonal crossing an orthogonal is the same "unrelated
  crossing" case and needs the same break — decide which one is "straight" there.
- Every glyph involved is themeable (`crate::symbols::PathGlyphs`), so the break must be
  expressed in terms of the theme's glyphs, never literals.
