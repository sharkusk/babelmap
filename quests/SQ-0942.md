## What this is for

A project web page needs frames, and a terminal app is hard to sell in still
images. `examples/pty_capture` already drives the REAL binary under a pty and
renders what a terminal would draw, from a command — twelve before/after pairs
across five presses were generated in one session on 2026-08-20 — so the raw
capability exists. What is missing is a tool whose OUTPUT is meant to be looked at
rather than measured.

## Why it must not simply be the oracle with a nicer font

`tests/pty_stream/raster.rs` is a geometry oracle. Its own docs are emphatic: "It
is not a screenshot, and no amount of squinting will make it one… Judge geometry
from this picture; never judge typography from it." It draws with
`app::render::bitfont` — Uni-VGA 8x16 since SQ-0932, which already made these
pictures markedly better — and deliberately looks synthetic so nobody reads
typography into it.

Giving THAT tool a real TTF would be actively harmful. It would stop looking
synthetic while still not being anyone's terminal — no hinting, wrong face, wrong
metrics, no ligatures — and a picture that is 90% convincing invites exactly the
judgement it cannot support. That is the failure mode that cost three rounds on
SQ-0934, where a cell harness reported "no art inside the viewport" and was
believed.

So: a SEPARATE tool, sharing the capture code, with a real font. Tests never pass
the font flag; the oracle's default is unchanged.

## What it should produce

A gallery that regenerates each release, so the page cannot drift from the build:

  - Several titles across the corpus, including the ones with unusual shapes —
    Journey's separate picture region, Arthur's tiled flank, scopa and fmvpoker
    rendering as one full-frame composite.
  - Several presses of the same game where they differ visibly (Blorb, Amiga,
    Macintosh mono, DOS), which is one of the project's more distinctive claims.
  - A few pane sizes, since layout changes character between them.
  - Optionally the SQ-0936 lock on and off, which is a natural before/after.

## What it must NOT be used for

The hero image. A real screenshot from a real Ghostty session beats anything
synthesised — genuine font, genuine hinting, genuine kitty placements — and costs
nothing but a keypress. This tool's value is REPRODUCIBILITY across many
combinations, not beauty in one.

Likewise the fidelity comparisons against `machine-screenshots/`: pairing a
generated render with a real hardware capture only works while a reader can tell
which is which kind of evidence. If the render starts looking like a photograph the
comparison gets weaker, not stronger.

## Notes for whoever builds it

- A font rasteriser is a dev-dependency of `app`, which is allowed (CLI crates and
  `app` may take deps; `zvm`/`gvm`/`scott` may not). `fontdue`, `ab_glyph`, `swash`
  and `cosmic-text` are the candidates.
- Pin `random_seed` for any game with randomness. A first fmvpoker comparison on
  2026-08-20 showed 37,097 differing pixels that were entirely a different card
  deal; with the seed pinned it was 0. An unpinned gallery will regenerate
  differently every release for no reason.
- `pty_capture` must negotiate KITTY or every frame silently measures the
  half-block backend. It prints a VERDICT line; check it rather than assuming.
- The gitignored media (`stories/`, `treasures/`, `masterpieces/`) is required, so
  this cannot run in CI as it stands. Decide whether the gallery is generated
  locally and committed, or generated in a job that has the media.
