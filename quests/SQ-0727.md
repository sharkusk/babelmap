--- note 2026-08-09T18:20:59Z ---

User's screen, transcribed verbatim from advent.z6's help screen (hybrid/Ghostty, 2026-08-09), after SQ-0712 landed:

                                    About Adventure
     N   n xt subj ct                                           P = previous
     RETURN = r ad subjec                                       Q   r sume game

Almost certainly should read:

                                    About Adventure
     N = next subject                                           P = previous
     RETURN = read subject                                      Q = resume game

WHAT IS DROPPED. Lowercase `e` and `=`, and not uniformly:
- "N = next subject" loses the `=` and both lowercase `e`s (indices 2, 5, 13) but keeps everything else.
- "RETURN = read subject" KEEPS its `=`, loses the `e` in "read", and appears truncated after "subjec".
- "Q = resume game" loses the `=` and the `e` in "resume".
- "About Adventure" on the line above is INTACT, including two lowercase `e`s — so whatever this is, it does not affect that row.
- Uppercase `E` in "RETURN" survives.

DO NOT assume it is glyph-specific. `e` and `=` being the victims may be coincidence of position rather than of character: v6 places text at PIXEL coordinates and the cell paths map that to a fixed grid, so accumulated rounding can drop whichever glyph happens to land in a cell another glyph already claimed. Measure the runs' x coordinates before theorising about characters. That "About Adventure" is centred on its own row while the damaged rows carry left/right pairs is consistent with a column-mapping problem and inconsistent with a font/encoding one.

SECOND, RELATED DEFECT — same rows, different path. The SQ-0712 agent reported, and explicitly did not fix: "advent's help screen renders its reverse-video header rows (About Adventure, N = next subject) fine as cells but they are missing from the RASTER composite. Present both before and after my change, unrelated to either quest." So in raster these rows do not appear at all. Both belong to this quest; a fix should account for the rows existing in one path and being mangled in the other.

STILL UNKNOWN, ask the user: which render mode produced the transcription above (presumed hybrid, unconfirmed), and whether the truncation after "subjec" is real or an artefact of copying out of the terminal.
