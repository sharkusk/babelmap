REPRODUCED AND LOCALISED TO THE BYTE 2026-08-11, first attempt. Fixture `stories/James Clavell's Shogun.adf` (release 295 / serial 890321), Amiga profile via the medium, hybrid, 100x40, 8x18px cells, kitty negotiated. Driven with:
```sh
cargo run -q -p app --example pty_capture -- \
  --story "stories/James Clavell's Shogun.adf" --size 100x40 --timeout 150 \
  --keys "wait:2500,cr,wait:2000,cr,wait:2500,text:look,cr,wait:2500,text:look,cr,wait:2500" \
  --raw /tmp/sh.bin --out /tmp/sh.txt --png /tmp/sh.png
```

THE EMITTED BYTES AROUND THE PROMPT (raw stream, `<ESC>` expanded):
```
<ESC>[25;10H<ESC>[39;49m     <ESC>[26;10H<ESC>[7m<ESC>[38;5;15;49m><ESC>[27mlook<ESC>[39;49m <ESC>[27;10H<ESC>[7m<ESC>[1m<ESC>[38;...
```
`ESC[7m` (reverse ON) is emitted immediately before the `>`, and `ESC[27m` (reverse OFF) immediately after it, before the typed text. So the prompt character ALONE is drawn reversed, on the recalled input lines. That is the user's report exactly: "after the first input, the > is improperly reversed in future inputs."

CORROBORATING COUNT over the whole capture: **26 `ESC[7m` against 22 `ESC[27m`** — reverse is turned on four more times than it is turned off. Whatever sets it is not always clearing it.

WHY THE PROMPT AND NOT THE TEXT: the run is bracketed tightly around the single `>` glyph, so this is not a leaked attribute spanning a region — something is deliberately emitting reverse for the prompt cell and clearing it for the following text. Look for whoever styles the prompt/echo of a RECALLED input line, not for a stray SGR.

RELEVANT CONTEXT: Shogun genuinely uses reverse video for its own text — its opening paragraph and the `Bridge` room heading are printed inverted, confirmed in the same capture (the background map shows those columns at terminal default while the rendered frame shows white boxes, i.e. real SGR 7). So a naive "stop emitting reverse" fix would break legitimate output. The defect is the prompt inheriting or being given the attribute, not reverse video itself.

NOT YET MEASURED, and it is the next step: the IbmPc control. The user states this happens with the Amiga interpreter on BOTH the ADF and the bare z6, which already rules the medium out and points at the profile — but no capture under IbmPc has been taken, so "Amiga-only" rests on the user's report rather than on a measurement. Capture the same z6 under the default profile, diff the bytes around the prompt, and the difference localises it immediately.

ARTEFACTS: `/tmp/sh.bin` (raw stream), `/tmp/sh.txt` (decoded report), `/tmp/sh.png` (rendered frame — the prompt is at row 37, col 9).
