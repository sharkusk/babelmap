--- note 2026-08-21T03:18:48Z ---

CONFIRMED by the user on a real terminal, which settles the one judgement the tests could not make.

The report said "amiga zork-zero is wrong color -- orange" without naming the right colour. The captures answered it: `machine-screenshots/amiga-zorkzero.png` draws a BLACK caret on Zork Zero's grey #A3A0A3 page, and `machine-screenshots/amiga-shogun.png` a WHITE one on Shogun's dark #3A3C3A page. Two v6 games on one machine, two different caret colours — so at v6 the caret has NO COLOUR OF ITS OWN, it reverses the live pair. The lane implemented that reading rather than substituting a different fixed constant, and the user has now confirmed it is right.

Worth keeping because it is the general rule and not a Zork Zero fact: a fixed `cursor_colour` is STRUCTURALLY wrong at v6, not merely the wrong value. `CursorShape::ReverseSpace` is how a machine's look declines to state a caret, and `period::caret_cell`/`caret_over_text` answer `None` for it so the structural caret — which reverses the live style — takes over. Any machine that gains a v6 capture later should be read the same way before a constant is added for it.

`machine-screenshots/mac-zorkzero.jpg` and `mac-shogun.jpg` are the control that keeps the rule honest: the Mac draws the same 1px bar at v6 that its v3 capture does, which is why the substitution is per machine rather than applied to every row at v6.
