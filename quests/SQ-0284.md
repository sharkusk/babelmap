--- note 2026-07-12T16:00:02Z ---

DESIGN (settled 2026-07-12, alpha). Per-story storage key = "IFID if present, else content hash", per engine: (1) Z-machine -> existing zvm::ifid::compute_ifid = ZCODE-<release>-<serial>-<checksum> (header-derived, always present; never hashes). (2) Glulx -> NEW: parse the Blorb IFmd metadata chunk for an embedded <ifid> (blorb crate doesn't do this yet -- add a small zero-dep scan); if absent (Blorb w/o IFmd, or bare .ulx), fall back to a hand-rolled zero-dep content hash (FNV-1a-style, since gvm/blorb stay zero-dep). This splits the app's current one-size compute_ifid (which misapplies the ZCODE formula to Glulx bytes) into a proper per-engine key, and gives gvm-cli a real key (stop naming by story-filename). MIGRATION: NONE -- accept that existing Glulx .gvfs/.babelmap/.qzl orphan under the new key (alpha; Glulx persistence only ~3wks old; Z-machine keys unchanged). Note in docs/changelog. CLI STORAGE CONFIG: add --data-dir <path> (override the sidecar/save directory; default = story directory) and a filename-suffix override, for BOTH gvm-cli and zvm-cli. Consistent CLI default = story directory + the new per-story key naming. Depends on nothing in SQ-0283 but shares CLI files; sequence after SQ-0283.

--- note 2026-07-12T16:21:42Z ---

DESIGN REVISED (2026-07-12) -- SIMPLIFIED, supersedes the IFID/hash approach above. Storage key = STORY FILENAME across the board (both CLIs AND the app). NO IFID extraction, NO Blorb IFmd parsing, NO content hash -- all dropped. Obvious/visible; user owns collisions (rename if two same-named stories share a --data-dir). IMPORTANT split: this is only the STORAGE key. IFID computation STAYS for known-title lookup + hint association (those match a shared works database; filename can't) -- do NOT remove zvm::ifid or the app's IFID use for titles/hints. LAYOUT (recommended, pending final user OK): directory-per-game -> <base>/<story-filename>/ containing `aux` (zvm), `vfs` (glulx), and `saves/<name>.qzl` (in-game @save) + `saves/<name>.babelmap` (Save State). base defaults to the story's own directory; --data-dir <path> overrides base. Per-game dir gives short fixed inner names AND makes SQ-0285 (browser save listing) = read one directory. Simpler alt = flat `<story>.<ext>` next to story (smaller diff, scatters files) -- not preferred. The earlier per-file suffix-override flag is now moot (fixed inner names) -> drop unless user wants it. App storage moves from <save_dir>/<ifid>.* to filename-keyed per-game dirs; app title/hint lookups stay IFID. No migration (alpha). Sequence after SQ-0283; SQ-0285 depends on the per-game dir layout.
