MEASURED by SQ-0746's agent, reported as found-not-fixed:

`Machine::v6_input_window` is not written into the host archive. A Restore State taken while a game is waiting on a read through a secondary panel comes back with `input_window` 0, so `BufferWindow::reads_input` is false and the typed input is not echoed until the next read re-establishes it. Everything else on that frame restores correctly, and after SQ-0746 the restored panel does at least show its prompt where it previously came back blank.

Pre-existing since SQ-0585 — the divert rule already depended on this field before SQ-0746 made the echo depend on it too; SQ-0746 only made the consequence visible.

This is squarely the "persist the recipe, not the result" rule from CLAUDE.md: `v6_input_window` is an input to what the screen must show, and Quetzal saves no screen state by design, so carrying it is ours to do. Note the repo's restore-test convention when this is picked up — restore tests must PERTURB before asserting: restore, then make a move (here, type at the restored prompt), then assert. Asserting the frame immediately after the restore is exactly when everything still looks correct. Cover restoring into a different terminal size and a different graphics backend.
