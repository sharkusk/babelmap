SYMPTOM (user, 2026-08-09): reproduces on ANY version of Beyond Zork. From the opening screen, type `BEGIN`; the story text plays; the game then returns to its centred title screen — but the first screen's text (including the line where `BEGIN` was typed) is still on the pane, showing beneath/behind the centred title. Per the walkthrough only the centred title text should be present at that point.

Fixtures on hand: `stories/beyondzork-r57-s871221.z5` (a plain v5, drivable headlessly — start here), `stories/bzorkizm.z5`, `stories/beyondzork.blb`, `stories/Beyond Zork - The Coconut of Quendor.adf`. The user says every version behaves the same, so the .z5 is a faithful oracle and no disk image is needed.

WHERE TO LOOK — hypothesis, not a finding, so measure it first. Beyond Zork is a v5 whose story window is the host transcript, not a v6 painted window. The likely mechanism is that the game's screen clear (`erase_window`) is not clearing what the pane actually shows: either the opcode does not reach the transcript at all, or it clears the model while retained scrollback replays the old lines back into the viewport. Trace what the game emits around the title repaint before deciding — `@erase_window -1` vs `@erase_window 0`, and whether a `@split_window`/`@set_cursor` sequence is involved, are different bugs with different fixes.

This is a v5 cell-path defect, NOT the v6 composite. Whatever the fix, it must not disturb v6 titles, and any transcript-clearing change needs checking against games that legitimately expect scrollback to survive.
