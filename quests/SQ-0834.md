DESIGN — the user's addition, 2026-08-13: "we likely need a quick menu for 834 when pointing at a disk with multiple stories. this can be a simple choice given to the user: pick 1...n during startup."

So: when a mounted image yields more than one story candidate, `zvm-cli` prints a numbered list and reads a choice on startup. One story → open it without asking. Zero → an error naming what was mounted.

**This is not hypothetical — it is the common case.** From the SQ-0833 survey: Lost Treasures Vol I carries 4 stories on floppy1 and 6 on floppy2; Vol II carries up to 4 per disk; the IIgs set holds 28 across six disks; the ST compilations hold 3-6 each. A single-story disk is the exception in this corpus, not the rule.

TWO THINGS THE MENU MUST GET RIGHT, both learned from the surveys:

1. **Label from the DIRECTORY, not the filename, when there is one.** On the Atari ST compilations every story is literally called `STORY.DAT`; the folder (`HITCHHIK/`, `BUREAUCR.ACY/`, `CUTHROAT/`, `LEATHER.GOD/`) is what names the game. A menu listing "1) STORY.DAT 2) STORY.DAT 3) STORY.DAT" is useless. Where neither name helps, the Z-machine header does: version, release and serial are always readable, and this corpus contains three different Hitchhiker's releases, so showing `v3 r56 s841221` is genuinely disambiguating rather than decoration.
2. **A non-interactive path is required, or this is untestable and unscriptable.** Add a flag (e.g. `--story <n>` or a name match) so a choice can be made without a TTY, and so the gate can drive it. `zvm-cli` already depends on `crossterm`, so a TTY check is available — when stdin is not a terminal, do NOT block on a prompt: list the candidates and exit with an error telling the user which flag to pass.

Scope note for the lane: wire what `blorb` offers TODAY (`adf::Adf::looks_like_adf` / `mount` / `pictures`, and `looks_like_story`). New container formats — DOS/ST FAT12 (SQ-0833), ProDOS (SQ-0836), Mac DiskCopy+HFS (SQ-0837) — plug into the same selection path as they land. Do not build them here, and do not pre-abstract for them beyond what one format needs.
