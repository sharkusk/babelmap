--- note 2026-08-16T15:30:24Z ---

`crates/app/examples/ring_scout.rs` (added by SQ-0894 as the headless instrument for the ring's tiling) boots a story WITHOUT the interpreter profile the app applies: it passes `interpreter_number: None` and never calls `set_palette`, unlike the `boot()` helper the integration suites use.

**Consequence: on Apple/Amiga media it measures a frame the renderer never draws.** MEASURED by the SQ-0898 lane on `stories/Arthur - The Quest for Excalibur.adf` — the scout reported a **172-native-px flank** where the app renders a **30px pole**. That nearly cost the lane its reproduction of the Frame-plan stretch defect, and it would have been read as "cannot reproduce" rather than as a broken instrument.

This matters more than an ordinary tool bug because the scout was BUILT to be the cheap, reliable layer — no pty, no terminal negotiation, no timing flake — and the whole point of CLAUDE.md's three-layer rule is that you trust the cheap layer until it cannot explain the symptom. An instrument that silently disagrees with the app on a whole class of media is worse than no instrument: SQ-0894's own corpus sweeps (the (b) no-op measurement over 56 frames, the flank-column table) all ran through it, so any of those numbers taken on DISK MEDIA should be treated as unverified until re-measured.

`.z6` fixtures are unaffected — they carry no medium to resolve a profile from — so the SQ-0894 measurements on `zork0-r393-s890714.z6`, `arthur-r74-s890714.z6`, `shogun-r322-s890706.z6` and `journey-r83-s890706.z6` stand. It is the `.adf` / `.po` / `.2mg` / `.dsk` readings that are suspect.

## Fix

Boot through the same path the suites do. `crates/app/tests/suites/v6_side_border_tiling.rs`'s `boot()` and `more_pager_first_new_row.rs`'s `boot_v6()` are the references; `InterpreterProfile::resolve` reads the medium (see `docs/features/interpreter.md` and `crates/app/tests/suites/real_media_releases.rs` for the release each medium carries). The scout already mounts disk images correctly via `hints::load_mounted_story` — it is only the profile and palette that are missing.

## Worth doing at the same time

Have the scout PRINT the resolved profile and release it booted, so a disagreement between it and a `/dump-windows` capture is visible on the face of the output rather than having to be deduced. A disk image is a different RELEASE, not the same story on other media (CLAUDE.md), and the instrument should say which one it is holding.
