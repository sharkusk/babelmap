--- note 2026-07-30T15:30:07Z ---

Reproduced and diagnosed (headless probe over Coloratura.gblorb + CounterfeitMonkey-11.gblorb, debug trace on).

FINDING 1 — the PC does not "halt"; it is pinned by construction.
`Debugger::pc()` for Glulx returns `machine.instr_start_pc()`. The inspector can only ever be read while the VM is parked for input, and the VM is always parked on the SAME instruction: the `@glk glk_select` inside Inform's Glk varargs veneer stub. Measured: Coloratura pc = 0x00049a at boot and after every command ("look", "wait", "x me"); CounterfeitMonkey pc = 0x00103c, likewise unmoving. Nothing advances because nothing can — that address is where suspension happens.

FINDING 2 — the surrounding disassembly is CORRECT, not garbage.
Coloratura 0x000492 is a C0/stack function of exactly three instructions:
    000492  ; function C0/stack, 2 locals
    000497  copy sp, L0            <- the reported "copy sp, 0" (L0 misread as 0)
    00049a  glk #0xc0, L0, L4      ; glk_select
    0004a2  return L4
That is the textbook I6 Glk varargs shim: pop the arg count into L0, hand it to @glk as its numargs operand, return the result. CM's variant is C1/locals (`copy L0, sp` / `glk #0xc0, #0x1, _`). It reads as wrong only because it is 3 instructions of dispatch glue with zero story context. Decode correctness is independently backed by the executor-oracle round-trip tests (`decode_round_trips_with_executor`, `real_image_decode_round_trip` over glulxercise.ulx).

FINDING 3 — the real defect, and why manual escape fails.
`DebugPanelState::refresh()` unconditionally does `self.disasm_addr = self.pc` on every per-turn refresh (PC-follow, debug_panel.rs:283). Call Stack `ret=……` tokens ARE already clickable (`clickable_spans`, Section::CallStack) and jump the Disassembly into real game code — the frames carry rich return PCs (0x00b34a, 0x055024, 0x012073, 0x06187f …) — but the next turn snaps the anchor straight back to the veneer stub. So the inspector is unusable for following Glulx execution: you cannot stay anywhere useful.

Net: this is an anchoring/UX defect, not a disassembler defect. Fix direction pending user decision (hop out of the veneer in `pc()` vs. make the panel anchor sticky vs. both).
