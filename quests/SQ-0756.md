TWO DEFECTS, both demonstrated by a real user attempt 2026-08-09.

**1. It describes the wrong frame — structurally, every time.** The command must be reached through the palette (or a hotkey dialog), so the frame being dumped is always the modal's. The user's capture reads:

    render path: cell — modal overlay open: palette
    win0 ... cells: NOT DRAWN this frame
    win1 ... cells: NOT DRAWN this frame
    win2 ... cells: NOT DRAWN this frame
    win3 ... cells: NOT DRAWN this frame

All four windows NOT DRAWN, because the modal owns the frame. The geometry is live state and still useful, but "what did the game's last frame actually look like" — the question the command exists to answer — is exactly what it cannot report. `recent render paths (oldest first): raster x2 · hybrid-ring x2 · cell — modal overlay open: hotkey_dialog · cell — modal overlay open: palette x6` shows six modal frames stacked on top of the frame of interest.

Fix direction: report the last NON-MODAL frame — its render path, its drawn cells, its viewport — not the frame the dump itself caused. The command already tracks a render-path history, so the data to identify that frame is present.

**2. Its output is uncopyable when kitty placeholders are on screen.** The dump is drawn INTO the terminal, so selecting it captures the surrounding unicode placeholder glyphs. The user's paste is dense with U+3EEE-range placeholder characters interleaved through every line, and whole fields are truncated mid-word (`mp-windows` for `dump-windows`). Ironically the corruption is caused by the same graphics protocol the dump exists to diagnose.

User's suggestion, verbatim: "we probably need it to dump to console so we can copy on exit or somethign". Take that as the requirement, not necessarily the mechanism — writing to a file under `~/.babelmap/` and printing the path would serve equally and survives the session ending. Whatever is chosen must be copyable while the TUI is still running, since asking the user to quit to read a diagnostic defeats its purpose during a live investigation.

WHY THIS IS HIGH PRIORITY: it is currently blocking SQ-0755. Three headless investigations have failed to reproduce Journey's misplaced prose, and the agreed next step was for the user to capture the real frame — which this command cannot do.
