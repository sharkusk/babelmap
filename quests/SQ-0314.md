Design decisions (user, 2026-07-15):

1. SCOPE = stub only. The first 1-2 cells out of the corner are diagonal, then hand off to the EXISTING orthogonal lane router. Router, crossing model, and box stride are all UNTOUCHED. (The full 45-degree stair between rooms stays deferred per the 2026-06-22 diagonals spec.)
2. The corner ARROWS (↗↖↘↙ on the box corner cell, via corner_anchor map.rs:258 / diagonal_arrow) REMAIN as-is. The new diagonal glyphs are used AFTER the arrow, on the OUTSIDE of the box border.
3. Motivation is not just cosmetic: this ENABLES THE 4 CORNER SLOTS as connector attachment points. Today box_edge_anchor (map.rs:1273) deliberately keeps anchors off corners (v_max = BOX_H/2 - 1), so a Left/Right side has only 3 usable cells (rows 1-3). Corner slots materially raise the per-room slot budget.
4. This quest SUPERSEDES SQ-0184 (U+2571/2572), now discarded.

Geometry findings (verified against unicodedata, not recall):
- U+1FBA0 upper-centre<->middle-left; U+1FBA1 upper-centre<->middle-right; U+1FBA2 middle-left<->lower-centre; U+1FBA3 middle-right<->lower-centre.
- EVERY endpoint is an edge MIDPOINT, never a cell corner. So these bridge a v-attachment (upper/lower centre, where │ attaches) to an h-attachment (middle left/right, where ─ attaches) — exactly why they join a diagonal into an h/v path cleanly, and why U+2571/2572 (corner-to-corner) cannot.
- Corollary: U+2571/2572 and U+1FBAx live on DIFFERENT sub-grids (corner vs midpoint) and cannot connect to each other.
- Chaining: "U+1FBA3 then U+1FBA0" (L->R) ascends 1 row per 2 cols = true visual 45deg on a 1:2 terminal cell. Mirror "U+1FBA1 then U+1FBA2" descends. A pair spans lower-centre -> upper-centre (both v-attach); cutting a chain mid-pair ends on an h-attach.

BLOCKER to fix: symbols.rs is_wide_estimate (:404-435) blanket-rejects 0x1F000..=0x1FFFF as "Emoji, Mahjong, etc.", which swallows all of U+1FBA0-U+1FBAF. These are NARROW box-drawing glyphs. Hardcoded preset defaults bypass the gate, but style.toml OVERRIDES would be silently rejected — violating the standing "every UI element must be themeable" rule. Carve the 1FBA0-1FBAF range out of that reject list.

FONT RISK: U+1FBAx is Unicode 13 "Symbols for Legacy Computing" — much thinner font coverage than the U+2500 box-drawing block. Keep the existing corner arrows as the default; ship the diagonals so a terminal without the font isn't broken.
