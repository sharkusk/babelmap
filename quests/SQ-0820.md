--- note 2026-08-12T22:00:43Z ---

FOUND 2026-08-12 by the SQ-0814 lane, reported rather than acted on so the screen-layers fix stayed surgical.

MEASUREMENT. fmvpoker.z6, two steps from boot, host Save State round trip and restore, then a move on each side. The window canvases match byte for byte, the painted ground matches, the erase fills and canvas anchors match (SQ-0814) — and the SCREEN MODEL still differs. The whole of the difference is `BufferWindow::px_runs` on the prose window: `[PxText { y: 247, x: 76, text: "Current Bet:" }, PxText { y: 265, x: 76, text: "10" }, …]` in the saved session, `[]` in the restored one.

CAUSE. `session::screen` builds `px_runs` from `ZWindow::streamed` (SQ-0729) — where a v6 prose window's streamed text is SITTING, in pixels. The archive's `ZWindowDto` (crates/app/src/archive.rs) carries `props`, the grid `cells`, `fg`/`bg`, `texts` (V6Text runs) and `prose` (SQ-0585 secondary-window lines). It does NOT carry `streamed`, and it does not carry `retired` either — the third layer of the same family (`ZWindow::retired`, the prose a window has handed over as real paint).

WHY IT MATTERS. Same argument as SQ-0585's `prose`, which is already persisted with the comment "a restore has to reproduce what was on screen … after a restore into its split layout the game repaints neither window, so an unpersisted panel would come back blank and stay blank". A Save State swaps memory under a game that never learns it happened; nothing repaints the streamed runs, so fmvpoker resumes with its bet and pot legends missing from the pixel raster. It is the CELL grid that keeps them (`cells` is archived), so the defect shows in the raster/hybrid composite and not in cell mode, which is presumably why it has gone unnoticed.

SHAPE OF THE FIX. Two more `Vec<V6TextDto>` fields on `ZWindowDto`, `#[serde(default)]`, mirrored in `from_window`/`to_window` beside `texts`. Recipe, not result — these are the game's own runs in native pixels, no cell geometry. A format-version bump, since an older build reading them would drop them.

TEST. The oracle is already written and is exactly the one SQ-0814 had to back away from: restore an archive into a fresh boot, play one move, and compare the rendered pane against a session that reached the same state under its own steam — see the "two restored sessions" note in `crates/app/tests/suites/v6_restore_screen_layers.rs`, which explains why that comparison was scoped down. fmvpoker.z6 is the fixture (deterministic across boots and across declared host sizes, unlike Journey and advent, both of which diverge between two independent boots).
