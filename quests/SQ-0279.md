DESIGN LOCKED (2026-07-11) — reframed from "filename picker" to "route Glk create_by_prompt through babelmap's save system as typed, named, on-disk, browsable entries."

Key scoping fact: Glulx @save/@restore are intercepted opcodes (0x0123/0x0124 -> host Save State snapshot via SaveRequest/RestoreRequest), so create_by_prompt NEVER handles save/restore here. Its only real consumers are Transcript (SCRIPT ON), InputRecord (command record/replay), and game Data files. Current bug: Model::fileref_create_by_prompt (glk.rs ~1025) returns a fixed name __prompt_<usage&0xf>__ so successive prompts of the same usage collide.

Chosen approach = "Same manager, typed entries": prompted files become real named on-disk entries in the saves manager, tagged by type (Save/Transcript/Recording/Data), created/picked with the EXISTING SaveAs prompt + saves-picker UI. write/append -> SaveAs prompt names it; read -> saves manager filtered to the usage type -> pick one.

Implementation shape (mirror existing patterns):
- gvm: add StepResult::NeedFilename{usage, fmode} (mirror SaveRequest/RestoreRequest, exec.rs ~21-48); a pending_fileref suspend field (mirror pending_saveload exec.rs:152); emit it from the 0x0062 create_by_prompt arm (exec.rs:2973) instead of auto-naming; re-report in step() (mirror saveload_result exec.rs:3335); a supply_filename(Option<String>) resume that alloc_filerefs the chosen name (or NULL on cancel). Keep create_by_name + the SQ-0278 VFS unchanged.
- app: reuse Prompt/PromptKind::SaveAs (state.rs:705/911) + the saves manager, opened like open_ingame_saves (main.rs ~4758) via the ingame_io/flag-hop resume plumbing. Saves-listing model gains a type/usage tag; the manager renders + filters by type. Prompted-file bytes stored as on-disk named files in the save store (persist_files.rs/archive.rs), superseding the in-memory VFS for the prompted case (write-stream flushes to the named file on close). compute_ifid keys per story as usual. Honor shared-chrome dialog conventions (Tab/Shift-Tab/Enter/Esc) + styleable (add ColorScheme entries, no literals).
- gvm-cli: handle NeedFilename in drive() via a prompt_and_read_line-style hook (zvm-cli main.rs:501 precedent); or auto-name in the headless case.
- Docs: extend docs/persistence.md (this is a 4th kind of per-story file) + to-verify smoke.

This is the biggest task in the current save/persistence arc: gvm suspend path + saves-manager typed-entry UI + on-disk typed storage + CLI. Deserves a fresh-context build (plan via subagent-driven-development).
