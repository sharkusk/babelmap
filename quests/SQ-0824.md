Magnification half — MEASURED, premise corrected, no code shipped (awaiting the user's policy call).

Fixture: `Journey - The Quest Begins.adf` (release 30 / serial 890322), hybrid, kitty, cell 8x18.

1. The reported "2.05x" is a misreading. At terminal 166x44 the v6 pane is 164x41 cells = 1312x738 device px; native is 640x400, so the uniform letterbox scale is s = min(1312/640, 738/400) = **1.845**. The band that carries the plate is `[Art, tiled]` (`draw_chrome_band_image`), source **247x283** unit px -> **456x522** device px = 1.8462 x 1.8445. The 2.05 came from dividing the transmit width by the PLATE bbox (222x254) instead of by the band's own source; 2.05 is just 1312/640, the width ratio the letterbox does not use.

2. Why the runs are 3 and 4. `build_graphics_canvas` is UNIT space, and Journey's art lands there at V6_ART_SCALE = 2: the plate's opaque bbox is 222x254@(21,25) and every same-colour run in it is even (GCD 2x2), i.e. the artwork is **111x127 art pixels replicated 2x**. So one ART pixel is 2 x 1.845 = **3.69 device px** -> runs of 3 and 4. Measured on the emitted stream (pty_capture, oracle PNG, placement rows 2..30 cols 11..67): horizontal runs 4:9299, 3:4291, 7:3317, 8:2161, 11:1954, 15:804 — exactly the reported clustering, and runs of 1-2 are absent, which is the 2x block proving itself.

3. The integer to snap is therefore the ART-pixel factor k (device px per art pixel), not s. Snapping s itself to an integer means 1.845 -> 1.0, a 46% linear loss.

4. Cost of k = floor(box / art), art = 111x127, across the pane sweep (Journey, honor=true):
   pane -> box device px -> current plate size -> k -> snapped size -> change
   60x24  -> 168x198 -> 168x198 (1.51) -> k=1 -> 111x127 -> -33%
   80x24  -> 224x270 -> 224x270 (2.02) -> k=2 -> 222x254 -> -1%
   100x30 -> 280x324 (2.52) -> k=2 -> -21%
   117x41 -> 328x378 (2.95) -> k=2 -> **-32%**
   120x30 -> 328x378, plate 300x343 (2.70) -> k=2 -> -26%
   130x50 -> 368x414 (3.31) -> k=3 -> -9%
   140x40 -> 392x450 (3.53) -> k=3 -> -15%
   150x60 -> 424x486 (3.82) -> k=3 -> -21%
   164x41 -> 456x522, plate 410x468 (3.69) -> k=4 -> 444x508 -> **+8%**
   180x50 -> 552x630, plate 500x571 (4.5) -> k=4 -> -11%
   200x60 -> 560x648 (5.05) -> k=5 -> -1%
   236x65 -> 720x828, plate 650x743 (5.85) -> k=6 -> 666x762 -> +2.5%
   Floor is free-or-better at four sizes and costs 21-33% at four others; the worst are the ratios just under an integer (2.95 -> 2). Round-to-nearest would take 117x41 to k=3 = 333x381 against a 328x378 box, i.e. a ~1.5% crop of the plate's edges for a 32% size gain.

5. Path classification (which callers carry content art):
   - `draw_chrome_band` — a crop of the ONE canvas scaled by s; tiles must join and must line up with the story viewport. Cannot be snapped per band; snapping it means moving s, which also shrinks the transcript viewport (at 164x41, s 1.845 -> 1.5 costs ~17 columns of text). Carries Zork Zero's / Arthur's banner plates.
   - `draw_chrome_band_stretched` — two different jobs on one function: (a) the Menu-plan flank PANEL (Journey's picture column, art centred in a panel flooded with the game's own panel colour) = CONTENT ART, snappable; (b) `flank_crop` under the Frame plan and the divider extensions = DELIBERATE non-uniform stretch (SQ-0755), must not be snapped.
   - `draw_chrome_band_image` — tiled flanks. For Arthur/Shogun/Zork Zero these are border columns whose source is composed at the uniform scale precisely so they keep the top plate's horizontal factor (SQ-0698); snapping them would misalign them with that plate. For JOURNEY the same arm carries the whole plate (no top plate exists to align with) — and it is this arm that draws the plate at the user's own 164x41.
   So the snap needs a caller-supplied classification, and the discriminator is not the function.

6. Padding: no new fill is needed. `menu_flank_panel` already returns the panel colour sampled from the art's own outer edge and `fill_pane_page(fill, bg, buf)` floods it; the pane flood above it uses `story_bg_rgba`. The existing letterbox already carries the right ground, so SQ-0827's `page_for` white-on-black trap is not on this path.

7. Separate defect found while measuring: `menu_flank_panel` ceils cols and rows INDEPENDENTLY, so the plate's aspect is distorted. At 80x24 the 222x254 plate is drawn into 224x270 — x1.0090 vs y1.0630, a 5.3% aspect error. Worth its own quest.
