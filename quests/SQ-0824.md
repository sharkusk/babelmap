--- note 2026-08-13T07:10:04Z ---

Magnification half — MEASURED, premise corrected, no code shipped (awaiting the user's policy call).

Fixture: `Journey - The Quest Begins.adf` (release 30 / serial 890322), hybrid, kitty, cell 8x18.

1. The reported "2.05x" is a misreading. At terminal 166x44 the v6 pane is 164x41 cells = 1312x738 device px; native is 640x400, so the uniform letterbox scale is s = min(1312/640, 738/400) = **1.845**. The band that carries the plate is `[Art, tiled]` (`draw_chrome_band_image`), source **247x283** unit px -> **456x522** device px = 1.8462 x 1.8445. The 2.05 came from dividing the transmit width by the PLATE bbox (222x254) instead of by the band's own source; 2.05 is just 1312/640, the width ratio the letterbox does not use.

2. Why the runs are 3 and 4. `build_graphics_canvas` is UNIT space, and Journey's art lands there at V6_ART_SCALE = 2: the plate's opaque bbox is 222x254@(21,25) and every same-colour run in it is even (GCD 2x2), i.e. the artwork is **111x127 art pixels replicated 2x**. So one ART pixel is 2 x 1.845 = **3.69 device px** -> runs of 3 and 4. Measured on the emitted stream (pty_capture, oracle PNG, placement rows 2..30 cols 11..67): horizontal runs 4:9299, 3:4291, 7:3317, 8:2161, 11:1954, 15:804 — exactly the reported clustering, and runs of 1-2 are absent, which is the 2x block proving itself.

3. The integer to snap is therefore the ART-pixel factor k (device px per art pixel), not s. Snapping s itself to an integer means 1.845 -> 1.0, a 46% linear loss.

4. Cost of k = floor(box / art), art = 111x127, across the pane sweep (Journey, honor=true):

5. Path classification (which callers carry content art):
   - `draw_chrome_band` — a crop of the ONE canvas scaled by s; tiles must join and must line up with the story viewport. Cannot be snapped per band; snapping it means moving s, which also shrinks the transcript viewport (at 164x41, s 1.845 -> 1.5 costs ~17 columns of text). Carries Zork Zero's / Arthur's banner plates.
   - `draw_chrome_band_stretched` — two different jobs on one function: (a) the Menu-plan flank PANEL (Journey's picture column, art centred in a panel flooded with the game's own panel colour) = CONTENT ART, snappable; (b) `flank_crop` under the Frame plan and the divider extensions = DELIBERATE non-uniform stretch (SQ-0755), must not be snapped.
   - `draw_chrome_band_image` — tiled flanks. For Arthur/Shogun/Zork Zero these are border columns whose source is composed at the uniform scale precisely so they keep the top plate's horizontal factor (SQ-0698); snapping them would misalign them with that plate. For JOURNEY the same arm carries the whole plate (no top plate exists to align with) — and it is this arm that draws the plate at the user's own 164x41.
   So the snap needs a caller-supplied classification, and the discriminator is not the function.

6. Padding: no new fill is needed. `menu_flank_panel` already returns the panel colour sampled from the art's own outer edge and `fill_pane_page(fill, bg, buf)` floods it; the pane flood above it uses `story_bg_rgba`. The existing letterbox already carries the right ground, so SQ-0827's `page_for` white-on-black trap is not on this path.

--- note 2026-08-13T07:44:15Z ---

Native-source half — MEASURED, and the premise is FALSE. Commit 5b19b9a3. Quest deliberately left OUTSTANDING: the magnification-uniformity question is a taste call for the user, not settled here.

1. **The 2x pre-double is not a second sampling.** `v6_scaled_art` doubles with image's Nearest, which at an integer ratio is pure replication (out i takes src floor(i/2)). A Nearest resample of that takes floor((o+0.5)*2N/T), and floor(floor(2u)/2) = floor(u) for every real u >= 0, so the pair IS floor((o+0.5)*N/T) — one Nearest resample from the artwork's own resolution. Bit for bit; pinned by `render::graphics::resample_tests::the_art_scale_predouble_composes_away_under_nearest` at (444,508),(456,522),(410,468),(328,378),(224,270),(222,254),(168,198).

2. **So it cannot fix what the user sees.** Everywhere the final resample magnifies — every pane from ~80 columns up, INCLUDING the reported 166x44 — sampling the native artwork changes not one pixel. The hybrid band path is canvas -> resize_directional -> crop -> `Resize::Fit(None)` at exactly band size (an identity), so there is no third resample either. Raster's `v6_fit_source` is the only place with a genuine non-integer double (prescale then protocol fit); hybrid is the default and has none.

3. **Where it differs it is WORSE, and by exactly this quest's own margin.** A target between the artwork's size and its double magnifies from the artwork while it minifies from the plate, so the direction decision flips. Measured on the real plate (Journey r30/890322), RMS against the artwork's own area average: 160x180 shipped 1.96 / from-native 11.26; 168x198 shipped 1.64 / 10.68; 200x234 shipped 0.80 / 9.93. The right-hand column is the reported aliasing back again — nearest at 1.4x keeps some art pixels twice and others once. The unit plate is the better source precisely because it is bigger.

4. **The real cause of the unevenness is non-integer magnification.** At 166x44 one art pixel is 3.69 device px. Emitted runs across the plate: 4 x7757, 3 x3372, 7 x2796, 11 x1965, 8 x1646, 15 x914. Snapped to k=4 (444x508) every run is a multiple of 4: 4 x12056, 8 x4804, 12 x2344, 16 x1244 — perfectly uniform.

6. **The snap is only available on 8 of the 12 sizes, and NOT at the user's own.** The plate straddles two arms, and the discriminator is `hybrid_bottom_plan`: `slack == 0` (no vertical letterbox margin) returns `Letterbox` before the menu test is ever reached, so Journey loses the Menu plan and its picture column goes down `draw_chrome_band_image`'s side-border TILER instead of `menu_flank_panel`. On the panel arm the dest box is chosen independently and IS snappable; on the tiled arm the factor is the uniform letterbox scale `s`, shared with the story viewport, and cannot move without taking ~17 columns of transcript with it. 166x44 (s = 1.845 = 738/400 exactly, slack 0) is on the tiled arm.

TASTE CALL OPEN, for the user: floor (free at 80x24, costs 8-32% elsewhere), round-and-crop (costs +1% to +19% of overflow beyond the box), or leave it. And whether it is worth doing on the panel arm alone when the reported size is on the other one.
