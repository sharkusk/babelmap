RE-MEASURED 2026-08-12 (commit 3f5eaf4b's lane) ON THE EXACT FIXTURE, SIZE AND KEY SEQUENCE THIS QUEST RECORDED — Journey release 30 (`stories/Journey - The Quest Begins.adf`), 117x64, map hidden, hybrid + kitty, four Enters from boot. THE SYMPTOM NO LONGER REPRODUCES.

The final screen carries exactly ONE virtual placement, the 320x378 picture column uploaded by the last flush, at rows 17..37 cols 4..43. The 920x575 intro splash from flush 2 holds no cells at all. The hand-rolled decoder and the placement oracle agree, with no disagreements listed — so this is not one decoder's reading.

WHAT I COULD NOT ESTABLISH, and it is worth saying plainly rather than claiming a fix: WHICH change closed it. The obvious candidate is SQ-0772's re-seat (`place_protocol` re-lays every ratatui-image row into self-describing, buffer-visible cells, and its doc comment names this quest). It is not that. I disabled `reseat_kitty_placement` outright, rebuilt, and re-captured: only one placement on the final screen, exactly as with it enabled. The pre-SQ-0772 shape self-heals under ratatui-core 0.1.2, because its diff compares `diff_option` as part of cell equality — a `Skip` continuation cell and the next frame's ordinary blank are NOT equal, so the diff does emit a space over them. The mechanism this quest's note describes ("identical to the previous buffer's blanks — so the diff emits NOTHING") does not hold against that diff implementation.

So either the capture predates a ratatui bump, or SQ-0747's band-lifecycle work changed which images Journey places. Not worth more cycles to bisect; recorded so nobody re-derives the dead end.

A buffer-level regression test for the mechanism was written and then DELETED rather than committed: with the re-seat disabled it still passed, so it discriminated nothing and would have been a false guard. `a_ratatui_image_placement_is_reseated_into_self_describing_cells` already pins the re-seat itself.

WHAT DOES GUARD THIS FAMILY NOW: `pty_emitted_stream::every_abandoned_upload_is_deleted_and_no_live_one_is` (SQ-0753), which asserts on the same capture that no image on the final screen has been deleted and no upload absent from it was left undeleted. A stale placement of an image the app has since freed would fail it.

CLOSED AS `confirm` RATHER THAN `done` on purpose. The quest's own note flagged "NOT YET CHECKED: whether the user sees this in Ghostty" — a real terminal may composite a partly-overwritten virtual placement differently from either decoder, and only the user's eye settles that.
