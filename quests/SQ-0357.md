A frame within a frame — ornate block shell (top a ramp cresting at centre, where the layer-tab strip overlays it) wrapped around an ordinary single-line box. Reads like an ornate book cover, and cost 2 cols + 2 rows of the map it framed. User confirmed and chose full removal over merely changing the default.

63 references. The removal took several things with it that existed ONLY to serve it — each found by following a compiler warning rather than by grepping:
  - `draw_framed`'s `base: BorderStyle` param: solely the picture-frame discriminator (every other style arrives via `sides`). Removed + 10 call sites updated. This also orphaned upper_window.rs's `let border_style = colors.virtual_window_border` — safe, since `sides` already carries it (upper_window_border_sides is derived from it).
  - `resolve_sides`' `Vec<String>` warnings: rejecting a per-side "picture-frame" was its ONLY warning, so it was returning a vec that could never be non-empty. Simplified to return PaneSides; 6 call sites.
  - style_editor.rs DIMMED its entire zone grid for picture-frame, and glyph_actions.rs REFUSED to open the glyph picker — both because a composite border has no per-zone glyphs to override. Every remaining border does, so both gates went. NOTE: style_editor.rs was missed by my first grep (head-truncated at 20 of 63 hits) and only caught by a final full sweep — worth remembering that a removal needs the UNtruncated list.
  - RAMP/PF_SIDE_L/PF_SIDE_R/PF_BOTTOM consts, draw_picture_frame(), the draw_pane_frame arm (incl. its <7x7 degrade-to-single path).

Tests: rewrote rather than deleted where the test still had value — `map_pane_default_is_a_single_line_border` (main.rs, TestBackend) still renders the REAL DEFAULT_STYLE_TOML end-to-end and now asserts ┌ + content 18x8 (vs 16x6 before: the two rows/cols reclaimed); `a_border_selector_opens_the_glyph_picker` keeps the sanity half of the old picture-frame-gate test. Deleted only the two tests whose whole subject was removed (picture_frame_exact_glyphs_and_content, picture_frame_tiny_pane_degrades_to_single, per_side_picture_frame_warns_and_falls_back).

Docs: style.example.toml (map_border → single; statusbar border comment listed picture-frame but not rounded — fixed both), docs/features/customization.md. README does not mention borders.

BEHAVIOUR CHANGE: an existing style.toml naming "picture-frame" now falls through parse_border_style's `_ => Single`, same as any unrecognised name — silent, and consistent with how that parser already treats garbage. Acceptable pre-release (no back-compat obligations).
