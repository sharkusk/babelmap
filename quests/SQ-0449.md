EXTENDED (user): persist the accumulated execution knowledge across sessions. Design: DON'T serialize the whole DisasmCache — persist ONLY the cumulative ever_exec_pcs set (the sole session-varying input); the cache is deterministically rebuildable from the story bytes, so on load we build fresh + re-fold the persisted PCs to reconstruct all verified/blue/Rd state. Compact + no cache-format versioning headaches. Sidecar: per-story under the SQ-0284 data dir (<data_base>/<story-key>/), a small binary of u32 PCs with a magic header (mirror the VFS/aux sidecar pattern, SQ-0278). PERSIST on quit when --debug is enabled. LOAD the sidecar whenever /debug OR --debug is used (so a casual /debug session benefits from prior --debug runs). Keyed by story-key so it's tied to the story; a stale/foreign file at worst shows a few wrong blue lines (acceptable for a debug aid) — optional story-hash guard. NOTE the asymmetry: only --debug sessions persist new tracing; a plain /debug session loads but doesn't write (could revisit).
