WHY SQ-0840's UNIFICATION DID NOT PREVENT THIS — asked by the user, "I thought we made all of the disk formats use the same path."

**It did, and this is not a hole in it.** SQ-0840 unified how a disk is MOUNTED AND QUERIED: `detect`, `mount`, `stories`, `pictures`, `contents`, behind `blorb::medium`. Every caller that mounts a disk shares that path — `graphics.rs:303`, `hints.rs:697`, `zvm-cli/media.rs:67`.

`launch_options.rs` **never mounted anything.** Its art enumeration is a FILESYSTEM DIRECTORY SCAN (`read_dir` at :201, `looks_like_art_name`, `belongs_to_story`) that predates disk support entirely and walks for loose `.MG1`-style files beside the story. There was nothing to unify, so unification did not reach it.

**Two distinct jobs, and only the first was done:**
1. "Every disk format is mounted the same way" — SQ-0840, complete.
2. "Everything that looks for a game's assets knows disks exist" — never done, and this quest is one instance of it.

## The coordinator's miss, recorded

SQ-0840's survey named three call sites and `launch_options.rs:225` was not among them. Worse: when the user separately asked whether the graphics APIs were duplicated, that site WAS inspected and cleared — correctly, because it is not a second decoder. But the question asked was "is the decoder duplicated?", never "does this enumerator know about disks?". A site can be clean on one axis and broken on another.

## A second fact that matters for the fix

**`Volume::pictures()` returns THE archive — one, by the format's own tiebreak — not all of them.** So a caller can be fully on the unified path and still be unable to offer BOTH Macintosh archives. Enumerating every archive on a volume needs `contents()` plus `InfocomPics::parse`. Being "on the unified path" was never sufficient here.

## AUDIT — what else has this shape

Every `read_dir` in `crates/app/src` was checked:

* **`hints.rs:553`** — scans the story's directory for hint sidecars, same shape. A hint file inside a disk image would be missed identically. **No demonstrable live case**: no disk in the corpus carries a hint sidecar, and Solid Gold releases carry hints inside the STORY, which `hints.rs:697` already reaches through the mount path. Latent, not symptomatic — do not fix it speculatively, but know it is there if a hint-bearing disk ever turns up.
* `persist_files.rs`, `storage.rs`, `fetch_worker.rs`, `hint_download.rs`, `picker.rs`, `picker_ui.rs`, `state.rs`, `glulx_session.rs` — all concern the HOST filesystem by nature (saves, downloads, per-game config, story listing). Disks do not apply.

So the fix here is the only live instance.
