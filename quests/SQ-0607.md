## Detail

`TerminalBackend::redraw_chrome` (crates/gvm-cli/src/glk_term.rs) opens with
`if !self.is_tty { return; }`. `grid_put_attr` still fills the cell buffer, so the
content is tracked and then never emitted — silently dropped rather than degraded.

Reproduced: `printf 'yes\nno\nlook\n' | gvm-cli stories/CounterfeitMonkey-11.gblorb`
produces no trace of the status grid, which on a TTY reads
"Back Alley, noon    Goals: 1  Score: 0".

By contrast zvm-cli's piped output carries status text inline: a v3 game emits its
status line (verified with Ballyhoo: "> In the Wings   Score: 0  Moves: 0") and a v4+
game's upper window comes through as ordinary lines (verified with arthrizm.z5 — the
menu header and legend appear).

## Fix shape

In the non-TTY path, emit each grid window's rows as plain text lines at the point the
game finishes writing them (before it blocks for input is the natural moment — that is
where `flush_out` already runs). Trim trailing blanks; skip a grid whose content has
not changed since it was last emitted, or a status line repeats on every turn.

Worth fixing on its own merits — the piped path is what the test harnesses and any
scripted use read — and it is a prerequisite for [[SQ-0606]], since a screen-reader
user would otherwise lose the status line entirely.
