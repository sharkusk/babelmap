## Detail

`TerminalBackend::redraw_chrome` (crates/gvm-cli/src/glk_term.rs) opens with
`if !self.is_tty { return; }`. `grid_put_attr` still fills the cell buffer, so the
content is tracked and then never emitted — silently dropped rather than degraded.

Reproduced: `printf 'yes\nno\nlook\n' | gvm-cli stories/CounterfeitMonkey-11.gblorb`
produces no trace of the status grid, which on a TTY reads
"Back Alley, noon    Goals: 1  Score: 0".

By contrast zvm-cli's piped output carries status text inline: a v3 game emits its
status line (verified with Ballyhoo: "> In the Wings   Score: 0  Moves: 0") and a v4+
game's upper window comes through as ordinary lines (verified with arthrizm.z5 — the
menu header and legend appear).

## Fix shape

In the non-TTY path, emit each grid window's rows as plain text lines at the point the
game finishes writing them (before it blocks for input is the natural moment — that is
where `flush_out` already runs). Trim trailing blanks; skip a grid whose content has
not changed since it was last emitted, or a status line repeats on every turn.

Worth fixing on its own merits — the piped path is what the test harnesses and any
scripted use read — and it is a prerequisite for [[SQ-0606]], since a screen-reader
user would otherwise lose the status line entirely.

## Shipped 2026-08-03 — commit 394497f9

Done as the prerequisite for SQ-0606 (its own plan lists this as step 4).

### Implementation
- `grid_plain_text(&GridWin) -> String` — rows the grid currently owns, trailing
  blanks and blank rows trimmed.
- `TerminalBackend::emit_grids_plain()` — called from `flush_out` (off-TTY only),
  i.e. right before the game blocks for input.
- New fields: `last_grid_plain: Vec<(u32, String)>` (per-window dedupe) and
  `plain_at_line_start: bool`.

### The three rules, and why each is needed
1. **Row count from `rect.height`, not `cells.len()`.** `grid_put` grows the cell
   buffer to whatever row the game addresses; it never shrinks on its own.
2. **Dedupe per window.** A status line is rewritten every turn and usually says
   the same thing.
3. **Break onto a fresh line when mid-stream.** Needed a NEW field —
   `current_col` is a TTY-only wrap counter and is not maintained in put_text's
   off-TTY branch, so the first attempt produced
   `Can you hear me? >>  Back Alley, noon ...` welded to the prompt.

### Verified
Against the pre-change build (worktree at cd93a404), piped:
- byte-identical where no grid exists: Kerkerkruip 223, ABCA5 632, BlueLacuna 187
- additive only where one does: CounterfeitMonkey-11 122 -> 201, Coloratura
  2128 -> 2195
- status appears turn 1, then only on change (Back Alley -> Sigil Street)
- TTY output byte-identical under a pty for CM (987 B), Kerkerkruip, Coloratura
  (38642 B)
- Gate 0 errors, 64 == 64. Clippy clean.

### A test that lied, and the fix
`piped_grid_that_shrank_does_not_report_rows_it_lost` PASSED under falsification.
Cause: `window_layout` already calls `cells.truncate(rect.height)`, so the
rect-shrink path never reaches `grid_plain_text` with a stale buffer. Rewrote it
as `piped_grid_reports_only_the_rows_it_owns`, exercising the path that does
(a `grid_put` below the rect with no layout event) — it now fails with
`"Hall\n\nSTALE\n"`. Kept a separate test for the layout-shrink path since that
behaviour is worth pinning even though a different mechanism provides it.

Worth remembering: falsification caught a test asserting a true fact for a false
reason. The other three rules all failed correctly first time.

### Note for SQ-0609
Kerkerkruip's opening line, piped, is literally "Kerkerkruip has a mode optimised
for those using a screen reader. Enable the screen reader mode?" — a game that
already solved this for itself and can be asked what it changes.
