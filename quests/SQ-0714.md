--- note 2026-08-09T15:30:57Z ---

MEASURED 2026-08-09, with fmvpoker.blb in place (a copy of Zork0.blb — the game reuses Zork Zero's picture file, and FMVPOKER.EG1 is byte-identical to zork0.eg1, so the picture NUMBERS match). Resource resolution is fine: 2213 pictures available, @picture_data(99) -> h=400 w=640 and (100) -> h=128 w=96, both resolving.

THE DEFECT, from the drained TurnResult:

  EV pic=0  win=0..7 at(x1,y1) erase=true  at_cursor=true   <- erases every window
  EV pic=99 win=0    at(x1,y1) erase=false at_cursor=true   <- the 640x400 BACKDROP

`at_cursor=true` on that draw routes it down the window-0 inline-float path in
GameSession::apply_picture_event, so it never reaches a window canvas. Confirmed
downstream: the model publishes NO Graphics window at all across every step
(5 windows: buffers and grids only), and classify_windows reports story_gfx=None.
The art therefore renders as a transcript float in the text flow rather than as
placed backdrop, which is why the reporter sees some graphics with the layering
wrong, and differently in each render mode.

WHY THE DISCRIMINATOR MISFIRES. SQ-0695 established `at_cursor = (y == cursor_y)`
to tell Zork Zero's drop-caps and Shogun's inline ship (drawn ON the text line,
meant to flow with the paragraph) from Arthur's centred plates (drawn at a position
the game computed while the cursor sat elsewhere). fmvpoker defeats it honestly:
@erase_window resets the cursor to (1,1), and the game then draws its backdrop at
(1,1). The two are indistinguishable by that rule alone.

CANDIDATE SIGNALS, none yet verified — measure before choosing:
- SIZE. Picture 99 is 640x400, the whole screen. A float FLOWS BESIDE TEXT; one
  that fills the entire window cannot be one. This is the strongest signal and the
  cheapest to test.
- NO TEXT SINCE THE ERASE. `out_chars` is 151 on both the erase and the draw — not
  one character was printed between them. A drop-cap is drawn as text flows.
- Whether an erase of the SAME window immediately precedes the draw.

Do NOT simply invert the rule: Zork Zero's drop-caps and room icons, and Shogun's
opening ship (y=0 resolved to the cursor, with a right margin set for text to flow
beside it), all depend on the inline path and are covered by existing tests.

Related and possibly a shared root: SQ-0712 (mysterious01 — text window and
graphics window both at (1,1)) is also a window-0 placement question. Both should
be looked at against SQ-0697's unfinished "v6 text is paint" half rather than
patched independently.
