Design sketch (from the SQ-0425..0427 disasm debugging thread):

Confidence tiers, highest→lowest:
1. Executed / runtime-confirmed — addr in exec_pcs, the parked PC, or a call-stack routine. Ground truth.
2. RD-discovered — recursive-descent from constant `call` targets (proven call target).
3. Linear-scan (soft) — heuristic guesses (byte ≤15 + validating body); where false positives live.
4. Data (.byte) — unreachable/unknown bytes.

What it touches:
- zvm crates/zvm/src/cpu/disasm_cache.rs: track per-unit provenance. Today `build()` has `rd` (hard) and `extra` (linear/soft) sets and folds `exec_pcs`/parked-PC/func_addrs via confirm_pc/confirm_routine, but the tier isn't retained per Unit. Add a provenance tag per Instr/RoutineHeader (rd vs soft vs confirmed vs data). `disassemble()` returns Vec<String> — extend to carry a per-line tier (parallel Vec or a small struct), without breaking the existing string format.
- app Debugger trait (crates/app/src/engine.rs) + GameSession impl (session.rs): surface the per-line tier alongside the disasm text.
- render crates/app/src/render/debug_panel.rs draw_disasm: apply a per-tier style.
- style: add ColorScheme fields + style.rs selectors + style.toml docs for each tier (per the styleable-UI policy — every new UI element themeable). Suggested selectors e.g. debug_disasm:executed / :rd / :soft / :data.

Note: the `|` exec-coverage gutter already marks executed (binary); this adds a graded color so RD-inferred vs linear-guessed vs data are distinguishable at a glance — the linear-soft tier is the "don't fully trust this" signal that would have flagged the 0x0058f0 false positive.
