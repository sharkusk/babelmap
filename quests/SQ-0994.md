## The organising principle: separate what was MEASURED from what was ASSUMED

That distinction is the reason this is worth building, and it should shape the layout rather than being a footnote. Several values lanthorn runs on are guesses that look exactly like measurements, and a user cannot currently tell which is which:

- The cell size falls back to a hardcoded 10x20 when `CSI 16 t` goes unanswered — and on Windows there is no ioctl backstop at all. `cell 10x20` and `cell 10x20 (assumed)` mean completely different things, and every graphics geometry decision downstream is computed from it. This is exactly what bit SQ-0973, where the nominal 10x20 made a device box 4580x2880.
- A capability list is empty both when the terminal said "no" and when nobody asked (non-tty, `halfblocks()`, tmux without passthrough).
- The interpreter profile may come from the medium, from a user answer, or from a fallback — `ProfileSource::{Medium, Asked, Fallback}` already distinguishes these and `licenses_machine_colours` already turns on it.

## What to report (accumulated across several quests)

**Terminal**
- Protocol in use, and whether auto-detected or forced by `--image-protocol`.
- Cell size in pixels, **and whether measured (`CSI 16 t`), derived (TIOCGWINSZ), or assumed (10x20 default)**.
- Cell aspect and its signed distance from 2.000 — the ratio that makes a half-block sample square. Note a cell is `round(adv*px)` by `round(line*px)` and the two round at different rates, so real cells swing 1.75..2.25 even for a font whose design ratio is exactly 2.002. Ghostty's `adjust-cell-height`/`adjust-cell-width` act directly on this, so naming the deviation is actionable. (This was SQ-0986, which should be folded in here and closed as subsumed — its own note carries the measurements.)
- Detected capabilities: `Kitty`, `Sixel`, `RectangularOps`, `TextSizingProtocol`, `CellSize`, `Background`, and `KittyCompression`.
- **Whether kitty uploads are actually being compressed** — the question that prompted this. `KittyCompression` present means `o=z` is on the wire; absent means raw. Failure is silent either way, which is why it needs surfacing.

**Story**
- Engine, Z-machine Version or Glulx, release and serial, and the medium it was mounted from.
- Interpreter profile, its `ProfileSource`, the palette it resolves colour numbers through, and `honor_game_colours`.

**v6 render**
- Hybrid vs raster and which `picture_takeover_reason` fired.
- Native screen size, `art_scale`, current magnification, and whether the pixel lock is on.

**Traffic**, if cheap to carry: bytes emitted this session, and the compressed/raw ratio when compression is on. SQ-0977 measured that under half-blocks ~80% of the stream is SGR, and under kitty the placeholder cells now cost more than the compressed images do — both are the kind of thing a user reporting "it feels slow" could paste back.

## Constraints

- One slash command in the single `slash::COMMANDS` registry (`crates/app/src/slash.rs`) — verb-noun, no Command enum.
- Every new UI element must be styleable via a `style.toml` selector; never hard-code a colour.
- Do not add per-frame cost to gather any of it. If a statistic is not already tracked, say so rather than adding a counter to the render path.
