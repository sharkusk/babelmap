--- note 2026-08-09T23:29:50Z ---

User's report 2026-08-09, Zork Zero booted from the Amiga disk image with the interpreter profile in place: "NO dropcap or map icons … map works, and room icon is shown there".

So the same pictures render correctly inside the in-game map and produce nothing inline in the transcript. **The art decodes; only the inline path fails.** That is the whole diagnosis worth having up front, and it rules out the decoder.

STRONG HYPOTHESIS — the PNG seam. The inline path is built around PNG bytes: `PictSource::pictures_png()` and `crates/app/src/render/inline_image.rs` work from encoded images, which is what a Blorb hands over (`PNG ` chunks, sometimes `Rect` placeholders). A native Infocom archive hands over something structurally different — `blorb::infocom_pics::Picture { width, height, indices, palette, transparent }` with an `.rgba()` accessor, i.e. **decoded pixels, no PNG container**. If the inline path asks for PNG bytes and the native source can only answer `None`, drop caps and room icons silently vanish while every path that takes decoded pixels — including whatever draws the in-game map — keeps working. Verify by checking what the inline path actually requests before building anything.

If that is the shape, the fix is a seam question rather than a rendering one: either the native source encodes to PNG on demand, or the inline path accepts decoded pixels alongside PNG. Prefer whichever keeps ONE representation flowing through the renderer; two parallel paths through `inline_image.rs` is how the hybrid/raster divergences in this codebase started.

CONTEXT: drop caps and room icons are the subject of SQ-0704 (flattening an inline image onto the story page) and SQ-0695 (`at_cursor` distinguishing an inline float from placed art). Both assume the image arrives at all, so neither is implicated — but their tests are the ones that will tell you if a fix regresses the Blorb path, which must stay byte-identical.

NOT this quest: the wrong COLOURS on compass boxes, the room icon inside the map, and Arthur's banner — that is SQ-0740 (Amiga colour-register semantics).
