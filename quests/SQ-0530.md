SCHEDULED 2026-07-29, paired with SQ-0549 — strong evidence they are the SAME root cause, and one Arthur probe serves both.

Both are "hardcoded near-the-top row" assumptions colliding with Arthur, which paints its status bar at NATIVE ROW 12 (directly above the story window), not at the top of the screen. That row-12 fact is already documented in-tree at `crates/app/src/render/screen.rs:507`.

The two independent places that assume the bar is near row 1:

1. RENDER (SQ-0549) — `render/screen.rs`, `const STATUS_BAND_ROWS: u16 = 4`. Rows < 4 get anchored to the top of the pane; rows >= 4 get stamped absolutely. Row 12 >= 4, so the bar is drawn at terminal row 12 — the reported "floating 25% down".

2. ROOM DETECTION (this quest) — `crates/zvm/src/location.rs:82`, `status_line_room_name`:
       let scan = active_rows.min(2).min(upper.rows);
   It scans **only upper-window rows 1 and 2**, for both the `Location:` label form and the first-segment form. The centered fallback `centered_status_line_room_name` is likewise hardcoded to row 1. Arthur's room name is at row 12, so every one of these paths returns None and no room is ever detected. That matches the symptom exactly.

HYPOTHESIS, NOT YET CONFIRMED — I have not run Arthur. Probe first (standing rule: never implement a guessed interpretation of render geometry). One headless dump serves both quests: for Arthur, print every upper-window row index with its text, plus the story window's top row, plus the window w_px/h_px. Confirm the room name really is at row 12 and note whether it is left-justified, centered, or `Location:`-labelled before touching either site.

Design note for the fix: in both places the correct rule is probably "the status band is the full-width run immediately ABOVE the story window's top row", which is derivable — the hybrid path already computes `story_rows`, and the cell path has `layout.story`. Resist widening the `min(2)` scan to some larger constant; that just trades one magic number for another and risks pulling menu/banner text into room names for other games.

REGRESSION SURFACE (this is a zvm change, so it is load-bearing for many games): `status_line_room_name` is shared by every v4+ game. Changing its scan MUST keep passing the existing Hitchhiker / Bureaucracy / AMFV left-justified cases, the `Location:` label form, and the BeyondZork/Trinity CENTERED path — whose comment is explicit that the centered result is accepted only under PlayerParent validation. Do not weaken that validation to make Arthur work.
