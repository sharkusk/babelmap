--- note 2026-07-29T03:46:32Z ---

REOPENED by user test against ~/.babelmap/saves/advent.blb.save/default.babelmap.

Repro: walk SOUTH from "At West End of ..." into the first "Maze" room, then a bare
/peel-layer. Result: "peel-layer: Maze's Unknown passage is not a boundary — both sides
stay connected another way."

TWO SEPARATE DEFECTS.

1. WRONG EDGE (the real one). The first cut assumed the passage walked is reachable as an
   exit OUT of the room just entered, i.e. opposite(arrived_via) from the current room.
   That only holds when the passage is reciprocal. Here it is not: you enter the Maze going
   SOUTH but leave going DOWN, so the Maze room has no north exit and the edge asked for is
   not the passage the player used at all. `peel_at_edge(graph, room, d)` cuts an edge
   leading OUT of `room` and keeps `room`'s side (SQ-0364), so it cannot express "cut the
   edge I arrived on".

   The passage actually walked is the INCOMING edge `prev --arrived_via--> current`. Cutting
   it must keep the FAR side (the room just entered), which no existing mapper entry point
   does: `peel_at_edge(prev, arrived_via)` would cut the right edge but keep the wrong side.

   User's requirement, verbatim: "the point of not having to specify a direction is that
   this may be a one-way entrance so we want to be able to peel even if there isn't a
   return path." So the fix must work with NO return edge at all.

   Needs: a mapper function that peels at a given incoming edge, taking the destination
   side. Also record the previous room alongside the direction — `Mapper::arrived_via`
   currently stores only the Direction, and the incoming-edge cut needs the origin too.

2. THE REFUSAL NAMES A DIRECTION IT NEVER TRIED. In input.rs the `Err(why)` arm passes the
   ORIGINAL `dir` argument to `peel_refusal_message`, which is still `None` for a bare
   /peel-layer, so it renders as "Unknown". It must report the seam actually attempted.
   Cheap fix, independent of (1), and worth doing regardless — the message is currently
   actively misleading.

ALSO CHECK while fixing: the refusal said "both sides stay connected another way", so even
the intended cut may not disconnect the region here. Now that maze rooms are properly
distinct (SQ-0526) there may be several routes between the maze and the rest, in which case
a single-edge cut can be legitimately insufficient and the command needs to say so in terms
the player can act on.
