## Confirmed by field measurement — and the cause is NOT the rounding

`/dump-windows` from the user's two machines, same game (advent.blb):

| | 1x | scaled |
|---|---|---|
| cell reported to the game | 7x14 | **14x28** (exactly 2x) |
| pane | 127x68 cells = 889x952 px | 99x52 cells = 1386x1456 px |
| toolbar window | **3 rows**, canvas 889x42 | **2 rows**, canvas 1386x56 |

The reported cell is exactly doubled on the scaled display, so `Picker::font_size()` is
handing us DEVICE pixels there, not logical points (the `startup.rs` comment's assumption
is wrong for this terminal). advent asks Glk for a fixed pixel height; `ceil(H/14) = 3`
rows but `ceil(H/28) = 2`, so the same request buys one row fewer.

In apparent (logical) units: the toolbar is 42 units tall on 1x and 28 on the scaled
display — **two thirds the size**, against text that is the same apparent size on both.
That is the whole of the reported symptom. The earlier div_ceil dead-band theory was
wrong, and the threshold rule proposed to fix it was overfit to one cell height.

## The fix, and its trade-off

Report a DPI-independent cell size: divide the terminal's reported cell by the display
scale before handing it to Glk. Then a game's fixed-pixel request keeps the same apparent
size on both machines.

- **Cost:** the canvas shrinks with it (693x42 instead of 1386x56) and is upscaled 2x by
  the terminal to fill its cell rect, so bitmap art gets softer. Sharpness vs consistent
  sizing is a real trade, not a free win.
- **Detection:** no reliable signal. Wayland sets no `GDK_SCALE`/`QT_SCALE_FACTOR` (checked
  on the user's session — scaling is per-output), and guessing from "the cell looks big"
  would misfire on anyone running a genuinely large font at 1x. So it needs to be an
  explicit config key, defaulting to no change.

## Same root cause as SQ-0563

Pixel-precise mouse reporting is disabled because SGR-Pixels reports device pixels while
the cell size was assumed logical. Whichever way that discrepancy is resolved, the same
scale factor settles both — one setting, two fixes.
