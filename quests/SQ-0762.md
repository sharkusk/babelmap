AGREED WITH THE USER 2026-08-10 ("Tier 1 it is").

THE GAP THIS CLOSES: every harness in this repo asserts on babelmap's internal model — the cell buffer, the layout, the placement records. **None asserts on the bytes we actually write to the terminal.** The model can be right while the emitted stream is wrong, and this session produced several defects that were "not in the model" yet plainly visible on screen. A byte-level harness is the only thing that can tell those two cases apart.

WHAT IT MUST DO:
- Run the real binary under a pty, send keystrokes, capture the emitted byte stream.
- **Verify the graphics protocol actually negotiated.** If the pty does not advertise kitty support and we silently fall back to halfblocks, the harness is exercising the wrong backend and every result is worthless. Check this FIRST and fail loudly rather than quietly measuring the wrong path.
- **Decode the stream into a readable form** — named escape sequences with their parameters (kitty APC graphics commands and their placement rects, SGR colour changes, cursor moves), not raw bytes. Raw output is unreadable and therefore undiagnostic; the decoding is most of the value.
- Be usable ad hoc (drive a story, dump the decoded stream to a file) as well as from a test.

CROSS-PLATFORM CONSTRAINT (see [[cross-platform-requirement]]): a pty is unix-only. Gate it so Windows still builds and its test suite still passes — a `#[cfg]`-gated test or an explicit skip, never a broken build. `zvm`/`gvm`/`scott`/`blorb` take zero external dependencies; the app may add them, and a test-only dev-dependency is the least invasive way in if a pty crate is needed. `script(1)` is present on this machine if a shell-level approach is preferred.

FIRST REAL TARGET, to prove it works: Journey off `stories/Journey - The Quest Begins.adf` (release 30 — NOT `journey.z6`, which is release 83 and a different build, see [[CLAUDE.md]] Test fixtures) at pane 115x61. The open defect is `menu_flank_panel`'s fill painting rows 53..61 under the menu. In the emitted stream that must appear as either a placement rect reaching those rows or SGR spans setting the panel's background there. If the harness cannot distinguish those two, it is not finished — they are different bugs with different fixes.
