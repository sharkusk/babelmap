--- note 2026-07-29T02:30:40Z ---

Symptoms (user, TTY): after a host Save State in Zork Zero, the first command's output prints with the HOST THEME's foreground; the background is still the story's white. Only fg is wrong. It self-heals on the next turn. Runs with honor_game_colours = true.

RULED OUT by headless probe (zork0-r393-s890714.z6, honor_game_colours = true, driven to a Line prompt in the Banquet Hall):

1. The VM is innocent. `Engine::save_state()` does not disturb the colour state. Transcript runs for the turn immediately after the save still carry fg=Standard(2) bg=Standard(9), identical to the turn before it, and so does the turn after that.
2. The story window keeps its pair across the save: `BufferWindow { fg: Some(16777218), bg: Some(16777225) }` before the save, after the save, and after the following command.
3. The rest of what the save path reads is also harmless — calling `aux_data()` and `pictures_png()` in between changes nothing.
4. The renderer is symmetric in fg/bg. `render/transcript.rs` resolves each channel through `resolve_glk_channel(game_ch, slot_ch, base_style_ch, honor)`; a run carrying both channels cannot lose only its fg at draw time.

So the loss is in the app layer between the save and the next turn's push, OR that one frame renders through a different path.

MECHANISM THAT FITS the "story bg + theme fg" appearance: the chunk's runs end up with fg = Default while bg is still painted by the v6 page flood (`fill_pane_page` fed by `story_bg_rgba`, SQ-0532 wave-5), which does not consult the runs at all. A Default fg then resolves to the theme's transcript ink. That is exactly how you get the story's background under the host's foreground.

PRIME SUSPECT (unverified): `AppState::prevailing_run_colour_before()` returns the last run for which `fg != 0 || bg != 0` — so a run carrying a bg but NO fg yields the pair `(0, bg)`. `fill_line_default_colours()` then fills the bg and leaves fg Default, an fg-only loss that would heal on the next turn. Today that path only runs on the `merge_echo` branch in turn.rs (self-echoing games), and the probe did not see Zork Zero self-echo its command, so the trigger is not yet explained — check whether the Save State flow changes `last_transcript_line_is_story()` / `game_echoes_command()` for that one turn.

NOT REPRODUCIBLE HEADLESSLY YET: `turn.rs::finish_command_turn` is a BIN module (`pub(crate)`, `crate::` refs), so an integration test cannot drive the real turn path. Reproducing needs either a lib-side extraction of the echo/merge logic or a test that replays the same AppState calls by hand.
