FOUND 2026-08-11 by a read-only audit of the batch the user had confirmed from memory. Neither SQ-0756 nor SQ-0759 is behaviourally broken — the code changes are real and the behaviour is right. What is missing is the guard.

THE HOLE: **nothing in the entire tree calls `dispatch_slash_outcome(SlashOutcome::DumpWindows, …)`.** Every test drives the supplier side and stops one call short of the consumer the fixes actually changed.

SQ-0756 (commit 87a120f6 — the dump must describe the last GAME frame, not the modal, and be copyable). `crates/app/tests/window_dump_last_game_frame.rs` has 4 passing tests that cover the bookkeeping well: `the_dump_describes_the_last_game_frame_not_the_modals` drives real frames, opens a modal, asserts `path_of(&frame.cells) == "path:hybrid-ring"` and `frame.modal_frames_since == 2`; the writer is covered by `the_dump_is_written_to_a_copyable_log_verbatim`. But **reverting the one line `let (frame, frame_line) = state.v6_dump_frame();` back to `state.v6_cell_map.borrow().clone()` breaks NO TEST in the tree** — despite that test file's own doc comment claiming precisely that falsification. Nothing asserts the `[dump appended to …]` path line is surfaced to the user, which was half the requirement. The placeholder-glyph assertion is also somewhat circular: the test feeds plain ASCII in.

SQ-0759 (commit 28241616 — capturing a dump must not churn the state being diagnosed). `crates/app/tests/window_dump_bound_key.rs`, 9 passing tests. Claims (1) and (2) are genuinely guarded: `a_ctrl_binding_survives_the_direct_set_filter` is a real regression guard on the `DEFAULT_DIRECT_COMMANDS` entry, and `the_palette_route_moves_both_counters_which_is_the_defect` drives modal frames and asserts `after.1 > before.1`. **Claim (3) is not covered at all.** `a_bound_key_capture_leaves_the_render_path_and_upload_count_untouched` calls `key_to_command` (a pure resolver) and then draws one more frame — *the dump is never taken*. What it proves is that drawing another identical non-modal frame moves neither counter. If the `DumpWindows` arm began invalidating the band cache or pushing a path entry, the assertion labelled "a bound-key capture must upload no bands" would still pass.

Note also what that commit does and does not do: it is mostly the config-syntax rewrite plus keymap diagnostics. The one behavioural change touching the complaint is adding `"dump-windows"` to `DEFAULT_DIRECT_COMMANDS` (without it, `"ctrl+d" = "dump-windows"` resolves to `KeyResolve::None`). It does not remove the churn; it makes the churn AVOIDABLE, and only if the user hand-edits config.toml — no default binding ships.

ACCEPTANCE, both headlessly checkable:
  - SQ-0756: a test invoking `dispatch_slash_outcome(SlashOutcome::DumpWindows, …)` against a state whose `v6_cell_map` holds a MODAL frame and whose `v6_last_game_frame` holds a GAME frame, asserting the emitted transcript lines describe the game frame AND carry the log path. Falsify by reverting to `state.v6_cell_map`.
  - SQ-0759: the same dispatch call with `band_encodes` and `v6_path_log` snapshotted immediately before and after, asserting both unchanged. Falsify by making the arm touch either.

WIDER LESSON worth applying beyond these two: a test that exercises everything except the line the fix changed passes for the wrong reason, and a doc comment asserting a falsification nobody ran is worse than no comment. When a fix is one line in a dispatch arm, the test must go through that arm.
