## Shipped 2026-08-03 — commit 7c2d1f53

### Naming decision
`--story-only` over `--lower-only`. "Lower window" is Z-machine jargon: Glk has
buffer and grid windows (no upper/lower), and Scott has neither. `--story-only`
reads correctly in all three vocabularies. `--lower-only` survives as a zvm-cli
alias only.

`--no-status` still works but prints a notice on stderr and is honoured —
silently ignoring a removed flag looks identical to honouring it, which is the
worst of the three options. zvm-cli's parser ignores unknown flags (`_ => {}`),
so without the explicit arm it would have been silently dropped.

### Why the rename at all
Two switches of different strengths were sharing a word:
- plain mode: quietens **one-row** chrome, keeps menus and forms (SQ-0612)
- `--story-only`: takes the **whole** upper window, menus included

### gvm-cli parity
Same flag, suppressing every grid window. On a TTY it stops painting them but
leaves the window layout untouched — a Glk game lays itself out from the window
tree, so pretending its windows do not exist would change what it draws. Result:
reserved rows go blank rather than reflowing. Measured 19 status paints → 0.

### Help rewrite
Every `--plain` block described a flag that only stripped escapes. Since then it
also hands back line editing and echo, drops `[MORE]`, and quietens the per-turn
status — none of it findable from `--help`. Each engine's block now says what it
does in that engine's terms and points at `/status`. scott-cli's says explicitly
that there is no `--story-only` there, because its room block IS the story.

### Verified
`--plain --story-only` loses Planetfall's InvisiClues menu (0 `RETURN = See hint`
lines vs 1 under `--plain`); same for Counterfeit Monkey's hint menu in gvm-cli.
All three spellings select story-only. Gate 0 errors, 64 == 64. Clippy clean.
Falsified twice.
