USER 2026-08-10: "To do the dump windows in journey I need to ctrl-p which switches to frameless. This causes several redraws. We may want to have a hot key that doesn't mode switch."

THE PROBLEM: the act of measuring perturbs what is measured. SQ-0756 already fixed the correctness half — the dump now reports the last NON-MODAL frame rather than the palette's — but the redraws still happen, and they churn exactly the counters the dump exists to report. Visible in the user's own captures: `recent render paths ... raster x18 ... cell — modal overlay open: palette x23`, `band uploads since launch: 163`, `24 modal frame(s) ago`. Band-cache state, upload counts and path history are all polluted before the snapshot is read, and the frameless switch is itself a layout change that can evict cached bands.

WHAT ALREADY EXISTS, and should be checked FIRST before building anything: `config_template.rs` documents a `[keymap.global]` section binding registry commands to keys —

    [keymap.global]
    quit = "ctrl+q"
    toggle_map = "f2 ctrl+m"

with "Names are the snake_case command names from the command registry (see /help)". `dump-windows` is a registered command (`slash.rs:468`, `Context::Global`). So `dump_windows = "f9"` may already do exactly what the user wants. UNVERIFIED — `keymap.rs` contains no mention of `dump`, and the registry name is kebab-case while the keymap doc says snake_case, so the name conversion needs checking end to end.

THREE THINGS TO ESTABLISH:
1. Does binding `dump_windows` in `[keymap.global]` work today? If yes, this may need only a documentation line and a note to the user — say so rather than writing code.
2. Does the bound path avoid the modal entirely, or does it still route through the palette/hotkey dialog?
3. Does taking a dump via a bound key leave the render path, band cache and upload counters undisturbed? That is the actual requirement. A hotkey that skips the palette but still forces a redraw has not solved it.

Note the standing rule from [[command-registry]]: keys bind to command strings, there is no Command enum, and new commands go in `slash::COMMANDS`. Whatever the fix, it must not introduce a second dispatch path.
