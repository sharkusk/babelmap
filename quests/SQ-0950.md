--- note 2026-08-21T02:04:10Z ---

MEASURED, not inferred. `cargo run -p app --example ring_scout -- --story stories/fmvpoker.z6`:

  booted as IbmPc · release 60 serial 001227 · screen 320x200 · art scale Some((2,2))
  win0 Some((0,0,640,400)) -> clear Some((0,0,640,400))  prose Some((22,234,594,158))
  picture_takeover: art_paints_anything  -->  RASTER (the ring never runs on this frame)

So this is NOT SQ-0944 failing. fmvpoker's story window covers the screen and its plate paints, so the frame goes to the full-frame raster composite, which rasterises every character on the screen by construction — chrome runs AND the transcript prose. Under half-blocks a rasterised 8x16 glyph arrives as 8x2, so the whole game is mush. A pty capture at 117x40 (cell 10x20, --image-protocol halfblocks) shows ZERO glyphs anywhere on the pane.

SCOPE. `--all` says fmvpoker is the only title taking raster on its BOOT frame (zork0, arthur, shogun, journey, mysterious01, scopa, advent all reach the ring). But `picture_takeover` is a per-FRAME decision, so any title hits this on a full-screen picture frame — Zork Zero's map/rebus and Arthur's Merlin composite are the ones already named in the code. fmvpoker is simply the title that is there from the first frame.

THE OBVIOUS CHEAP FIX DOES NOT WORK — tested, not assumed. Stubbing `art_paints_anything` to false does not route fmvpoker to the ring: `art_encloses_screen` fires next and it is raster again. Both arms are genuinely true of this screen (the plate paints AND encloses), so narrowing the gate means retiring several arms against a screen that really is a full-screen picture, which is what the takeover exists for. SQ-0711's scopa lesson points the same way: a screen with pixels on it can only be shown by the composite.

(An apparent difference in the card art between the two captures was a different deal, not a rendering change — fmvpoker animates. Pin `random_seed = 12345` in the harness config dir before comparing frames, as SQ-0936's previews had to.)

SO THE LIKELY SHAPE IS SQ-0944'S MOVE ONE LAYER UP: keep the composite, withhold the text rows from it (`TextLayer::SkipGlyphRows`, which raster currently never uses — it passes `TextLayer::All` and that is deliberate, "raster has no cells to draw text with"), and stamp the runs as glyphs over the placed image with a ground sampled from underneath, gated on `backend_flattens_alpha_to_black`/`backend_layers_glyphs_over_art` exactly as the ring is. Two things make it more work than the ring's version: the composite is built OFF-THREAD and cached (`V6Ready`), so the skip set has to reach the job and the stamp has to happen after placement; and the raster path also images the transcript prose and any secondary prose window (SQ-0729), so it is not only chrome runs.

Worth deciding first whether raster-on-half-blocks should exist at all, or whether the honest answer is that raster is a kitty-and-better mode and half-blocks always gets a cell-based rendering of the same screen.
