--- note 2026-07-11T20:27:12Z ---

Precedent to reuse (don't invent a new persistence path): the codebase already splits "VM = pure bytes, host = disk I/O". (1) crates/zvm/src/quetzal.rs: save_quetzal(machine)->Vec<u8> / restore_quetzal(machine,&[u8]) are explicitly "no filesystem I/O" — the app writes the bytes out. (2) crates/app/src/aux_store.rs is the near-exact mechanism: a per-story BTreeMap<String,Vec<u8>> persisted to <save_dir>/<stem>.aux via aux_path()/read_global_aux()/write_global_aux() (std::fs + create_dir_all). The SQ-0277 Glk VFS is ALSO a name->bytes map (Model.files), so SQ-0278 = flush/load that map to disk the aux_store way, keyed by the story's IFID, on close/quit and at startup — plus decide sync policy (per-write vs on-close vs on-quit) and name sanitization for real filenames. See also app/src/session.rs writing .qzl saves for the save_dir + EngineSave pattern.

--- note 2026-07-11T20:30:49Z ---

CLI precedent (both hosts already do this): (1) gvm-cli/src/main.rs drive() writes machine.save_state() to {story}.glksave on SaveRequest and reads it on RestoreRequest — and since the v4 Glk snapshot now EMBEDS the VFS, that .glksave already round-trips the VFS across real sessions, but only on an explicit save, not auto-on-quit. (2) zvm-cli is the direct auto-persist template: aux.rs + machine.aux_data is a per-story key->bytes map encode_aux'd to a companion file, loaded at startup (main.rs ~477) and written on exit (~493) — the Z-machine twin of app/src/aux_store.rs. So SQ-0278 = give the Glulx Glk VFS (Model.files) the SAME automatic load-on-start / flush-on-quit treatment the Z-machine aux store already gets, wired in EACH host (app + gvm-cli), keyed by IFID/story path. Decide: separate .gvfs sidecar vs reuse the aux mechanism; sync policy (on-quit is the aux precedent); and whether a thin shared host helper is worth it vs per-host wiring.
