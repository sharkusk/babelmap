--- note 2026-08-14T06:58:52Z ---

The user's report, verbatim:

"the dialog for the auto layer split needs improvement. first it looks like it has a spelling mistake \"You came d out of Living Room\". It should spell out the direction/portal (eg. \"You came DOWN from the Living Room\"). Then the room list is cut-off as the dialog isn't wide enough when displaying the room names (we should list the rooms as bullet points and grow the dialog taller). Then, there is no space between the layer selection list and the buttons. there should be at least one space between those."

FOUR things, and the first two are one site.

1. **The direction is abbreviated.** `crates/app/src/input.rs:3795` uses `mapper::direction::short_label(suggestion.seam.dir)`, which yields "d". `crates/mapper/src/direction.rs` has ONLY `short_label` (line 76) — there is no long-form name to reach for, so one has to be added. Note `short_label` is load-bearing elsewhere: `SeamKey`'s hand-written `Ord` uses it precisely because it is "distinct for all thirteen" directions, so do not repurpose or change it — add alongside.

2. **The sentence is semantically WRONG for a descent, not merely abbreviated.** `input.rs:3799-3805` builds the Structural message as `"You came {d} out of {from}."` with `"Those {n} rooms have no other way in."`. That was written for SQ-0439's original RETURN trigger, where the seam is the way OUT and `from` is INSIDE the region. SQ-0853 added the descent trigger, which reports the SAME `Trigger::Structural` but where the seam is the way IN and `from` is OUTSIDE the region — the trapdoor, Living Room, Down. So the prompt describes a descent as if it were a return. The user's own wording is the correct descent reading: "You came DOWN from the Living Room."

   The fix is not just a string. The prompt currently has two arms (Structural, Name) for three situations. Either `Trigger` grows to distinguish the two structural forms, or the prompt derives the orientation from the data it already holds — it has the seam and the region, and whether `seam.from` is inside `region.rooms` is exactly the discriminator. Prefer deriving it if that is clean, since it cannot fall out of step with the trigger. Whichever way, both readings need their own sentence and both need a test.

3. **The room list is cut off.** The dialog is not wide enough for real room names. The user asked for the rooms as BULLET POINTS with the dialog growing TALLER rather than wider. Note the region can be large — a descent fires at four rooms but the same prompt serves regions of any size, and SQ-0853's own report mentions walking to five and six — so decide what happens past a sensible height (scroll, or an "and N more" line) rather than growing without bound.

4. **No separation between the layer-selection list and the buttons.** At least one blank line.

CONSTRAINTS. Every UI element must be styleable via `style.toml` (ColorScheme field + `style.rs` selector + render apply) — never hard-code a style; a bullet list and any new separator are UI elements. Shared-chrome dialog conventions apply: Tab/Shift-Tab move focus, Enter activates, Esc cancels, Space is widget-reserved. The three prompt outcomes (separate now / ask me again / never ask) must keep working — they are `SeamDecision::Armed`/`Deferred`/`Ignored` and `archive.rs` pins them across a save/restore round trip.
