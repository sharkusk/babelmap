## Fixed — and it was NOT a pin regression

Commit 52319c5f. Gate 0, clippy clean, 5634/5634.

### Reproduced under both placements, which is what settled the blame

The report was against `--pin bottom`. Capturing the same session under `--pin top` shows the identical defect — rows 13/16/19/22 instead of 1/4/7/10. So it predates SQ-0909 and was only made conspicuous by moving the story to where the eye rests.

### Mechanism

The newline that commits an echoed input line **scrolls**, and a terminal erases the newly exposed line with whatever background is in force at that moment. `read_line_raw` reset first and emitted the newline second:

```
look \x1b[0m  \r\r\n  \x1b[1;37;40mHilltop\x1b[0m  \x1b[1;37;40m\r\n\x1b[0m
        ↑ reset      ↑ scroll: erased with the TERMINAL's default
```

so the exposed line was erased with the default background, the game then wrote the room name over the first few cells, and the rest of the row stayed pale. **Exactly one row per turn** — the first line printed after the command. Every later line of the turn scrolls *inside* a styled run (see the second `\r\n` above, which sits within `\x1b[1;37;40m`) and was fine, which is what made it look like a property of room names rather than of the newline before them.

Only the background is re-applied, never the whole run: reverse video would make the erase paint the foreground colour across the line instead. A story that sets no colour emits exactly the bytes it always did.

### How it was diagnosed, since the method is reusable

`script` was useless — macOS's sends an EOT on the way in, which zvm-cli correctly reads as Ctrl-D and exits at the first prompt. A ~25-line Python `pty.fork` driver that writes a line whenever the child goes quiet drove the real game instead, and the capture was resolved through `qwertty-term-vt`, which reports per-cell backgrounds. That is what turned "a lighter colour to the end of the line" into a precise reading:

```
before   1 |Hilltop | 0:Palette(0) 7:Default
after    1 |Hilltop | 0:Palette(0)
```

Worth remembering: the CLIs have no pty harness of their own, and this took minutes to stand up. If a second CLI rendering bug of this kind appears, that is the tool.

### Test

The byte ORDER is the invariant, so `commit_line_bytes` was split out as a pure function and asserted directly — the background must precede the newline and be dropped after it. Testing it in place was not possible: it lived inside a raw-mode reader that needs a terminal.
