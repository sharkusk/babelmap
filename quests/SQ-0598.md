--- note 2026-08-03T06:08:17Z ---

Fixed in 5b751785 (trailered SQ-0597 — the two changes interleave in the same functions of ifdb_search_modal.rs, so they shipped as one commit).

Root cause: the modal kept a bare `hit_sel`/`opt_sel` index and recomputed the visible window from it every frame (`scroll_start`). A stateless rule like that can only pin the selection to one edge of the viewport, so walking back up scrolled the list under a cursor frozen on the bottom row.

Fix: both lists now use `list_scroll::ListScroll` — the same state machine the story picker drives, whose module doc already claimed "every selection-list modal" used it. Home/End/PageUp/PageDown and the shared scroll easing come along with it (the picker's run loop now ticks the modal's tweens too).

Falsified: restoring the old stateless rule in `ListScroll::ensure_visible` makes `stepping_back_up_moves_the_highlight_not_the_window` fail with the reported symptom — the window slid Game06..20 → Game05..19 while the highlight stayed put.
