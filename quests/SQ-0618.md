## Shipped 2026-08-03 — commit 24dbbb61

`cli_host::storage`: `story_key`, `game_dir`, `resolve_save_input`. 148 lines
out of the two CLIs (74 each), 157 in (including tests + the docs explaining
why the `.save` suffix exists at all).

### Two of the moved tests were weaker than they looked
Worth recording, because both would have passed a review:

1. **The collision test proved only that two paths differ.** What actually
   failed before SQ-0294 was `mkdir` refusing to create a directory where a file
   of that name exists. The moved version creates a real file and a real
   directory beside it.
2. **`resolve_save_input`'s "a path is honoured verbatim" case used an ABSOLUTE
   path** — and `Path::join` with an absolute path *replaces* the whole path, so
   the assertion passed whether the rule worked or not. Caught by falsification:
   forcing the bare-name branch left the test green. A RELATIVE path
   (`saves/foo.qzl`) is what pins it. The original zvm-cli/gvm-cli tests had the
   same blind spot.

Also added a case nothing covered: `story_key` cannot escape the directory it
names (`../../etc/passwd` → `passwd`).

### Verified
Beyond the gate: saved beside the story file (the collision case) — works;
restored it back — works; `--data-dir` override — works; save-directory layout
AND saved bytes byte-identical to the previous build. Falsified 3 ways.

### Survey follow-up (from SQ-0617's note)
Done: the three byte-identical helpers. Deliberately NOT done:
- `read_line_raw` / `read_char_input` — same skeleton, but zvm carries timed
  input, sound polling and terminating-character keys while gvm carries
  `LineEcho` modes. Sharing the skeleton alone is not obviously a win; wants a
  closer look before anyone tries.
- `enter_region` / `leave_region` — same names, DIFFERENT behaviour (zvm wraps in
  DECSC/DECRC to preserve the cursor, gvm parks it at the bottom). Do not merge.
- `sgr_open` / `style_wrap` — same names, `ZColour` vs `GlkStyle`. Nothing shared
  but the name.
