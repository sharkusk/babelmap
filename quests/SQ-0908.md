## Root cause: the ADF reader reported bare filenames, and Infocom used one filename for every game

`Adf::scan_file_headers` finds files by **scanning every block for a file header** rather than walking the directory tree — deliberate, and documented as such ("it finds files in subdirectories without recursing"). The cost was that an entry never knew its parent, so `Volume::contents` reported bare basenames.

*The Lost Treasures of Infocom* stores each game in its own AmigaDOS directory under Infocom's conventional `Story.Data`. MEASURED on `treasures/Lost Treasures of Infocom, The_Disk3.adf` — the disk the user's example is on:

```
before:  six rows, six entries, all of them "Story.Data"
```

`Adf::read_named` then matched case-insensitively on that name and returned the **first match in block order**, which on disk 3 is Suspended. Picking Hitchhiker's launched Suspended, exactly as reported. Disk 1 had the same collision three ways (Spellbreaker, Sorcerer, Enchanter).

`Hfs` and `Iso9660` already report full paths — the Masterpieces disc yields `MAC/ZORK ZERO/STORY.DATA` — so ADF was the odd one out, and the picker/asset code already handles path-shaped names (`discover_art_candidates` splits on `/` via `folder_of`).

## Fix

`AdfEntry` gains a `path`, built by walking the parent chain: a header block's `BSIZE-12` longword is its containing directory's block, and the walk climbs through `ST_USERDIR` headers until the root. `Volume::contents` reports the path; `Adf::read_named` tries the path first and the bare name second, so every caller that hands over a filename (the `--pictures` door) keeps working and answers as it always did.

**The `BSIZE-12` offset was verified empirically rather than taken from memory** (CLAUDE.md): the walk produces `c/GoWB`, `l/Ram-Handler`, `l/Disk-Validator` and `libs/icon.library` on disk 1 — the classic AmigaDOS system directories, which no wrong offset would invent.

## Verified on the real set

Every row on every disk now loads its own build:

## Test

`adf::tests::a_files_path_names_the_directory_it_lives_in`, hermetic (`treasures/` is gitignored). Builds a synthetic image with `Suspended/Story.Data`, `Hitchhiker/Story.Data` and `Hitchhiker/Extra/Story.Data`, over both OFS and FFS. Nested two deep on purpose — a parent chain that stopped one level up would still pass a flat pair. Asserts the paths are distinct AND that `read_named` returns each file's own bytes, plus that a bare name still resolves. FALSIFIED by reverting the walk: `["Disk.info", "Story.Data", "Story.Data", "Story.Data"]`.

The test builder gained `add_dir`/`add_file_in`, which is what any future directory-shaped ADF case will need.
