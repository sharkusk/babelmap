## Shipped 2026-08-03 — commit adeaa5c3

`--plain` no longer narrates the status line; `--show-status` opts back in.
Measured on Ballyhoo over four `wait` turns: **0** emissions under `--plain`,
**5** with `--show-status`, **5** piped (unchanged).

### Why it was chatty at all
A v3 status line carries `Moves: N`. The block therefore differs every single
turn and the dedupe can never fire — this is structural, not a tuning problem.
Games without a turn counter in the status were already quiet (Lost Pig 1,
Counterfeit Monkey 1, Scott 1 over the same four turns).

### The size carve-out — the part worth challenging
Suppression applies only to a **one-row** region. Blanket suppression was tried
and rejected on evidence: the Infocom releases with integrated InvisiClues draw
their hint menus in the upper window, and `--plain --no-status` loses all of it.
Planetfall's menu is twelve chapter headings plus a
`RETURN = See hint / Q = Resume story` legend → 0 lines survive. Lost Pig's HELP
menu → 0 of 4 items survive. Same rule in gvm-cli, where CM's hint menu is the
status grid grown from 1 row to 4.

`--no-status` remains the blunt instrument and still wins over `--show-status`.

### A naming correction I had to make mid-task
I repeatedly cited "Arthur's menu" as the motivating case. `arthrizm.z5` is a
standalone InvisiClues *hint file* (v5, serial 990304), not the game Arthur —
which is v6 and refused by zvm-cli outright (SQ-0601). The user caught it. The
behaviour I measured was real, but resting the argument on a hint file was weak;
re-verified against Planetfall and Lost Pig, which are actual games, and the code
comments now cite those. Worth remembering: the `*-invclues` fixtures are real
Infocom games with built-in hint systems; `arthrizm.z5` / `plundizm.z5` are not
games at all.

### Verified
Piped output identical across 5 Z-machine + 4 Glulx; TTY byte-identical under a
pty. Gate 0 errors, 64 == 64. Clippy clean. Falsified 3 ways (blanket
suppression loses the menu on each engine; disabling the gate restores the
per-turn status).

One pty run of Counterfeit Monkey reported a TTY difference that did not
reproduce — CM boots slowly and the harness has fixed sleeps. Two clean reruns at
identical byte counts, and the changed path is gated on `plain()`, false on a
TTY. Same harness impatience that faked a hang during SQ-0606.

### Not done
scott-cli is untouched — its room block is game output, not chrome. gvm-cli has
`--show-status` but no `--no-status`; nobody has asked for one.
