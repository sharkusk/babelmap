## Why

Status information reaches a plain-mode reader only at the moment the game chose to
write it, and then scrolls away. A sighted user re-reads a pinned status line for free;
a screen-reader user has to scroll back through the transcript to answer "where am I,
what's my score?".

## Options (undecided)

- A command the CLI intercepts before the engine sees it (`status`, `/status`) that
  prints the current status text. Cheapest, but risks shadowing a game verb.
- Emit the status line before each input prompt in plain mode. No new syntax, always
  current, but repeats on every turn — likely too chatty for a reader.
- A key the input layer intercepts. Fits the raw-mode path but not the cooked one that
  plain mode wants ([[SQ-0606]]).

The data is available in all three engines already: zvm-cli reads it for its pinned
line, gvm-cli tracks grid windows in its cell buffer, and a Scott game's status is
prose the game itself prints.

Worth deciding with a real user rather than from here — the right answer depends on how
noisy a reader finds per-turn repetition, which is the whole question.
