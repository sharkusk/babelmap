## Shipped 2026-08-03 — commit ad547c1e

`cli_host::Pager` owns the counting rule; each host feeds it the newlines it
writes. zvm-cli migrated first so the shared version was proven against the
working implementation before the other two were built on it — its TTY output is
byte-identical through the migration (1193 B) and it still pauses 3× on the same
10-row terminal.

Measured after: zvm 3 pauses, gvm 4, scott 1 on a short terminal; 0 in all three
piped (exit 0, no hang) and 0 under `--screen-reader`.

`--no-more`/`--no-page` added to gvm-cli and scott-cli to match zvm-cli.

### Two things worth remembering
1. **gvm's `windowed()` guard in `story_newline` is belt-and-braces, not
   load-bearing.** Windowed output returns early in `put_text_attr` into
   per-window line stores and never reaches it. It matters only for a game that
   streams first and *then* opens panels, leaving a pending word for `flush` to
   emit after the switch. My first falsification of that guard did NOT fail —
   because Kerkerkruip had not opened its panels yet in that run. The comment now
   says what the guard is actually for.
2. **A regex cleanup in this change deleted three v6-refusal tests (SQ-0601)**
   along with the line-counter test it was meant to move. Caught by diffing the
   function lists against the pushed commit; restored from `e6abedb5`. Lesson:
   after regex surgery on a test module, diff `fn` names against git rather than
   trusting the test count.

## Answer to "any other common code for cli-host?" (surveyed 2026-08-03)

Compared every fn name across the three CLIs. Remaining duplication, ranked:

**Byte-identical, clear wins:**
- `story_key` — sanitize a story filename into a per-game directory token.
  Identical in zvm-cli and gvm-cli, plus two duplicated tests
  (`story_key_keeps_extension_and_sanitizes`,
  `game_dir_does_not_collide_with_same_named_story_file` — the latter guards
  SQ-0284/0294).
- `resolve_save_input` — bare name vs path → `.qzl`. Identical (same md5),
  duplicated test too.
- The per-game dir construction itself: `--data-dir` override else the story's
  own parent, joined with `format!("{}.save", story_key(..))`. Same four lines
  in both mains, and the `.save` suffix is a bug fix (SQ-0294) that exists twice.

**Partial overlap, needs judgement:**
- `read_line_raw` / `read_char_input` — same shape (echo, backspace, Ctrl-C/D
  exit) but zvm carries timed input, sound polling and terminating-character
  keys while gvm carries `LineEcho` modes. The *skeleton* is shareable; the
  bodies are genuinely different.

**Same name, do NOT share:**
- `enter_region` / `leave_region` — NOT identical. zvm wraps in DECSC/DECRC to
  preserve the cursor; gvm parks it at the bottom. Different deliberate choices.
- `sgr_open` / `style_wrap` — same names, different types (`ZColour` vs
  `GlkStyle`). Nothing in common but the name.
- `new`, `main`, `build_machine`, `as_any` — engine-specific or trait boilerplate.

scott-cli shares nothing further: no saves, no windows, no colour.
