SCOPE DECIDED (user, 2026-07-29): **prefill only** — open the dialog with the room's current notes already in the field so you can edit in place. NOT a multi-line notes editor (that was offered and declined; `Room.notes` stays a single-line `String`).

This is a one-line change plus tests, and the pattern already exists in the same match block:
  - `crates/app/src/input.rs:1801` — `RenameLayer` already does the right thing:
      `TextEntryDialog::new(TextEntryKind::RenameLayer(layer), current_name)`
  - `crates/app/src/input.rs:1808` — `EditNotes` opens empty:
      `TextEntryDialog::new(TextEntryKind::EditNotes(id), "")`
So `TextEntryDialog` already supports an initial value; nothing new is needed in the widget.

Fix: pass the selected room's existing notes as the initial value. Read them off the graph at the point the dialog opens (`graph.room(id)` -> `.notes`), same shape as how `current_name` is resolved just above.

Preserve the existing semantics, which are documented at `input.rs:2764` and must not regress: **submitting an empty field clears the notes**. With a prefill that becomes "select-all/clear then Enter", which is still reachable — but the comment at :1807 ("Opens empty: submit replaces the room's notes (empty clears them)") is now stale and must be updated in the same commit.

Check while there: whether the cursor lands at the END of the prefilled text (edit-append is the common case) rather than at position 0, and whether the field scrolls if the notes are longer than the dialog width.

Tests: prefilled-with-existing-notes, empty-room-opens-empty, submit-empty-still-clears.
